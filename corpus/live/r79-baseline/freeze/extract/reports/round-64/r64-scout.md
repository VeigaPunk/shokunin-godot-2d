unobservable from the reader side. For these fixture arms that suffices —
the forge's ppid gate makes its write provably post-death, so forged bytes

## 1. Where an observation can be timestamped (Q1)

**Not inside `run_process`/the CASES path.** `run_process` (:149–158) is a
single-shot `subprocess.run(..., capture_output=True, timeout=...)` (:151):
output exists only at return or inside `TimeoutExpired` (:152–156) — no
per-line timestamps, no mid-stream hook. `communicate()` drains pipes
internally but exposes nothing until EOF-or-timeout. The only liveness
evidence the current runner captures is `poll()` **after** the fact:
`child_exit_at_timeout` inside the `TimeoutExpired` catch (:592, :739).

**The insertion point is a raw-`Popen` + selector loop, and the file already
contains the pattern**: the `--probe-crash-exit` reject arm registers
`process.stdout` on `selectors.DefaultSelector`, loops
`select()`→`readline()`→`process.poll()` (:1159–1174). The while-live gate is
that loop with the poll **after** the readline that returned a candidate
line: `line_observed_while_live = (proc.poll() is None)` evaluated at the
instant `readline()` returns the marker line.

Liveness primitives — measured (arm: sh ppid-gated descendant writing SIG
post-death, identical gate shape as fixture :65):

| primitive | forged arm outcome | verdict |
|---|---|---|
| `proc.poll()` (waitpid WNOHANG) | marker observed 5/5, while-live **0/5** | **sound**: reaps the zombie; dead child always reads dead |
| `os.kill(pid,0)` | marker observed 5/5, while-live **5/5** | **zombie-blind → false accept**: signal-0 succeeds on an unreaped zombie (`marker_states=['Z']` every rep) |
| `/proc/<pid>` bare existence | same flaw as kill0 (zombie keeps its dir) | unsound |
| `/proc/<pid>/stat` **state field** (`Z`/`X` = dead) | while-live **0/5** | sound but redundant — `poll()` is one syscall, immune to pid-reuse, and reaps |

Consequence for the arm design: reuse `pid_alive` (:629–640) **only** for the
post-return/orphan checks it already serves (non-children, post-reap state);
never as the observation gate on the direct child. `kernel_ppid` (:781–792)
remains valid for the hold arm's corroboration.

A heartbeat `poll()` on each select wake additionally yields
`child_first_dead_at` — reader-side ordering proof `first_dead < marker_read`
lands **in-record** (~22ms on all five Godot forge reps), which the r63 row
could only fixture-assert via `write_ppid` (r63 critic's stripped-gate slip
class narrows further: the ordering evidence is generated by the reader).

Ordering subtlety, recorded not asserted: `poll()` and the `/proc` truth
sample are two syscalls — on 5/20 fast-sh genuine reps the gate read
"alive" while the immediately-following state sample already read `Z`
(death landed in the µs between them). Keep both fields per line.

Buffering nuance: `text=True, bufsize=1` still routes reads through a
`BufferedReader`; `readline()` can return bytes pulled by an earlier
underlying `read(2)`. The honest record is "gate result at the instant
`readline()` returned the line", not a per-syscall timestamp. Harmless for
the forge arms (no forged bytes exist pre-death at all); relevant to the
genuine arm's semantics.

## 2. Pipe bytes survive death (Q2)

Measured (`bytes_survive_death` arm, receipt
`whilelive-verdicts.json`/`raw/bytes_survive_death.stdout`): `sh -c
'echo SIG; exit 0'`; parent `wait()`ed to a full reap (exit 0, `/proc/<pid>`
gone), slept 0.5s, then read the pipe — **SIG still delivered**. Pipe bytes
are kernel-buffered and outlive the writer; a post-death read observes
pre-death bytes indistinguishably.

So: **"written while alive" is never checkable from the reader.** Pipe bytes
carry no writer identity or write timestamp. The only checkable property is
"observed while alive" — and even that only orders observation vs death, not
authorship: a descendant writing *during* the child's life would pass the
gate. The declared claim is specifically about **post-death** forged
signatures, which this fixture makes provable — the descendant polls
`/proc/self/stat` until its ppid flips off the godot pid before writing
(fixture :64–65). Forged bytes therefore cannot be in the pipe before death,
and the observation-time gate is sufficient. Document, do not overclaim:
this discriminates post-death writes, not same-lifetime fd-inherited writes.

## 4. Verdict on the claim

**Testable as a while-live read.** Predicted discrimination holds on this
host: forged post-death signatures are never live-observed (deterministic —
guaranteed by write-ordering, not scheduler luck: forged bytes cannot be read
before they are written, and they are written only after death, so the
post-read `poll()` sees dead every time); the genuine default-arm signature
is live-observed 10/10 with ~65ms slack (Godot's `quit(0)` teardown).

The genuine side **is** a read-vs-exit race in principle: even `sh`'s
`echo;exit` won 20/20 but with margins down to µs (5 reps showed `Z` in the
truth sample µs after an alive poll). On a stalled reader or a faster-teardown
build, a genuine marker could be observed post-death → false reject. The arm
must therefore record per-line `{t, stream, gate_alive, proc_state}` plus
`t_marker`/`t_first_dead` so a falsified rep is visible in the receipt rather
than folded into a boolean — which is also what makes the row falsifiable as
declared.

## 6. UNKNOWNs / caveats

- Genuine-arm margin is timing-dependent in principle (30/30 live here:
  20 sh worst-case `echo;exit` + 10 real Godot). Record fields keep a
  falsified rep visible per the brief; if it ever lands post-death, the gate
  cannot distinguish — report the falsified outcome with measured timing.
- The gate authenticates **observation order, not authorship**: a
  fd-inheriting descendant writing *pre-death* passes it — outside the
  declared claim (post-death forgery) but the boundary belongs in the row's
  `bounded_claim`.
- Single host (Linux 7.2.3-arch1-3, godot 4.7.2.stable.arch_linux.ed1daf0bf,
  Python 3.14.7); orphans reparent to ppid 1573 (`systemd --user`).
- Mechanism arms use `/usr/bin/sh` children (fd-inheritance semantics
  identical; fixture arms prove the Godot spawn inherits pipes), but the
  decisive arms re-ran the **real fixture file** under real Godot.
- `t_first_dead` needs ≥1 heartbeat between death and marker arrival; the
  fixture's 50ms descendant-gate granularity gives ~22ms of cover. A forge
  without the ppid gate could write closer to death and race the heartbeat —
  irrelevant here (existing arms are gated), worth one comment in the row.
