# Round 21 crash-exit critic — falsification review

Scope: read-only adversarial review of the proposed real-Godot normal-exit vs SIGTERM pair and current uncommitted probe. I made no runner, fixture, seeded corpus, engine/editor, or control changes. ## Verdict: concept is causal, current implementation has a deterministic fail-closed metadata defect

The core contrast can reject a copied marker: the accept invocation runs the same script, emits `CRASH_EXIT_PROBE: expected signature`, and normally calls `quit(1)`; the reject invocation prints it, then awaits a timer, and the parent signals the direct `Popen` child. `classify_process` requires exact expected return code and no launch/timeout error, so `Popen.returncode == -SIGTERM` with that same stdout signature must classify false. Requiring `poll() is None` after observing the marker is meaningful proof that the direct Godot subprocess had not exited at that observation; a signature alone would be insufficient. The bounded, external termination treatment is distinct from ordinary timeout handling.

However, in the current `probe_crash_exit` implementation, reject record initialization omits `"expected_exit": expected_exit`, while `same_expected_exit` evaluates `record.get("expected_exit") == expected_exit` for **both** records. Thus the reject arm always contributes `None == 1` (false), and `meta_pass` can never be true, even if Godot executes and all signal evidence is correct. This is fail-closed rather than false admission, but must be fixed before the opt-in probe can pass; rerun it and report this initial failure as telemetry, not as a pass.

## Adversarial checks and boundaries

- **Signal/signature spoof:** In normal/reject invocations, same `script_path`, marker boolean, and expected exit are asserted. `classify_process` rejects the signal return code even when marker text is present. But `marker_observed`/`same_marker` are booleans and `classify_process` is a substring check, not an exact-line check; current fixture itself prints exactly once, so inspect raw streams and require the exact marker line in each if claiming exact same signature. The script is copied from fixture source into per-run scratch; the raw artifact should record its hash or verifier should establish the source hash unchanged.
- **Race:** `process_was_running = process.poll() is None` is a point-in-time observation immediately before `send_signal`, not atomic proof at signal delivery. In this fixture the process waits 30 seconds, while the marker/read/signaling bound is 8 seconds; that makes spontaneous script exit before SIGTERM implausible. Preserve the actual order/timing and state this bounded behavior rather than implying atomicity. A missing marker / early process exit must fail the pair.
- **External process proof:** `Popen` launches Godot directly, not a shell wrapper, and observed `-SIGTERM` is Python's POSIX signal return-code convention; this is better evidence than the scout's shell status 143. Report actual `sys.platform`, OS and Godot version, sent signal, Python return code and any shell-vs-Python distinction. Don't port `-15` semantics to Windows or other platforms.
- **Timeout and cleanup:** Startup/marker wait uses an 8s deadline; post-signal `communicate` uses 3s, then attempts `kill()` and a further bounded `communicate`. `finally` also tries cleanup if still live. This addresses the direct child, not descendants/process trees. Inspect for surviving Godot processes after the run. One residual code path: if the *second* `communicate(timeout=cleanup_seconds)` after forced `kill()` itself raises `TimeoutExpired`, that exception is not caught by the `(OSError, ValueError)` handler; it could escape the probe, preventing verdict artifact creation. It is unlikely for direct SIGKILLed Godot, but the failure path is not fully represented as a FAIL record. If touching this area is in scope, capture it as cleanup failure without claiming tree cleanup.
- **Early exit / normal control:** `quit(1)` proves the normal expected nonzero control. Marker-first ordering makes the signal arm's signature a deliberately copied success marker and ensures the marker must be observed before signal. A marker without `process_was_running` must never count.
- **No process-tree proof:** Direct PID signal and `communicate` establish this one child only; they don't prove child/descendant cleanup. Do not claim general crash classification, timeout/tree cleanup, or cross-platform behavior.
