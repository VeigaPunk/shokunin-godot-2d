# Round 25 presets/template scout

Scope: read-only inspection of the tracked export preset, its runner call site, historical adverse records, and local Godot/template installation. No exports or battery runs were performed; no files outside this report were changed.

## Findings

- Tracked `corpus/fixtures/export_presets.cfg` has one `[preset.0]`, `Linux/X11`, and `export_path=""`; `preset.0.options` selects `x86_64`. SHA-256: `0b321c1c866e5d61e5e4fe8842fe8552f8d6cac3c9b7659f285f2c15b59ba694`.
- Runner's export case creates `export_project/out`, asserts it is empty, and sets export destination to `out/fixture.x86_64` (`run_battery.py` lines 225–250). It passes `--path <scratch>` and destination as strings derived from `args.runs`; neither is normalized with `.resolve()`. The `--runs` value defaults to an absolute path derived from `HERE`, but a caller-supplied relative value remains relative. The runner process inherits caller CWD; no explicit subprocess `cwd` is set in the shown export command path.
- Historical r16 adverse (`corpus/lessons/r16-export-adverse.json`, scratch `.../20261012T184136853021Z/scratch`) and r24 adverse (`corpus/lessons/r24-export-adverse.json`, scratch `.../20261013T012020522893Z/scratch`) both have the same `ERROR: Prepare Template: The given export path doesn't exist.` and zero products. Both JSON records identify scratch by a relative path. This establishes recurring signature, not causal attribution to relative `--runs`; no paired evidence here.
- Current machine reports `/usr/bin/godot`, version `4.7.2.stable.arch_linux.ed1daf0bf`; matching template directory `/home/vgpnk/.local/share/godot/export_templates/4.7.2.stable` exists and contains `linux_debug.x86_64` (73,703,800 bytes) and `linux_release.x86_64` (73,519,416 bytes), among other platform templates. Thus an absent local Linux template is not indicated. This does not prove that historical runs had the same template state or that Godot can consume it successfully.
- The runner emits the warning `Detected another project.godot at res://controls. The folder will be ignored.` in both adverse export logs. That warning is a candidate project-layout confound but is not itself shown to cause this export-path error. Other remaining candidates include Godot's interpretation of relative `--path`/destination, project scan/export state, or environmental/template resolution. This scout cannot distinguish them.

## Assessment

Relative path causality remains **unproven** from this read-only inspection. The cfg's blank export path is not evidence of missing configured output: the runner explicitly supplies an output path, and creates its parent directory first. No runner correction is justified by these observations alone. A controlled relative-versus-absolute paired export should preserve identical project/preset bytes and Godot binary, report CWD and exact commands, and verify destination existence immediately before/after each invocation. No engine/editor or seeded controls changes were made.
