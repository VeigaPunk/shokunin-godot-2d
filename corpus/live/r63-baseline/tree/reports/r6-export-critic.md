# Round 6 export readiness — adversarial critique

## Evidence available

The standing claim in `LOG.md` is deliberately narrow: distinguish a configured export preset from a missing/invalid template or preset, without publishing a distributable. In the current checkout, I found no `r6-export-scout.md`, `r6-export-executor.md`, `export_*` fixture, or `export_presets.cfg`; `run_battery.py` has no export case and remains a 21-case list. Thus there is not yet a concrete implementation or raw export-run log to validate. Do not count the claim as measured or infer round-6 success from prior battery evidence.

## Falsification requirements

- **Preset syntax/static check is not an export.** Reading/parsing `export_presets.cfg`, checking a preset name, or opening the project in editor/headless mode can show configuration presence or project parseability only. It cannot establish the selected platform's export templates are installed, that Godot accepts the selected preset, that resources import correctly for export, or that a package can be produced. A true template-readiness check must invoke the relevant Godot export/template operation and record its actual diagnostics. If a real export is intentionally excluded, state plainly that only static configuration was checked—not “export ready.”
- **Actual template/export evidence needs provenance.** Capture exact Godot executable/version, invocation and arguments, working/project path, selected preset/platform, environment relevant to template lookup, exit status, stdout and stderr separately, and output artifact facts. A transcript pasted into a report or a hand-authored JSON PASS is not evidence. Preserve raw output and independently check its association with the command (e.g. invocation wrapper records argv, status and unaltered streams); hashes help detect later alteration but alone do not prove the command ran.
- **Do not equate exit 0 or a success substring with success.** Godot can emit `ERROR`, `SCRIPT ERROR`, parse/import failures, missing-resource/template diagnostics, or warnings before/alongside a success-looking line. Review the complete streams and fail on relevant error diagnostics, even when exit code is zero. Conversely, expected negative probes must distinguish the intended missing-template/preset diagnostic from a generic command failure, parser error, timeout, missing executable, or unrelated resource failure. Require positive and negative cases to reach the intended decision point and apply the same meaningful readiness assertion.
- **Bound side effects.** A purported non-export readiness check may still create `.godot` editor/import caches, UID/import metadata, logs, or modify project-local files. A real export writes an artifact even if it is temporary. Run only on a disposable scratch copy in the declared ignored live area; enumerate and inspect changed paths before/after, keep the destination inside that scratch tree, and remove temporary outputs only after recording their hash/metadata. Do not use the production project, shared user export-template directories for destructive cleanup, or repository paths outside the authorized scope. State explicitly that an export artifact was generated if one was, even if deleted afterward; no publishing is permitted.
- **Asset rights are outside this test's proof.** Export success only says the tool could package inputs; it grants no license or redistribution rights. Conversely, a synthetic fixture passing does not establish that project assets are cleared. Keep the fixture synthetic and make no licensing, ownership, or production-distribution claim. A rights review needs separate provenance/license evidence.

## Acceptance recommendation

Treat the axis as unproven until a non-author replay can inspect raw positive and negative evidence, verify no relevant errors were ignored, and confirm side effects stayed inside scratch. If only static preset validation is provided, narrow the result to “preset configuration check” and do not present it as actual template/export readiness or a distributable build. No engine/editor source edits or asset-rights conclusions are warranted by this critique.
