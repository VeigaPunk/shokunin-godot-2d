# Round 13 juice — adversarial critic

## Scope and decision

Read-only review of the Round 13 mission in `LOG.md`, seeded `animation_property.gd`, and the evolving `tween_flash.gd` / `run_battery.py`. I also ran the Tween fixture from a disposable `/tmp` copy; no repo source was changed by these experiments. **The feature is genuinely new, narrow coverage**: AnimationPlayer already proves a property track starts and reaches an intermediate `position.x` value after `advance(0.5)`, with a zero-speed mutant. It does not exercise SceneTree Tween creation/scheduling, `CanvasItem.modulate`, nor a transient-to-baseline return. The shared concept “an animation changes a property” overlaps, but the engine API, visual-feedback property, and temporal-return obligation differ. This supports one additional bounded behavior case, not a broad claim about juice or visual quality.

## Runtime evidence observed

At review time the fixture had `MAX_OBSERVATION_FRAMES := 90`, baseline `(0.7, 0.8, 0.9, 1.0)`, a Tween sequence to `FLASH` and back, and `--no-tween` as the mutant. On installed Godot 4.7.2, a disposable copy passed positive with a non-baseline `transient_modulate` and final baseline after 62 observations. `--no-tween` exited 2 with the intended assertion; its final property remained baseline and both `transient_seen` and `baseline_restored` were false. This distinguishes the two states and tests return, not merely start. The earlier evolving 36-frame version failed positive (sequence still underway at frame 36); 90 was sufficient in my replay. Do not restore 36 without a runtime check. Evidence is engine property state, not rendered output.

## Adversarial checks / caveats

- **Start/no-start:** the mutant really skips Tween creation, so it tests the intended missing-start behavior. The positive checks an observed deviation and subsequent approximate return; no hard-coded midpoint/color assertion. A different transient mutation of `modulate` could satisfy this pattern, so attribution rests on fixture construction plus the single controlled mutant.
- **Null / parse errors:** no explicit null Tween is used; skipping start leaves no Tween reference. A script parse/runtime error must not count as the intended mutant. Current runner classifier rejects `SCRIPT ERROR:` and `Parse Error:` globally and requires the expected exit/signature, which is directionally sound.
- **Negative diagnostic matching needs repair/verification:** the fixture currently formats the assertion with appended state fields (`transient_seen`, `baseline_restored`, frame count and final color), while the runner's `tween_no_start` allowed-error entry appears to be the bare message ending `...baseline`. `classify_process` allows exact lines, or prefix matching only when the configured allowance ends in a comma. The actual detailed `ERROR:` line therefore appears not to be allowed; the no-start process may be correctly rejected as unrelated-error despite its intended exit/signature. Run the combined battery and inspect raw output before claiming the paired case passes; align allowance narrowly with the stable prefix plus one-error-line rule (as used by similar cases), not a blanket ERROR allowlist.
- **Temporal bound:** 90 process frames is a practical bound and passed here; it can vary with engine timing. The observation loop exits as soon as baseline follows a non-baseline snapshot. A too-short bound gives false negatives; the earlier 36-frame run demonstrated this. Keep the explicit bound and record observed count.
- **Warnings/errors:** positive replay had no warnings or errors. Negative expected assertion is an intentional `push_error` and must be the only allowed diagnostic; unrelated errors and parse errors must remain failures. I did not run the evolving entire battery, so overall warning/error cleanliness and case count remain unverified.
- **Reporting:** say “Tween-driven `modulate` property excursion and return observed in headless runtime.” Do not say a flash was visibly rendered, perceived, or integrated into a game.

## Verdict

Coverage claim is substantively valid and non-duplicative at the narrow feature level, with a useful matched no-start control. **Conditional HOLD on admission** until the evolving battery positively classifies both cases, especially the verbose expected negative diagnostic, and verifies the prior cases remain intact. No source edits made; scratch experiments stayed under `/tmp/r13-juice-critic`.
