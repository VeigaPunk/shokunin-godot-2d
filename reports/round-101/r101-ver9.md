## 3. The identity: 7-field tuple (scope clause, established r60-verifier)

`(script, flags, expected_exit, actual_exit, signature, verdict, error)` — per battery *record*,
not per CASES tuple. Empirical scope evidence from the two real receipts (runs-v vs
runs-v2 rep2b, both 519 rows PASS): 7-field tuple **0 mismatches** over all 509 shared names,
probe verdicts identical, discrimination dicts identical; meanwhile `command` is identical in
only **7/519** rows (the 7 command-less probe rows) and `scratch`/`seed`/timestamps differ —
`output`, `command`, `scratch`, `xdg_data_home`, `elapsed_seconds` are correctly outside the
compared scope.

**Do not compare CASES markers to record signatures.** Static check vs the registry finds 10
names where the recorded `signature` is not the CASES marker string — by construction
(`export_readiness` marker `…executable=nonempty`; record
`EXPORT PASS preset=Linux/X11 executable_bytes=73703800`; `export_preset_missing` marker
`No export preset 'Missing preset' found`; record `ERROR: Invalid export preset name: …`), and
9 `input_lattice_*`/`r92_tilemap_nav` rows whose CASES entry carries a *tuple of accepted
alternatives* while the record carries the line actually observed. The comparator therefore
compares run-to-run records only; the static mode compares only `script`, `flags`,
`expected_exit` (pure registry data).

## 4. Criteria (implemented in `ver9_prior_rows.py`)

- **C1 inventory** — no prior case dropped; battery verdict PASS; every current row PASS.
- **C2 7-field equality** — per prior name, the *value set* of 7-field tuples must be equal
  (both directions): `prior_value_missing` ∪ `prior_value_drift` must be empty.
- **C3 multiplicity** — per-name execution count must equal the baseline count, except names
  carrying the recorded dedupe disposition (`crash_spontaneous_sigabrt` 3→1,
  `crash_self_sigkill` 2→1, reason `9ede7c50`). An extra *identical* copy is still a mismatch —
  this is the forged-extra-replay-line class (r100-critic F2) at the receipt level.
- **C4 only-new** — new rows reported; with `--expect-new-prefixes` every new name must match a
  prefix, each prefix must be non-empty, and every new row must PASS.
- **C5 probes / discriminations-preserved** — every prior probe row present; verdicts equal;
  every baseline-true discrimination key still present and still true (new keys allowed and
  listed as `discrimination_keys_added`).
- **C6 census guard** — from `probe_error_clause_surface.census`: `dead_entry_count` not above
  baseline (baseline 0), `rows_with_expected_errors` not below baseline (baseline 80).
- **C7 registry (static / `--registry-only`)** — CASES names unique; every baseline name in the
  registry; per-name `script`/`flags`/`expected_exit` ∈ baseline value set; each expected new
  prefix non-empty. Runs without executing the battery, so it can be used as a pre-flight.
- **0-mismatch criterion**: `verdict == PASS` ⇔ no failure class at all (exit 0). Exit 1
  otherwise. `--report <path>` writes the JSON report.

Order of `results` is deliberately **not** compared (the r100 dedupe legitimately reordered the
crash tail); duplication/drop is caught by C1/C3 by name+multiplicity instead.

## 6. Orchestrator runbook (copy-paste)

1. Pre-flight (seconds, no Godot), **before** this round's CASES rows land:
   `python3 reports/round-101/mutations/ver9_prior_rows.py
   --baseline reports/round-101/mutations/ver9_baseline_r100.json --registry-only
   --runner corpus/fixtures/run_battery.py --report <dir>/preflight.json`
   → must PASS. FAIL here (`registry_prior_case_missing` / `registry_static_mismatch` /
   `registry_duplicate_names`) means a prior CASES row was dropped, renamed, or mutated — stop
   and fix before spending battery time.
   Re-run the same command **after** the round's CASES rows land, adding
   `--expect-new-prefixes <the prefixes the new rows actually use>` (check with
   `registry_new_prefix_census` in the report); `registry_new_prefix_empty` then means the
   expected new rows are missing. Do not pass a prefix before it lands — it fails by design
   (observed today: same command with `--expect-new-prefixes r101_` → FAIL
   `registry_new_prefix_empty`, because r101 rows are not in the registry yet).
2. Record `sha256sum corpus/fixtures/run_battery.py` and the seed-tree path in the round record.
3. Run the battery yourself, unmodified copy, e.g.
   `python3 corpus/fixtures/run_battery.py --godot /usr/bin/godot --runs <dir>`
   (the r100 verifier ran from a frozen tree copy at `/var/tmp/r100-verify/tree/corpus/fixtures`;
   no opt-in probe flags are needed for the 7 probe rows).
4. Regression gate: `python3 reports/round-101/mutations/ver9_prior_rows.py
   --baseline reports/round-101/mutations/ver9_baseline_r100.json --current
   <dir>/<ts>/verdicts.json --runner corpus/fixtures/run_battery.py
   --expect-new-prefixes <landed prefixes> --report <dir>/regression.json` → **must exit 0**.
   Pass every prefix actually used by the round's new rows; with no prefixes the only-new
   census is report-only (weaker).
5. Acceptance is the 0-mismatch criterion: `failures == []` — no dropped prior case, 0 tuple
   mismatches, 0 multiplicity violations, all prior discrimination keys still true, census
   `dead_entry_count == 0` and `rows_with_expected_errors >= 80`, only-new all PASS and
   prefix-censused.

## 7. Caveats / retained unknowns

- **Observation vs inference**: everything in §2–§5 is observed output; the "expected 516 rows"
  figure is inference from the dedupe history plus the registry parse, to be confirmed by the
  actual integration run — the comparator accepts either multiplicity only where the baseline
  records a disposition, so a pre-dedupe 519-row run would fail C3 by design.
- Cross-host determinism of any field is not claimed (same host, same day, two runs).
- The baseline extract cannot reconstruct dropped `output`/`command` fields; the full receipts
  are only in `/var/tmp` (sha-pinned above). A later round wanting those must re-run.
- Mutant receipts were slimmed to the comparison scope (7 fields + probe keys): the first
  unslimmed write hit `OSError: [Errno 122] Disk quota exceeded` on `/tmp` (tmpfs 16 G, 80 %
  full, 3.1 G free) — a documented, comparison-neutral reduction, not a scope reduction.
- `--registry-only` does not check CASES markers against record signatures (the 10 known
  benign divergences in §3); the marker comparison is intentionally out of scope.
- `ver9_selftest.py`'s synthetic positive case (M12) proves the prefix path; the actual r101
  row names/prefixes are unknown at this seat and must be passed by the orchestrator.
