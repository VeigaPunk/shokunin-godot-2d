## Mutation design

Two arms, both inserting one source line into the replay loop of a scratch copy at the
exact anchor, reusing the anchor line's own indentation (verified by byte grep: anchors at
`r100b_seq.gd:96` and `:112`, one match each; the script refuses to run if the anchor match
count is not exactly 1):

| arm | anchor | injected source line | forged fixture sha256 |
|---|---|---|---|
| `extra` | `await _cell_hover()` | `print("FORGED_EXTRA_CELL_OUTPUT")` | `f13005f1a8e526a3034a1d477cc7fe18f30bbfd97493b6a941a0e5f7694e983c` |
| `forged_cell` | `await _cell_warp()` | `print("PASS r100_gui warp FORGED_EXTRA_CELL_OUTPUT cursor=(99.0, 99.0)")` | `5510769cd8f3afa6199e94f9147109a9217b2312a6c46dffc125fb632a579680` |

Why these shapes: `extra` is the r100-critic `m_seq` shape (a foreign non-`PASS` line); the
`forged_cell` shape is strictly stronger — it mimics the pin dialect (`PASS r100_gui warp …`)
with a fabricated field, so it also tests whether the fix is sensitive to *cell-set* changes.
Both land between two genuine cell lines, i.e. inside the transcript, not at its edges.

## Harness fidelity (why the classification is the landed one)

The script seeds itself from the harness's own bytes, not from a paraphrase:

* `CASES` → `ast.literal_eval` of the landed list (509 rows; source label `ast-literal`,
  module-import fallback never needed);
* `classify_process` → the harness's own nested function located by `ast.walk`,
  compiled from its `ast.FunctionDef` node and executed standalone (its body has no free
  variables). So exit-code equality, signature substring test, `ERROR:` allowlist and
  `SCRIPT ERROR:`/`Parse Error:` rejection are the landed semantics;
* the per-row `expected_errors` dict → the landed `{...}.get(name, ())` dict literal,
  `ast.literal_eval`'d (`('ERROR: Parameter "t" is null.',)` for both seq rows);
* **per-row flags**: each row is launched with its own `--clean=1` / `--clean=0`. This was
  a real bug in the first version — a single `--clean=1` invocation classifies `noclean`
  FAIL — and the control gate caught it. A single shared run cannot classify both rows.

Command shape is byte-identical to the harness's `execute()`:

```
godot --headless --path <scratch> --script res://r100b_seq.gd -- --clean=1   # or --clean=0
```

Scratch is minimal: `project.godot` (89 bytes, `[application]` only, no autoloads/main
scene) + `r100b_seq.gd`. Nothing else in `corpus/fixtures` is referenced by that launch;
`--full-copy` reproduces the harness's whole-directory scratch if wanted.

Control gate: an unmutated run must classify both rows PASS, else the run prints
`RESULT: INVALID` (exit 2) — a broken launch must never be misread as a rejection.

Outcome definition: `ACCEPT` = all rows PASS (mutant survives); `REJECT` = any row FAIL.
`--expect accept|reject` sets the expectation; `RESULT: PASS` iff observed == expected.
Also emitted: in-memory simulation of a joined-transcript pin, an optional real
post-fix harness copy, and a per-file repo-pristine check.

## Which pin shapes actually kill which forgery (measured on the captured bytes)

Simulated over this run's transcripts (A0/A0b use the control transcript as the pin):

| shape | `extra` arm | `forged_cell` arm |
|---|---|---|
| A0 joined-14-line transcript as **substring** of output | **rejects** | **rejects** |
| A0b equality of the filtered `PASS r100_gui` block | **accepts** | rejects |
| A1 cell count = 14 + cell order | **accepts** | rejects |
| A2 `PASS r100_gui` line-set equality | **accepts** | rejects |
| A3 total output line count | **rejects** | **rejects** |

Read this carefully, it is the actionable result for C2: pinning only the 14-cell
transcript *as a filtered block* (`"\n".join` and compare against the filtered lines), or
only a cell set/count, **does not reject the `extra` arm** — the forged non-`PASS` line is
invisible to those shapes, which is the exact blind spot r100-critic F2 describes. A pin
that sees interleaving (contiguous transcript substring) or total line count does reject it.
`forged_cell` is killed by any cell-sensitive shape because it adds a 15th `PASS` line.

## Labels

* **Observation**: every transcript line count, digest, PASS/FAIL and JSON field quoted
  above comes from an executed godot run or from bytes captured by one.
* **Simulation**: the joined-transcript pin, the emitted post-fix harness, and the A0–A3
  matrix are computed shapes over observed bytes — not the landed C2 fix. The acceptance
  test is `--expect reject` against the actual landed harness.
* **Unknown**: whether the landed C2 pins cover all 14 cells in the exact shape A0 assumes;
