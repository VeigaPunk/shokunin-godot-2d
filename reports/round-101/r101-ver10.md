## 1. Receipt anatomy (read-only observation, with code cites)

* A battery run materialises `corpus/live/runs/<stamp>/` (`run_battery.py:1669-1674`) and ends by
  writing `verdicts.json` (`:5332-5335`). Optional probe artifacts land beside it
  (`fault-verdicts.json`, `export-launch-verdicts.json`, `save-process-verdicts.json`, …).
* `verdicts.json` top level: `godot`, `seed` (fixtures dir), `scratch`, `probe_failing`,
  `results[]`, `verdict` (+ per-probe extras in some revisions: `probe_elapsed_s`, `started_utc`,
  `totals`, `done_marker`).
* Per-row record, `:2291-2297`:
  `case, script, flags, command, xdg_data_home, expected_exit, actual_exit, signature, verdict,
  error, output, expected_errors, required_stderr` — `output` is the **merged stdout+stderr**,
  `strip().splitlines()`; `required_stderr` rows additionally anchor stderr-only fragments.
* **`signature` is the pin, not the observation** (`:2293 "signature": evidence`); multi-variant
  rows store the whole tuple (`:2270-2287`, e.g. `input_lattice_pre_frame` at `:338-340`, two
  observed modes, PASS iff *any* variant appears). Classification is substring/any-variant, so
  pins are stable by construction while the surrounding receipt lines are not. That asymmetry is
  the protocol's strict arm (§4 step 4).

## 4. Protocol — the ×2 gate to run at integration

**Preconditions (all must hold, else the comparison is void):**
P1 same pinned tree: `git rev-parse HEAD` recorded; `sha256sum corpus/fixtures/run_battery.py`
   recorded and equal for both runs (the checker re-hashes it from `seed` and prints it).
P2 same Godot binary: `/usr/bin/godot --version` recorded once.
P3 same environment shape: same shell env, same `--runs` root **absolute** and outside the repo
   (recommend `/var/tmp/r101-runs`; `/tmp` is a full tmpfs here — §0), same flag set (no `--probe-*`
   unless both runs get it).
P4 runs are sequential (never concurrent — concurrency inflates the very load-sensitivity being
   censused), each detached and bounded: `timeout 2400`.
P5 both runs must end `PASS battery` (rc 0). A FAIL run is an integration event, not receipt drift.

**Commands (verbatim):**
```
cd <pinned tree>
mkdir -p /var/tmp/r101-runs/r1 /var/tmp/r101-runs/r2
date -u +%FT%TZ > /var/tmp/r101-runs/r1.start; uptime >> /var/tmp/r101-runs/r1.start
setsid timeout 2400 python3 corpus/fixtures/run_battery.py \
    --godot /usr/bin/godot --runs /var/tmp/r101-runs/r1 \
    > /var/tmp/r101-runs/rep1.out 2> /var/tmp/r101-runs/rep1.err
date -u +%FT%TZ > /var/tmp/r101-runs/r2.start; uptime >> /var/tmp/r101-runs/r2.start
setsid timeout 2400 python3 corpus/fixtures/run_battery.py \
    --godot /usr/bin/godot --runs /var/tmp/r101-runs/r2 \
    > /var/tmp/r101-runs/rep2.out 2> /var/tmp/r101-runs/rep2.err
R1=$(ls -d /var/tmp/r101-runs/r1/*/ | tail -1); R2=$(ls -d /var/tmp/r101-runs/r2/*/ | tail -1)
python3 reports/round-101/mutations/ver10_receipt_stability.py "$R1" "$R2" \
    --json /var/tmp/r101-runs/stability.json
echo "checker rc=$?"           # 0 = gate green, 1 = REJECT, 2 = NOT-A-PAIR
```

**Pass/fail rule.** Gate is green iff checker rc = 0, i.e. verdict ∈ {`IDENTICAL`,
`ACCEPTED-VARIANCE`}, the **claim arm is empty** (per-row `signature` / `required_stderr` /
`expected_errors` / `expected_exit` / `actual_exit` byte-equal — a difference means the pin
changed) and every receipt difference falls in a declared class from §6. `REJECT` = content
drift, `NOT-A-PAIR` = a precondition (P1–P5) broke. Raw `cmp` on the two `verdicts.json` is
**expected to fail** and is not the gate; the normalized byte arm is reported as
`normalized_byte_equal` for completeness (false on every real pair observed, true on a pair
differing only by stamp/paths — e.g. the stamp-only forgery below).

## 6. Acceptable-variance census (which receipt fields may differ, and when)

| class | field(s) it can appear in | may differ when | evidence | normalized by |
|---|---|---|---|---|
| `stamp_path` | `scratch`, `command`, `xdg_data_home`, `artifact`, any path inside a receipt line | always — every run has its own stamp/dir | every pair (structural); r25 pair scratch | any token containing the run stamp → `<RUNPATH>` |
| `pid_token` | row `output` lines, probe sub-records | rows that launch/observe processes | r88 pair: `save_process_{writer,reader,missing}`, `descendant_pipe_*` | `(godot_pid\|spawned_pid\|pipe_pid\|pid\|child_pid\|…)=N` → `<PID>` |
| `aslr_address` | crash rows' stderr dump (`Load address:`, `[N] 7f…`, bare 12+ hex) | ASLR — every launch | r88 pair `crash_spontaneous_sigabrt`; harness `:2262` says the backtrace is deliberately not pinned | → `<ADDR>` |
| `masked_digits` | peer-UID lines | kernel-assigned ids | r88 pair `r88_surfaces_mp_loopback` `uid_c=`; r88 `rep_analysis.py` declares `\d{4,}` → `<UID>` | 4+ digit runs → `<N4>` |
| `float_drift` | `tween_flash` `transient_modulate` | sampled at whatever frame the host delivered | r25 pair: **only** difference in 39 rows; r88 pair; my ×2 at HEAD | floats → `<F>` (case-allowlisted only) |
| `frame_phase` | `input_lattice_*` / order-lattice `post_ph,[post_pr` step lists | frame delivered before/after the input flush | r88 pair `press_phys` (2 vs 3 steps); harness declares bimodal (`:2270-2276`) | `(ph\|pr)+N{…}` → `<STEP>`, runs collapsed |
| `line_order` | any multi-line `output` | merged stdout+stderr interleave; classifier is substring-based so order is not a claim | r88 pair probe rows; harness pins anchors, not order | masked line multiset equality |
| `timing_float` | meta-probe fields (`elapsed_seconds`, `dead_observed_at`, `probe_elapsed_s`, measured/cleanup seconds) | wall-clock measurement | 790-pair field census; harness `:1331` "Pinning them would pin the host's scheduling" | field-name allowlist + float mask |
| `race_presence` | probe fields `None` vs measured (`dead_observed_at`, `descendant_kernel_ppid_at_return`) | bounded race won/lost | r88 pair | probe-only allowlist |

Everything else is `REJECT`. The claim arm (§4) is never masked.

## 7. Limits / unknowns (labeled)

* **Observation**: ×2 byte-identical receipts measured for 2 of 3 targeted HEAD cases (with
  stderr identical in all three); the stored 39- and 215-row pairs' censuses above.
* **Protocol, not a measured pass**: the full 509-row ×2 battery has not been run with this
  checker (hard rule 1). A 509-row census at HEAD must be produced by the integration run; the
  checker emits it automatically. Unknown: how many HEAD rows will land in `frame_phase` /
  `line_order` / `timing_float` under load ≥30 — no stored same-harness ×2 pair at r99+ exists.
* The two validated pairs are older harness revisions (39 / 215 rows vs 509 at HEAD): classes are
  evidence-backed, per-case incidence at HEAD is inference.
* `line_order` and `frame_phase` are permissive by design (merged-stream order and step-count are
  not pinned claims); the strict claim arm (signature/exit codes) is what keeps the gate honest.
  If the orchestrator prefers a hard order requirement, add `--ordered`-style strictness later —
  it would fail the r88 pair today (probe interleave), so it is not on by default.
* Row-count 509 / 0 duplicate names at HEAD verified by AST parse (no execution) of the committed
  `run_battery.py`.
