## 4. First principles: Y vs X translation in the 2D physics server

**Pipeline** [D, from fixture source + engine semantics]: `intersect_point` =
broadphase AABB query (collect candidates) → narrowphase point-in-rectangle tests →
results appended in **broadphase traversal order**. The installed binary contains
`GodotBroadPhase2D` / `GodotBroadPhase2DBVH` symbols and **0** `hashgrid` strings
(`strings -a /usr/bin/godot | grep -ci hashgrid` → `0`) [O] — i.e. the 2D broadphase is a
bounding-volume hierarchy, not a coordinate hash grid.

**Deduction.** The BVH's structure is a function of insertion sequence and AABB
comparisons (`a.min_x` vs `b.min_x`, `a.max_y` vs `b.max_y`, centroids, …). Translate every
body and the query point by the same vector `T=(0,dy)` (or `T=(dx,0)`):
1. every structural comparison has both operands shifted by the same component, so with
   exact arithmetic every comparison outcome — hence the tree shape and leaf order — is
   unchanged;
2. the query point keeps its relative position w.r.t. every AABB, so the candidate set is
   unchanged;
3. narrowphase point-vs-rectangle is translation-covariant, so hit/no-hit is unchanged;
4. therefore the **hit-order permutation and the whole tick ladder are identical** to the
   untranslated run, and the only pinnable token that can change is a coordinate read from
   the bodies that still reports the absolute offset — the y column of `_relpos`.

There is **no X-vs-Y asymmetry** in this argument: AABBs are axis-aligned, the traversal
appends candidates symmetrically in both axes, and the returned vector carries no
axis-priority. The prediction is therefore "same invariance for X and Y", which is what the
committed `celloff_x1000` row already shows for X and what §5 shows for Y.

**Rounding caveat** [D+O]: translation is exact only while every translated coordinate is
representable in float32. Observed boundary: `--off=134217728` (2^27, ULP=16) with 8 px
spacing makes the *pile geometry* collapse pairwise (`t2_relpos` x values
`[32,0,16,32,0]` instead of `[32,0,16,24,8]`). The ladder permutation nevertheless still
equalled the canonical one in that run — reported as observation, no mechanism claimed.

## 8. Forgery discrimination (the C3 acceptance test) [O]

"The flag-ignored forgery" = the committed fixture launched with the row's own flags
(`--arm=celloff --off=0 --offy=1000`). Measured receipt `c_y1000_r2.out`:

- contains the committed x0 expected line → **True** (it *is* the x0 line);
- contains the new C expected line → **False**.

Hence after landing C: a fixture that parses but does not apply `--offy` emits
`y=0.0000` and the row **rejects**; a run that applies it emits `y=1000.0000` and the row
accepts. Order tampering also rejects because the ladder token (`t2:4,0,2,3,1;…`) is part
of the same pinned line (measured invariant across every legitimate translation, so it is
a stable order fingerprint). This supplies mut-4's forgery path with exact pin bytes.

## 9. Limits, unknowns, host notes

- **Untested**: dy chosen large enough to break *x* representability is impossible (y is a
  separate float component); mixed simultaneous `(dx, dy)` with `offy` consumption;
  rotated/non-rect shapes; Rigid/Character piles; tps ≠ 60; separate-thread physics. The C
  measurement adds no new conditioning class beyond the sibling rows (same arm, same ticks,
  same 60-tps StaticBody ladder).
- **Precision boundary** [O]: invariance was verified for exactly representable offsets up
  to 1e6 (ULP 0.0625) and y=2^27 (exact for equal-y bodies). At x=2^27 the pile geometry
  collapses (ULP 16 vs spacing 8); the ladder still matched — mechanism unclaimed.
- **Mechanism of the k(k−1) rotation remains the r95 [I] item**; this shard measures order
  stability under translation, not the rotation's cause.
- **Host/one-off** [O]: the very first `x0` launch (batch 1) returned `rc=0` with `0 B`

  receipts are ephemeral, all load-bearing bytes are in this shard and the patch files.
