### Icon embedding (s10) — measured
* The icon is packed **three ways**: source `icon.svg` (111 B), sidecar `icon.svg.import` (192 B),
  imported `…ctex` (92 B). The `.import` remap carries `uid="uid://4fsjlb4mppd4"` and
  `path="res://.godot/imported/icon.svg-218a8f2b….ctex"`; `type="CompressedTexture2D"`,
  `compress/mode=0`, `svg/scale=1.0`.
* **No `.uid` file is ever a pack entry.** `main.gd.uid` exists on disk (20 B, `uid://d0dhpx0bvl8oq`)
  but the pack carries `main.gd.remap` (31 B) plus `.godot/uid_cache.bin` instead. A `.uid` census
  restricted to the *pack* is always 0 — census the **project tree** and the `uid_cache.bin` size.
* **UID derivation is deterministic, not random** (≙ pinnable literal): delete `.godot` +
  `main.gd.uid`, re-import twice → `uid://d0dhpx0bvl8oq` both times; an identical `main.gd` at the
  same res:// path in a second project dir (`pristine`) also got `uid://d0dhpx0bvl8oq`. **It is a
  function of (res:// path, content), not of the project directory** — see §8 V4 for the
  discriminating triple (different path → different UID; one extra comment → different UID), which
  also disproves the "fresh random UID per project" wording in the s10 header.
* **A `.uid` on disk is authoritative and never repaired by `--import`**: a forged `uid://aaaa`
  (10 B) survived import and shipped; a **0-byte** `main.gd.uid` also survived (uid stayed 0 B).
  Effect on the pack: only `.godot/uid_cache.bin` changes size/md5 (82→57 B for the 0-byte case;
  82 B with a different md5 for the forged case; all other entries identical, `.scn` aside).
  ⇒ a UID row is only fail-closed if it pins the *derived* value, not merely file existence.
* **`config/icon` pointing at a missing file is accepted silently**: `config/icon="res://missing.png"`
  → `--export-pack` **rc=0**, no `WARNING`/`ERROR`, no icon entries (count=7), `project.binary`=227 B
  (`ECFG`, all four settings). ⇒ an icon-census row alone is not fail-closed against a broken icon;
  add a negative-control row that pins the icon-less case.

**Findings a row must encode.**
1. **Exit code does not discriminate** — corrupt settings, missing pack, non-pack file and a good
   pack all exit **0**. Only stdout separates them; a row keyed on exit status has zero depth here.
2. **After a bad `project.binary`, nothing runs** (0 `_ready`/`_process` lines). The receipt must
   assert *positive* content, not merely "no ERROR".
3. `--quit-after N≥1` still terminates the failure case, so it is a safe liveness guard;
   `--quit-after 0`/absent never exits (exit 124 under `timeout`).
4. A cwd `project.godot` does **not** override a valid pack (`vbdecoy`/`vbcwd`); it only becomes the
   fallback when the pack's settings fail to load (`qa5_decoy` ran the DECOY scene). This is a
   measured precedence rule, not a documented one.

### 2c. `--quit-after N` frame accounting (observation)
* `--quit-after N` → `_process` runs **exactly N** times for N ∈ {1, 5, 10}; `_exit_tree` reports
  `frames=N`, `eng_frames=N`.
* During iteration *k*, `Engine.get_process_frames()` = *k-1* (0-based at entry).
* `Engine.get_frames_drawn()` is **0 for every frame** under `--headless` (`RendererDummy` never
  presents) — never pin it as a frame counter.
* The receipt is deterministic: same command twice → byte-identical (`vb5` vs `vb5b`); `--fixed-fps
  240` does not change the iteration budget (372-byte failure receipt identical to the no-fps arm).

## 3. Determinism envelope — **not reproducible across a re-import** (observation)

```
warm tree:  det_a1.pck == det_a2.pck   3048 B  sha a7fa8097ef05295d…   (same imported .godot)
cold tree:  det_b1.pck == det_b2.pck   3048 B  sha 644cd9e905d2ce67…   (after rm -rf .godot + re-import)
warm vs cold: DIFFER — first difference at pack byte 1598
```
Entry-level diff: the **only** differing entry is
`.godot/exported/133200997/export-3070c538c03ee49b7677ff960a3f5195-main.scn`, differing in exactly
**4 bytes at scene offset 493..496**, inside the `node_ids` field:

```
… 09 00 00 00 "node_ids" 00 20 00 00 00 01 00 00 00 [f7 35 82 73 | 58 95 c4 25] 05 00 00 00 …
```
⇒ a per-import random node-id (inference: it is the scene's node-id seed; the field name is
observed). Consequences for the C1 "determinism sha256 ×2" row:
* two exports from **one** imported tree are byte-identical (safe to pin);
* two exports separated by a re-import are **not** (4 random bytes), so a row that re-imports and
  claims equal sha256 is false, and a row that never re-imports cannot see this.
* `.godot/uid_cache.bin` is *not* random with a fixed `.uid` state (82 B, `48d14a0e…` in every valid
  warm tree) but changes with the `.uid` input: 57 B for a 0-byte `main.gd.uid`, different md5 for a
  forged uid.

## 4. Hazards found (fail-closed gaps)

* **H1 — `/tmp` quota zeroing.** Godot's `--import` under a quota-hit `/tmp` left a 0-byte `ctex`,
  0-byte `.import` and 0-byte `.uid`, while exiting rc=0; my own `Write`/`cat >` to `/tmp` failed
  the same way (`unrecognized filesystem error`, `Disk quota exceeded`). A fixture exporting from
  `/tmp` scratch can ship empty artifacts and still "pass" every size/magic check that does not
  assert a minimum. *Mitigation:* assert imported `…ctex` size > 0 and `project.binary` size > 0, or
  use a non-tmpfs scratch root.
* **H2 — a well-formed pack can be unrunnable.** `icon.pck`/`plain.pck` pass magic, count, all
  per-entry md5 and size checks, and `load_resource_pack` returns true — yet the engine boots to 2
  `ERROR:` lines and runs nothing (0-byte `project.binary`). Only the s11 launch receipt discriminates.
* **H3 — exit code 0 for every `--main-pack` failure class** (missing file, non-pack, corrupt
  settings). Rows keyed on exit status have no discrimination here.
* **H4 — a 0-byte `.uid` survives `--import` indefinitely** and silently changes the pack's
  `uid_cache.bin`; Godot never regenerates it. Any scratch tree copied from a failed run carries the
  defect forward.

## 5. Repro of H2 (empty `project.binary`)

`repro3.sh` §B, exact sequence `rm -rf .godot; godot --headless --path $P --import;
godot --headless --path $P --export-pack "Linux/X11" $OUT`, twice on the same project:

```
  import1 rc=0   export1 rc=0 bytes=3048   pb_size=219  pb_md5=e736bb8a  sha=f07d2d3893d82ab4
  import2 rc=0   export2 rc=0 bytes=2824   pb_size=0    pb_md5=d41d8cd9  sha=4fea3000b9299beb
```
⇒ **reproduced**: the same project, same flags, same shell, one cycle apart. The empty-`pb` pack is
exactly the valid pack minus the 219-byte payload (3048−2824 = 224 B with entry/padding overhead).
Flake-rate probe: 4 further controlled `rm -rf .godot → --import → --export-pack` cycles
(`flake.sh`) were **all clean** (3048 B, `pb_size=219`), so the defect is **intermittent, not
structural**. Lane-wide count: **4 empty-`pb` packs out of 17 exports observed** (`icon.pck`,
`plain.pck`, `icon.zip` from one shell chain; `repro2.pck` from the second controlled cycle) ≈ 24 %,
clustered in time (16:23 and 16:29), never reproducible on demand. Best hypothesis (inference, not
proven): a silent pack-writer write/truncation failure under host load — the entry md5 is exactly
`MD5("")`, i.e. Godot hashed an empty buffer; `/var/tmp` had 772 G free, so it is not ENOSPC.

Integration consequence: a row that exports and then boots the pack is **flaky by construction**
unless the fixture detects `project.binary` size 0 and either retries the export once or fails with
that exact diagnostic. Mechanism is unknown (not a stale `.godot`: the dir is wiped before every
cycle; not the `.uid` state: §1 shows that changes only `uid_cache.bin`).
