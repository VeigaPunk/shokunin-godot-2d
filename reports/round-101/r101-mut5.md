## Findings

- **F1 (observation, primary):** a wrong-magic patch on the PCK is detected by any census predicate that reads the artifact's first 4 bytes; `census=REJECT` for both mutants, `ACCEPT` for the real pack. The replica predicate = magic `GDPC` ∧ version ∈ {1..4} ∧ nonzero body. Evidence bytes above.
- **F2 (observation):** Godot's own loader is a second oracle: `--main-pack` on either mutant prints exactly `ERROR: Cannot open resource pack '<path>'.` and **exits 0**. Inference: an exit-code-only census cannot see wrong magic; the census row must read bytes (magic and/or sha256). Real pack under the same command prints `MUT5_PACK_STARTED scene=main`, rc=0.
- **F3 (observation):** the legacy `export_readiness` predicate (`run_battery.py:1877-1881`) accepts all wrong-magic artifacts and even a 1 MB partial ELF — it never reads the `.pck` at all. Inference: the export_prod PCK census row must pin magic bytes and/or artifact sha256 of the `.pck`; size>0 alone is blind. Integration wiring: run `mut05.py --source <pck produced by export_prod_s01/s04>` to re-test the landed row's predicate against the same mutants; expected receipt `MUT5 PASS`.
- **F4 (observation, environment):** `/tmp` is `tmpfs` mounted with `usrquota` (`findmnt`: `rw,nosuid,nodev,nr_inodes=1048576,inode64,huge=advise,usrquota`), 13G/16G used by the sibling 3D-lane swarm. Consequences seen: intermittent `OSError [Errno 122] Disk quota exceeded` on 2 KB writes; `dd bs=1M count=32` to `/tmp` → 0 B written; same 32 MB to `/dev/shm` → OK. This is why `--export-release` fails (`Failed to copy export template`, 73.5 MB copy) while `--export-pack` (PCK only, no template copy) succeeds. Inference: seats needing executable-producing exports on this host must prefer `--export-pack` or wait for quota relief; not a Godot fault.
- **F5 (observation, bonus):** `--export-pack` twice → identical sha256 `b90fad33…` for `pack.pck`/`pack2.pck` (byte-identical artifacts). Note for the E3 determinism row.
- **Unknown:** whether the landed `export_prod_s01/s04` rows inspect the `.pck` bytes (fixtures absent at run time); whether a wrong-magic *embedded* PCK (inside the exported executable) produces the same loader error class (no full binary export possible under the current `/tmp` quota).
