## Measured mechanics (observation unless marked inference)

### M1 — the Linux/X11 preset option `application/run/main_scene` is INERT for PCK exports
Preset carried `application/run/main_scene="res://alt_main.tscn"` while
`project.godot` kept `run/main_scene="res://main.tscn"`.

```
$ godot --headless --path /tmp/r101-E4/scratch --export-pack "Linux/X11" /tmp/r101-E4/p1/out.pck
EXPORT_EXIT=0   p1/out.pck = 3424 B   magic = 47445043 "GDPC"
$ godot --headless --main-pack /tmp/r101-E4/p1/out.pck --quit-after 30
EXIT=0  stdout=200 B:
    [s04-main] default=true frames=1..3      # the project.godot scene, not alt
```
A reader project (`ProjectSettings.load_resource_pack`) read the packed
`res://project.binary` (168 B, first bytes `45434647` = ECFG). Decoded ECFG:
key `application/config/name` -> `R101E4Prod`; key `application/run/main_scene`
-> `res://main.tscn`; key `application/config/features` -> `["4.7"]`. The string
`alt_main` is absent from the 168 bytes. Hence the packed main scene came from
project.godot, not the preset. (Direct `strings` check: the binary contains
`application/run/main_scene` once, consistent with the project-setting name;
nothing proves an export-option slot exists on this platform — PCK-only scope.)

### M2 — the swap lever that works: rewrite `project.godot` between states
At export time `run/main_scene="res://alt_main.tscn"`; after export restore
`res://main.tscn`. The already-written pack keeps the build-time value.

```
$ godot --headless --path /tmp/r101-E4/scratch --export-pack "Linux/X11" /tmp/r101-E4/p2/out.pck
EXPORT_EXIT=0   p2/out.pck = 3424 B   GDPC
$ godot --headless --main-pack /tmp/r101-E4/p2/out.pck --quit-after 30
EXIT=0  stderr=0 B  stdout (cat -A):
    Godot Engine v4.7.2.stable.arch_linux.ed1daf0bf (2026-08-17 01:18:38 UTC) - https://godotengine.org$
    $
    [s04-alt] swapped=true frames=1$
    [s04-alt] swapped=true frames=2$
    [s04-alt] swapped=true frames=3$
```
Frame receipt: the scene self-quits at frame 3; `--quit-after 30` is an upper
bound, so the receipt is exactly `frames=1,2,3` (deterministic), not "30".

### M3 — after the swap is exported, restoring project.godot restores the direct run
`godot --headless --path <proj> --quit-after 30` on the restored project prints
`[s04-main] default=true frames=1..3` (stdout 200 B, exit 0, stderr 0 B). This
is the "editor default differs from the packed main scene" contrast; the fixture
asserts both directions before printing PASS.

### M4 — /tmp on this host is quota-limited; export writes can truncate silently
Observed repeatedly (not a fixture bug):
```
$ tee /tmp/r101-E4/exp_dbg.log   ->  tee: /tmp/r101-E4/exp_dbg.log: Disk quota exceeded
$ godot --headless --path scratch --export-release "Linux/X11" out/out.pck
  ERROR: Prepare Template: Failed to copy export template.
  out/out.pck = 60751872 B, ELF magic, byte-identical 60 MB PREFIX of the
  73519416 B template   (partial copy)
$ --export-pack ...  -> 1740 B PCK (truncated) vs 3424 B on a clean run
$ one ovr arm under pressure -> pck_bytes=3264, child stderr=271 B; re-run
  immediately after -> pck_bytes=3440, child stderr=0 B
```
`df -h /tmp` reported 16 G / 13 G used / 3.1 G "available" while `write()`
returned EDQUOT, so availability numbers are misleading. Mitigations in the
fixture: scratch on `user://` (this repo's volume), child `TMPDIR` inside the
scratch tree, and child stderr recorded (not asserted, because of the one
transient 271 B observation). `--export-release <path>.pck` is not a PCK
export on this build — it attempts an executable/template write; PCK-only
export is `--export-pack`.

### M5 — PCK sha256 is NOT stable across identical exports (same size)
Six independent exports of the same project/recipe: sha256 `1be27173…`,
`63856472…`, `d7a2b7d4…`, `55f3868b…`, `57c8db4e…`, `4868d7b0…`; size 3440 B
each (the 3264 B sample is the quota-pressure anomaly). Difference is
length-preserving. Inference (not proven here): generated `.uid` files / cache
content differ per run — the exporter mints `main.gd.uid` / `alt.gd.uid` on
first scan. Directly relevant to E3's determinism rows: byte equality of raw
PCKs is not a valid pin; compare after normalisation or pin size+census.

### M6 — pack entry shape observed while reading a pack from a reader project
`DirAccess.get_files_at("res://")` after `load_resource_pack` listed:
`alt.gd.remap, alt.gdc, alt_main.tscn.remap, main.gd.remap, main.gdc,
main.tscn.remap, project.binary, project.godot` (scripts/scenes are
`.gdc`/`.scn`-style remaps; only project.binary + uid_cache are raw). Reader
detail: `get_string_from_ascii()` truncates at the first NUL, so substring
probes on ECFG bytes are invalid; decode the hex instead (M1).

## Cross-seat observations (do not duplicate blindly)

- **E0 overlap**: `corpus/fixtures/export_prod.gd` already lists arms `swap`
  (`export_prod_main_scene_swap`) and `export_prod_mainpack_quit_after_frames`.
  Semantics differ: E0 reports the pack keeping the pre-swap scene after the
  source is swapped; s04 exports with the swapped value and then restores the
  editor default plus a direct-run control. Dedupe/keep both is an integration
  decision; s04 stands alone (validated here).
- **E1/E3**: use `--export-pack` for PCK-only targets. `--export-release
  <path>.pck` did not produce a PCK here (template-copy path; failed under the
  /tmp quota). PCK sha256 is length-preserving non-deterministic (M5) — do not
  pin raw PCK sha256; pin size/census/normalised regions.
- **E5/E10**: the exporter mints `<script>.uid` files in the *project* dir
  (`main.gd.uid`, `alt.gd.uid`) during export; pack entries are `*.gd.remap` +
  `*.gdc` + `*.tscn.remap`, with `project.binary` and `.godot/uid_cache.bin`
  stored raw. A project.binary reader must decode hex, not `get_string_from_ascii`.
- **All seats**: `/tmp` EDQUOT is real under the concurrent 3D-lane swarm
  (M4). Prefer `user://` scratch, redirect child `TMPDIR`, and never infer
  success from an artifact's existence alone (a 1740 B truncated PCK still had
  GDPC magic).
