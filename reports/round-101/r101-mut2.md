## Findings

**F-M2-1 (MEDIUM, measured — the seat's target class: forged receipt lines are
invisible to receipt-pinned clauses).** A forged extra non-ERROR receipt line
leaves **every** clause shape True (V1), including the artifact-re-reading ones —
because those re-read the artifact, not the transcript. A duplicate forged
`[ DONE ] savepack` line also passes (V1b): `"[ DONE ]" in output` is
occurrence-blind. V5 shows the same for a launch receipt: a forged `READY` line
appended to a silent run is indistinguishable from the genuine receipt under a
substring pin (V5 vs V5c), and the harness's only exact-count guard
(`probe_export_launch`) is probe-local, while the engine's own `[ DONE ]` receipt
is ANSI-wrapped so a naive whole-line equality pin is not even expressible.
The measured boundary is the `ERROR:` family: only forged `ERROR:`/`SCRIPT
ERROR:` lines reject (V2). This is the export-row analogue of r100-critic F2 (and
of the r63 `descendant_pipe_forged_signature_release` precedent, `:1645-1651`:
signature presence is origin-blind).
*Consequence for C1:* a row whose evidence is a receipt line detects
"receipt absent/contradicted" only. It cannot detect "real receipt + extra forged
claims", and cannot distinguish a forged receipt from a genuine one. A receipt
pin needs pairing with (a) fixture-side fail-closed re-derivation (the landed
`export_prod_s10.gd` pattern: `_census_ok` + 4 internal forgery controls) or
(b) a paired negative arm with exact-count (the `probe_export_launch` pattern).

**F-M2-2 (MEDIUM, measured — artifact conjunct sufficiency).** The landed export
clause accepts a **junk artifact** (V3: 4608 B, magic `MUT2`, receipt genuine →
`landed_export=True`) and a real pack whose magic was patched `GDPC`→`GDPX` (V4 →
`landed_export=True`). Existence and size conjuncts do work (V3b/V3c False). So
for the C1 lattice, `size>0` is not enough: the discriminating conjunct must
re-read content (magic / sha256 / parse), which `magic`/`sha256` clauses do. This
independently reproduces CRIT-1's "fake PCK magic via header patch" and `size>0`
vacuity attack classes on my own bytes (overlap declared; kept because these are
the receipt-line companion arms).

**F-M2-3 (environment, measured).** `/tmp` is quota-blocked on this host right
now: `df` `16G 13G 3.1G 80% /tmp`, and a **13-byte** `printf 'quota-probe' >
/tmp/...` → `Disk quota exceeded` (16:25; also a 1.8 KB config copy at 16:22).
Consequence: fixtures with a hardcoded `/tmp` scratch root — e.g. landed
`export_prod_s10.gd` `SCRATCH_ROOT := "/tmp/r101-E10"` (sha256
`73986b5d02a98f62ec672014807e66b0d703a830d3825a342708eb008dc12033`) — are
exposed to `EDQUOT` on this host today; `/var/tmp` worked for 73 MB+126 KB
exports here. Unknown whether the integration battery's quota state differs then.

**F-M2-4 (minor, measured — invocation shape).** `export_prod_s10.gd`'s header
advertises `godot --headless --script corpus/fixtures/export_prod_s10.gd`; from
the repo root that command **fails deterministically**: `RC=1` with
`SCRIPT ERROR: Parse Error: Cannot infer the type of "imp_text" variable ...`
at `:244`/`:281` plus `:284-285`/`:291-294` (`Warning treated as error.`) and
`Failed to load script "res://corpus/fixtures/export_prod_s10.gd"`. With project
context the same bytes parse: `godot --headless --path corpus/fixtures
--check-only --script res://export_prod_s10.gd` → `RC=0`. The battery's
invocation shape (`--path scratch --script res://…`) is the passing shape; only
the header's standalone command is not literal-run — one-line doc fix for E10.
Both runs also print 3× `Unicode parsing error … Unexpected NUL character` after
the banner; classifier-inert (no `ERROR:`), noted so no seat chases it.

## Verdict and what the judge should weigh

**Complete.** The seat's question — "does a forged receipt line in an export row
pass?" — is answered by measurement on real bytes: **yes, as long as it is not
`ERROR:`-family and no conjunct re-reads the artifact content** (V1/V1b/V3/V4/V5),
and **no, only when** the forged line trips the diagnostic watch (V2) or the
conjuncts re-measure (magic/sha → V3/V4) or a size/existence conjunct fails
(V3b/V3c). The exact-count + negative-control pair (V5c silent control) is the
only shape that separates a forged launch receipt from a genuine one, and that
guard exists in the harness only probe-locally (`probe_export_launch`).
Recommendation for the C1 lattice: every receipt-bearing row should either pin
content re-derivation conjuncts (magic/sha/parse) or rely on fixture-side
fail-closed controls; receipt-string pins alone are origin-blind.

**Not measured (declared):** no battery run (hard rule 1); the full C1 lattice
rows (only `export_prod_s01.gd`/`s10.gd` landed so far — no CASES rows exist to
attack yet); no full `s10` run (its hardcoded `/tmp` root would delete E10's live
scratch — cross-seat hazard, avoided; foregone: its receipt bytes from a real
run); the `--main-pack --quit-after` frame-count receipt (s11/ver11 own it);
determinism sha ×2 rows (s03); the r100b full-replay forgery (C2 seat); `--offy`
(C3). Clause shapes are verbatim copies of live HEAD bytes; the arm classifications
are direct executions of those copies on real capture bytes + one disclosed
artifact mutation per arm (junk/truncate/delete/magic-patch), not of the harness
process itself.
