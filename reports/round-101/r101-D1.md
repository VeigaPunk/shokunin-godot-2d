## 6. Findings and recommendations for the C2 pin author (F-series)

* **D1-F1 (MEDIUM, arm split).** A full-replay pin set must carry **two** cell-3 lines: `h0=null` for `--clean=1`
  and `h0=P` for `--clean=0`. Pinning one hover line for both rows makes one row fail; pinning only the tail after
  `hover ` hides `h0`, which is the only cell-3 token that encodes the cross-cell pickup mechanism (S10).
* **D1-F2 (MEDIUM, forgery discrimination).** Because the harness's evidence check is a substring test (per
  `r100-critic` §F2), a forged extra **line** between cell prints survives any set of *separate* cell pins. Cells
  1–5 are one print each and are consecutive stdout lines (source-forced: exactly one `print` per cell body,
  `SEQ_DONE` last), so a **contiguous multi-line transcript** — `"\n".join` of cells 1–5, or the 5 line block plus
  cell 6 — rejects an insertion that individual pins cannot. Caveat: the evidence string must be accepted verbatim
  (newlines included) by `classify_process`; that path is the author's to verify (out of my scope).
* **D1-F3 (LOW, derivation anchors worth pinning).** Cells 2/4/5 contain tokens that discriminate semantics, not
  just formatting: `s9_rb` (child left IGNORE → P gets `b=2`), `s10_input_state held_push=0 cursor=(0.0, 0.0)`
  (push ≠ Input state), `m3_dc` (`dc=1` echo), `loc_c=-24.0,-12.0` (local mouse pos follows the cursor, not the
  delivered event). If C2 lands a compressed pin, keep these four; they are the cheapest forgeries to catch.
