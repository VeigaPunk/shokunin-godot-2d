**Format finding (observed):** on this platform `--export-release "Linux/X11" <path>.zip` is NOT a project-content zip. It is a zipped **app bundle**: the stock `linux_release.x86_64` template executable (byte-identical, 73,519,416 B) plus the exported PCK (byte-identical to the standalone PCK). Project files live inside the embedded PCK, not at zip top level. `zip1` vs `zip2`: entry contents identical (same entry sha256/CRC); whole-file shas differ because per-entry DOS `date_time` differs (`[2026,10,18,16,30,14]` vs `[2026,10,18,16,30,18]`). ## PCK format 4 — layout reversed from bytes (parser-verified)

Header, first 40 bytes (hex):
`47445043 04000000 04000000 07000000 02000000 02000000 70000000 00000000 10090000 00000000`

| offset | field | observed value |
|---|---|---|
| 0x00 | magic | `GDPC` |
| 0x04 | pack_format_version | 4 |
| 0x08/0x0c/0x10 | engine major/minor/patch | 4 / 7 / 2 |
| 0x14 | unknown word | 2 (meaning unknown) |
| 0x18 | data_offset (u64) | 112 |
| 0x20 | dir_offset (u64) | 2320 |
| 0x28–0x6f | reserved zero padding | header size = 112 |
| @dir_offset | u32 file_count | 11 |
| per entry | u32 path_len_padded, path bytes (root-relative, **no `res://`**, NUL-padded), u64 offset_rel, u64 size, 16-byte **MD5**, u32 flags | absolute = data_offset + offset_rel |

The directory ends exactly at EOF (last entry's flags end at 3124). All 11 entry offsets are 16-byte multiples; unreferenced spans between entries are 1–15 B alignment slack; `data_last_end=2312`, then 8 zero bytes of padding to `dir_offset=2320`. Unknown: header word @0x14=2; gap bytes were not content-analyzed.
