## F1 — Timeout truncation: probe fail-closed, receipt replay fail-open

Observation. `positive_then_hang` (prints the signature, then blocks 60 s):
killed at 5.01 s, `launch_exit=None`, `launch_error="TIMEOUT after 5 seconds"`;
partial capture is a true byte prefix and **contains the signature**:

```
launch_output: ['Godot Engine v4.7.2.stable.official.ed1daf0bf - https://godotengine.org', '', 'EXPORT_LAUNCH_READY scene=fixture']
tail_hex: ...455f5245414459207363656e653d666978747572650a
TimeoutExpired stdout type: bytes   (Python 3.14.7, text=True)
```

- The captured bytes are **byte-identical** to the healthy `baseline_positive`
  capture (`launch_output` lists equal; both tail hex end `...666978747572650a`).
  Under truncation the receipt's *content axis* cannot distinguish a clean
  exit from a process killed at the bound.
- `truncation_tail_loss` (signature → 6 s block → `printerr("ERROR: late fault")`)
  shows the complement: the late diagnostic is **never captured** (`"late fault"`
  absent from `launch_output`). Truncation silently drops post-signature content.
- Probe assertion on both rows: `False`; the battery verdict formula³ on a hang
  row returns `FAIL`. **Fail-closed.**
- But a replay of the recorded receipt that checks only `signature_lines == 1`
  accepts both truncated rows (`naive replay = True`). The recorded row says a
  process that never exited produced the expected startup event; only the
  `launch_exit` / `launch_error` fields reject it.

Required pin (already what the probe computes, `run_battery.py:4487-4490`,
verdict `4517-4523`): keep the **full conjunction** `launch_exit == 0 AND
launch_error is None AND len(signature_lines) == 1` (+ cleanup axes). Any
downstream grader reading `export-launch-verdicts.json` must not collapse it to
signature presence, because the timeout path preserves the signature line while
truncating everything after it.

Label: observation. Inference: the same content-identity holds for any
post-signature pathology that outlives the 5 s bound (a killed process's output
prefix is all that can ever be recorded).

## F2 — The signature channel is forgeable (merged stdout+stderr)

Observation. The probe classifies `proc.stdout + proc.stderr` (`4481`) and
matches the signature against that merged string (`4486-4487`), and the receipt
stores only the merged list (`4508`) — no stream attribution.

- `stderr_only_signature` (`printerr(...)` instead of `print(...)`): aux raw
  streams `stdout='Godot Engine v4.7.2...\n\n'`, `stderr='EXPORT_LAUNCH_READY scene=fixture\n'`;
  probe assertion **True**, sig_lines 1, exit 0. A signature that never touches
  stdout is accepted.
- `seam_split_signature` (`printraw("EXPORT_LAUNCH_READY scene=")` then
  `printerr("fixture")`): aux raw `stdout='...scene='` (no newline),
  `stderr='fixture\n'`. **Neither stream contains the line**; the merged string
  synthesizes one full match. Probe assertion **True**, sig_lines 1, exit 0.

Battery verdict formula³ over these rows (forged positive + `baseline_negative`
control, packs differ `2068034d…` vs `871cd061…`, `out/` empty for both):
**PASS** (computed, not run). So the probe would report PASS for a positive
build whose startup event was never printed as a whole line by any stream.

This is the same origin-blind merged-capture boundary documented at
`run_battery.py:2719` (r100-F1), and the codebase already hardened other cases
by splitting streams — `run_process_streams` (`1709`) and `classify_streams`
(`1744-1746`, "Signature must appear on stdout"). The export-launch probe has no
stream-split variant and no stdout anchor; it also records no stream attribution
in its receipt, so the forgery is not detectable post hoc from the artifact.

Label: observation for probe assertion + raw streams; inference (computed) for
the battery-level PASS.

## F3 — Calibration notes

- Launch bound 5 s vs observed: probe-shaped no-delay app 0.70-0.85 s
  (≈4.2 s margin under load 53-58); a 3.5 s-delayed app finished at 4.23 s
  (0.77 s margin) and still passed. Bound is adequate for the probe's payload,
  tight for slow starters under this host's contention.
- Export step flakiness under tmpfs pressure: 2 of 8 payloads needed 3 export
  attempts (attempts 1-2 rc=1,
  `ERROR: Project export for preset "Linux/X11" failed.` /
  `at: _fs_changed (editor/editor_node.cpp:1417)`), attributed to `/tmp` write
  pressure (independent probe: `dd` of 2 MB wrote 0 bytes twice while
  `df` showed 3.1G avail; EDQUOT on plain `shutil.copy2`). A failed export is
  fail-closed in the probe (`exp_ok` False → launch skipped → verdict FAIL) but
  is a spurious-FAIL source on a loaded host, not a forgery channel.

## Guards / recommendations

1. Keep the export-launch assertion as the full conjunction; pin it in any
   consumer of `export-launch-verdicts.json` (F1).
2. Record `truncated: true` / `captured_seconds` explicitly, or store a
   `truncation` marker alongside `launch_error`, so the timeout path is
   self-describing (F1).
3. Add a stream-split variant of the launch probe: capture stdout/stderr
   separately, anchor the signature to stdout (`classify_streams` pattern), and
   record stream attribution in the receipt (F2).
4. Optional: a negative control that emits only the seam halves
   (expect reject) to pin F2 against regressions.

## Verdict

- **Timeout truncation on the export launch probe: probe-level fail-closed**
  (asserted False, battery verdict formula FAIL) — no forged PASS through the
  probe's own predicate.
- **Receipt-level forgery-accepting boundary confirmed**: signature-only replay
  of a truncated row accepts (F1); the merged-stream channel additionally
  accepts stderr-only and seam-split signatures, and the battery verdict formula
  computes PASS for them (F2). Fix candidate: guard 3.
