## Verdict

**The CRLF seam is real in the child's byte stream and unobservable at the
harness boundary: the mutant is verdict-inert in both directions.**

* On the **success path the harness captures with `text=True`**
  (`run_battery.py:1716` `run_process_streams`, used by `execute()`), i.e.
  through `io.TextIOWrapper` universal-newline translation. A `\r\n` seam is
  decoded as `\n` **before any pin sees it**: for the two real seam variants
  the captured text is **byte-identical to the unmutated run** (sha256 equal,
  `cr_count = 0`), so the landed 1-line pins **and** a full-replay 14-cell pin
  both classify **PASS**. This is not a discrimination gap that a harder pin
  could close — the mutation does not exist in the classifier's input space.
* On the **raw decode path** (the *timeout* branches, `run_battery.py:1703`
  and `:1719`, `bytes.decode(errors="replace")` — no newline translation) the
  seam survives. The landed 1-line pins still PASS (the seam is outside their
  own text); a `\n`-joined 14-cell pin **rejects 13/23 boundary seams**.
* A **timeout record always classifies FAIL** (`classify_process` requires
  `error is None`), so the only path where the seam is visible cannot produce
  a PASS either.

A CRLF seam therefore **cannot forge acceptance and cannot flip any verdict**,
for the seq rows or any other row. What it *can* do is defeat a raw-bytes
receipt (e.g. a byte-mode capture or hash) — no such receipt exists for these
rows (`record["output"]` stores the normalized text).

**For C2:** the full-replay pin is the right fix and it closes the *content*
forgery class (control `seamC`, the `m_seq` shape: landed pin PASS →
full pin **FAIL**, both capture modes). The CRLF seam is the complementary
negative control: a correct full-replay pin **must stay green** on it under the
harness's own capture, and any proposed "CRLF-seam pin" that goes red on the
success path would be pinning bytes the harness cannot deliver.

## 3. Boundary sweep over the real captured transcript

Every `\n` boundary of the baseline blob (stdout + stderr, 23 boundaries:
banner, blank, 14 cells, `SEQ_DONE`, the `ERROR: Parameter "t" is null.` line
and its 5 backtrace lines, plus the stdout→stderr concatenation seam) with a
single CR inserted just before it:

```
sweep clean:   23 boundaries; full-pin rejects 13/23 in raw decode;
               normalized==baseline 23/23; text full-pin rejects 0/23;
               raw landed-pin rejects 0/23
sweep noclean: 23 boundaries; full-pin rejects 13/23 in raw decode;
               normalized==baseline 23/23; text full-pin rejects 0/23;
               raw landed-pin rejects 0/23
```

* **23/23** boundary seams normalize away to exactly the baseline bytes
  (inference from the byte substitution, validated by the two real seam runs
  in §1 which reproduce the same erasure end-to-end).
* The 13 raw-decode rejections are exactly the 13 boundaries **inside** the
  14-line pinned span; the 10 non-rejecting boundaries are outside it (before
  the first pinned line, after the last, and the stderr tail) — the structural
  floor of any substring pin, including the full-replay one.
* The landed single-line pins reject **0/23** boundaries in both modes.

## 4. Timeout-decode path asymmetry (the one place the seam survives)

`run_battery.py:1719` (`run_process_streams` timeout branch, and `:1703` for
the merged variant) decodes `exc.stdout` bytes with no newline translation.
Measured on a real godot process (`r101_mut08_timeout.gd`: print the landed
clean pin with a trailing CR, print `SECOND_LINE`, `OS.delay_msec(5000)`),
captured with a 1.5 s timeout:

```
nonempty=True  cr_count=1  rc=None  error="TIMEOUT after 1.5 seconds"
pin_in_decoded_landed      = True    # the seam fell after the pinned text
pin_in_decoded_two_line    = False   # "…\r\nSECOND_LINE" ≠ "…\nSECOND_LINE"
pin_in_normalized_two_line = True    # same text after \r\n -> \n
classify_landed_pin        = False   # timeout => error is not None => FAIL
classify_two_line_pin      = False
```

So the asymmetry is real (`\r` reaches the classifier only on timeout
records), but it is **not exploitable**: the timeout branch can only ever
classify FAIL. Nine further timeout-decode sites exist
(`run_battery.py:2435, 2582, 3011, 3208, 3456, 3518, 4483, 4593, 5269`), all
feeding meta-probe *analysis* rather than row verdicts; whether a CR seam can
perturb those meta fields was **not measured here** (unknown, out of scope).

## Findings

* **F-MUT8-1 (not a defect — negative control).** A CRLF seam injected into
  the `r100b_seq` replay is erased by the harness's own capture
  (`text=True`, `run_battery.py:1716`): captured text byte-identical to the
  unmutated run, `landed` and `full14` both PASS. The seam cannot forge
  acceptance, and no row-level pin (of any shape) can or should reject it on
  the success path.
* **F-MUT8-2 (raw path).** Where the seam does survive (timeout decode), the
  landed 1-line pins are blind (0/23) and a `\n`-joined 14-cell pin rejects
  the 13 interior boundaries — evidence for the C2 fix's shape, and for its
  structural floor at the pinned span's outer edges.
* **F-MUT8-3 (asymmetry, bounded).** Success path normalizes newlines, the
  timeout decode paths do not. Verdict-inert for row classification
  (`error is not None` ⇒ FAIL); unmeasured for the 9 meta-probe decode sites.

### Recommendation for the C2 landing

Pin the full replay as `"\n".join()` of the 14 cell lines **plus** the
terminal marker (`SEQ_DONE clean=…`) — that closes the content-forgery class
(`seamC`: landed PASS → full FAIL) and the interior CRLF seams in any
byte-mode receipt, while correctly staying green on the CRLF seam under the
harness's own text capture. Do **not** add `\r` to any signature: a pin
containing a CR can never match on the success path.
