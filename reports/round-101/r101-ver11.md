## 1. The predicate every CASES row uses (the reject channel)

`run_battery.py:2301` prints per case: `f"{record['verdict']} {name}: exit={code} signature={evidence!r}"`; `record['verdict']` is `"PASS" if classify_process(code, error, merged_stdout+stderr, expected_exit, evidence, expected_errors) else "FAIL"` (`:2278`, `:2291-2295`). So:

* **PASS line**: `PASS <row>: exit=<rc> signature='<evidence repr>'`
* **REJECT (expected signature)**: `FAIL <row>: exit=<rc> signature='<evidence repr>'` plus the `verdicts.json` record `{"case": <row>, "verdict": "FAIL", "output": [...]}` — the record's `output` list is the only place the rejection reason is visible.
* `classify_process` (`:1725-1742`) = `code == expected_exit and error is None and signature in output and not unrelated_errors and not "SCRIPT ERROR:"/"Parse Error:"`. `signature in output` is **substring containment** — the root of every additive-forgery gap below.
* Per-row allowlist (`:2225-2230`): `r100b_seq_clean` / `r100b_seq_noclean` allow exactly `'ERROR: Parameter "t" is null.'` (deterministic dummy-renderer backbuffer ERROR from the render cell).

Cross-cutting lander notes (observed, not inferred):
1. **Export rows must not share a project dir.** The harness stages a fresh scratch per battery run (`run_battery.py:1673-1695`); the C1 lattice adds several export rows per run, so each new export row needs its own project copy. A second in-place `--export-release` in the project that already produced artifacts failed **5/5** here with `ERROR: Prepare Template: The given export path doesn't exist.` + `ERROR: Project export for preset "Linux/X11" failed.`, while a fresh project exported 2/2 fine. A row that reuses the dir gets a **false reject** carrying exactly that ERROR pair.
2. **A failed export still leaves an artifact**: it is the **bare template**, byte-identical to `~/.local/share/godot/export_templates/4.7.2.stable/linux_release.x86_64` (both sha `d9f79ab8…`). A size-only clause accepts it; a magic clause does not (bare template is ELF, not `GDPC`). The C1 "templates-missing error class" row must match the output text (`Prepare Template:`), not only the artifact.
3. **`--export-debug` emits three products** per target (`<n>.x86_64`, `<n>.pck`, `<n>.sh`); the `.sh` is path-dependent and non-deterministic across runs — pin the exe and the pack, never the launcher.
4. **Additive forgeries are a discrimination gap, not a classifier bug**: the same substring semantics let a forged line ride the row while sitting plainly in the payload's `output` list. Keep each new pin as a single `\n`-joined block so the existing substring check becomes an exact-block check with **no** `classify_process` change.
