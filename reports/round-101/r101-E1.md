## PCK layout (measured, not inferred from docs)
Decoded from raw bytes and confirmed against `core/io/file_access_pack.cpp` (`PackedSourcePCK::try_open_pack`):

```
off 0   u32 magic            "GDPC" (47 44 50 43)
off 4   u32 pack_version     4
off 8   u32 engine_major     4
off 12  u32 engine_minor     7
off 16  u32 engine_patch     2
off 20  u32 pack_flags       2  (PACK_REL_FILEBASE)
off 24  u64 file_base        112
off 32  u64 dir_offset       absolute offset of the entry directory
off 40..111                  reserved / padding (zeros)
file_base + data_offset       each entry's bytes
dir_offset: u32 entry_count, then per entry:
            u32 path_len   (includes NUL padding to 4 bytes)
            bytes path     (relative, no "res://")
            u64 data_offset, u64 size, 16B MD5(data), u32 flags
```
Measured invariants (three independent packs):
| pack | bytes | entries | dir_offset | max(file_base+ofs+size) | align16 of max_end == dir_offset | entry offsets 16-aligned | dir end == EOF |
|---|---|---|---|---|---|---|---|
| pck1 | 3588 | 12 | 2768 | 2767 | yes | 12/12 | yes |
| pck2 | 4568 | 14 | 3632 | 3631 | yes | 14/14 | yes |
| w1   | 4432 | 14 | 3504 | 3492 | yes | 14/14 | yes |

- Every entry's `data_offset % 16 == 0`, and `dir_offset == align16(file_base + max(ofs+size))` **exactly** in all three packs. My first guess (a 0..3 gap) was wrong: observed gap was 12 in w1 — the alignment law replaced the guess.
- Stored path length is 4-byte padded with NULs (8 of 14 paths padded in w1). Decoding those bytes raw makes Godot print `Unicode parsing error ... Unexpected NUL character`, so the classifier strips NULs before decoding and reports `padded_paths=<n>`.
- `file_base` is 112 for every pack produced here (header 40 + reserved); `R3` pins `flags==2`, `file_base==112`.

## Forgery ladder (all against the real exported pack)
Each mutation is applied to a copy of the measured pack, written to disk, and re-classified. First failing row observed:

| Mutation | Result | First failing row (observed bytes) |
|---|---|---|
| `magic` (byte 0 xor 1) | rejected | `R1 magic=FDPC expected GDPC` |
| `version` (4→5) | rejected | `R2 version=5 engine=4.7.2 expected 4 and 4.7` |
| `engine_newer` (minor 7→8) | rejected | `R2 version=4 engine=4.8.2 expected 4 and 4.7` |
| `flags_rel_base_cleared` (2→0) | rejected | `R3 flags=0 file_base=112 expected 2/112` |
| `file_base_shifted` (112→116) | rejected | `R3 flags=2 file_base=116 expected 2/112` |
| `dir_offset_plus4` | rejected | `R4 entry 0 body beyond EOF at 3516 len=1685022510` |
| `count_plus1` | rejected | `R4 entry 14 path_len beyond EOF at 4432` |
| `path_core_renamed` (`scenes/actor.gdc`→`.gdz`) | rejected | `R7a declared census mismatch matched=13/14 extras=1` |
| `payload_byte` (flip data byte) | rejected | `R6 md5_ok=13/14` |
| `truncated` (drop last byte) | rejected | `R4 entry 13 body beyond EOF at 4372 len=24` |
| `hash_path_renamed` (rename inside `.godot/exported/<hash>/`) | **known accept** | `KNOWN_ACCEPT ... accepted=true note=hash_region_is_wildcard_covered owner=s04_main_scene_receipt` |

The known accept is honest, not hidden: a rename inside the engine hash region is byte-indistinguishable from a legitimate hash change under a wildcard census. Coverage belongs to a main-scene load receipt (scenario 04). This mirrors the lane's r63 known-accepting forgery precedent.

## Export-path findings that matter to the lattice
1. **`--export-release <preset> <path.pck>` copies the 73,519,416-byte `linux_release.x86_64` template onto the destination path first, then overwrites it with the PCK.** Evidence: a run that hit EDQUOT left a 4096-byte file beginning `7f 45 4c 46` (ELF) at the `.pck` path; a run with space produced 4432 bytes beginning `47 44 50 43`. Consequence: release-to-`.pck` needs template-size free space at the destination; the failure class is `Prepare Template: Failed to copy export template.` + `Project export for preset "Linux PCK" failed.`
2. **`--export-pack` writes `GDPC` directly** (no template copy, ~4.4KB) — the fixture defaults to this so a quota-tight host can still run the row. Both modes are validated; `--export-mode=release` exercises the release path.
3. **Mode does not change the bytes**: pack-mode and release-mode exports of the same project dir were byte-identical (`bytes_diff=0`, `entries_content_differ=[]`).
4. **Fresh project dirs can differ in UID-bearing content.** Three exports from one unchanged dir were byte-identical (`623e3be2…` ×3), but exports of the same materialized content in different dirs differed by exactly 72 bytes confined to `icon.svg.import`, `.godot/uid_cache.bin`, and the compiled `main.scn` — while every path and size stayed identical (`census_equal=True`). So this row pins **census-level** facts; whole-file sha pins must also fix the project dir (determinism is scenario 03's row, flagged there rather than claimed here).

## Integration notes for the orchestrator
- Proposed CASES row (do not edit shared files from this seat):
  `("export_prod_s01", "export_prod_s01.gd", [], 0, "PASS export_prod_s01 magic=GDPC version=4 engine=4.7.2 flags=2 file_base=112 entries=14 bytes=4432 floor=4276 md5_ok=14/14 census_engine=14 census_equal=true")`
  The signature above is a stable prefix of the observed line. Appending `census_sha=074a8746…` pins the exact engine-internal hash naming and should be re-pinned after any Godot update.
- **Timeout budget:** `run_battery.py` grants 60s only to scripts whose name starts with `__godot_export`; all other scripts get **8s**. Measured wall for this fixture was 3.6–4.8s under load 25–33 (export child alone 2.0–2.5s). An 8s budget is too thin on this host — a one-line change to the export-class predicate (`script.startswith(("__godot_export", "export_prod"))`) or a 60s row-specific budget is recommended.
- **EDQUOT hazard:** if the host's `/tmp` user quota is exhausted, the export child fails and the row reports
  `ERROR: EXPORT_PROD_S01 ASSERTION FAILED: export child rc=1 … tail=… Failed to copy export template`. That is an environment failure, not a regression; it is greppable for triage.
- The fixture is self-contained: it materializes its own project (no dependence on `corpus/fixtures/project.godot` contents) and uses `OS.get_executable_path()` for children, so it always exports with the binary that runs it.

## Known limitations / unknowns
- Known accept: hash-region path rename (see ladder). Needs a load receipt (scenario 04) to close.
- `--main-pack` census child passes `--script res://_census.gd`; it does not load the main scene, so it would not catch a renamed main-scene target. Deliberate scope boundary.
- The templates path is resolved from `OS.get_data_dir()/godot/export_templates/<major.minor.patch.status>` with a fallback to `…/export_templates/…`; only the XDG layout was observed here.
- Not measured: encrypted PCKs (`encrypt_pck`/`encrypt_directory`), sparse bundles (`PACK_SPARSE_BUNDLE`), and pack format v2/v3 — flags=2/v4 only.
