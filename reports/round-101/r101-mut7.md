## 2. Row-level discrimination (trimmed-CASES battery copies)

Method (r94-critic recipe): copy `corpus/fixtures/` to `/tmp/r101-mut7/fix-<variant>/`,
AST-trim `CASES` to 6 rows (3 hard-required `save_process_*` + `r100b_seq_clean` +
`r100b_seq_noclean` + `r100_gui_cursor`), mutate the copy, run the **copy**:
`python3 /tmp/r101-mut7/fix-<variant>/run_battery.py --runs /tmp/r101-mut7/runs-<variant>`.
`cases_integrity` is False in every trimmed run by construction (other prefixes absent),
so only per-row verdicts and the r100 gate are read; the trimmed overall verdict is not
evidence of anything else.

| variant | mutation | rows | r100 gate / dead entries |
|---|---|---|---|
| base | none | 6/6 PASS | True / 0 |
| blankseq | `r100b_seq.gd` -> blank unit | seq clean **FAIL**, seq noclean **FAIL**; gui+save PASS | **False** / 2 (both seq allowlist entries now dead) |
| blankgui | `r100_gui.gd` -> blank unit | `r100_gui_cursor` **FAIL**; seq+save PASS | True / 0 |
| blankneg | `save_process.gd` -> blank unit | all 3 `save_process_*` **FAIL**; seq+gui PASS | True / 1 (`save_process_missing` entry dead) |
| deadentry | synthetic never-matching `expected_errors` entry added to `r100b_seq_clean` | 6/6 PASS | **False** / 1 |

Deadentry detail (verbatim from `verdicts.json`):
```
"dead_entry_count": 1,
"dead_entries": [{"case":"r100b_seq_clean","entry":"ERROR: synthetic never-matching r101-mut7 entry","shape":"exact"}],
"r100_expected_errors_all_matched": false
```
Measured row lines (blankseq):
```
PASS r100_gui_cursor: exit=0 signature='PASS r100_gui cursor c0=(0.0, 0.0) ...'
FAIL r100b_seq_clean: exit=0 signature='PASS r100_gui cursor c0=(30.0, 14.0) ...'
FAIL r100b_seq_noclean: exit=0 signature='PASS r100_gui hover h0=P ...'
```
Conclusions (observation):
- Row-level checks are **non-vacuous**: blanking a fixture fails exactly its rows, for
  positive (rc=0/signature) and negative (rc=2/ERROR) shapes alike.
- The r100 gate is **live**: a never-matching entry flips it while every row stays green.
- Bonus: a silently-dead fixture also makes its pinned allowlist entries dead
  (blankseq dead=2, blankneg dead=1), so the census reacts to fixture death in a second
  dimension.
- Caveat: a gate is live only for *declared* entries; if the r101 block declares none,
  `all()` over empty is vacuously true (the r95-critic §2.7 shape).

Infrastructure incident (observation; affects repeatability, not the row verdicts):
one `runs-blankseq/*/verdicts.json` was cut at exactly **49,152 bytes** and the battery
aborted with `OSError: [Errno 122] Disk quota exceeded` (`battery-blankseq.log`).
`/tmp` is `tmpfs … usrquota`; the user's tmp quota was exhausted mid-run. Row verdicts

## 3. Export "silent nothing" measurements (Godot 4.7.2.stable)

Projects: `/tmp/r101-mut7/exp3` (full `corpus/fixtures` tree), `exp4` (mutated preset),
`exp1` (project.godot only). Command shape:
`godot --headless --path <proj> --export-debug "Linux/X11" <proj>/out/fixture.x86_64`
(or `--export-pack`).

### 3.1 Templates inventory (C1 correction)
`~/.local/share/godot/export_templates/4.7.2.stable/` has **35 entries, including both
`linux_debug.x86_64` (73,703,800 B) and `linux_release.x86_64` (73,519,416 B)**, plus
android/ios/macos/web/windows. C1's "linux_release.x86_64 present" understates it;
`--export-debug` is satisfiable on this host.

### 3.2 Success shape — the executable is a raw template copy
`--export-debug` on exp3: rc=0; products `['fixture.pck', 'fixture.sh',
'fixture.x86_64']`; stdout carries `savepack | Storing File: res://…` and
`[ DONE ] savepack`.
- `fixture.x86_64` = 73,703,800 B, sha256 `1a291d3d15e4180b…` = **byte-identical to
  `linux_debug.x86_64`** (verified by `sha256sum` on the template).
- `fixture.pck` = 828,108 B, magic `GDPC`, sha256 `1c753027c9005c6f…` (game content).
⇒ "artifact exists and is nonempty" is not evidence of packaging: it passes on a raw
74 MB template copy. Export rows must pin magic + a PCK content census (or PCK bytes).

### 3.3 Determinism
Two consecutive exports: executable sha identical (`1a291d3d…`); PCK sha identical
(`1c753027…`). `--export-pack` produces PCK 828,108 B magic `GDPC` sha `1c753027…` —
byte-identical to the sidecar PCK of the executable export (same project state).
Zip target: rc=0, 817,745 B, magic `PK\x03\x04`, sha `45dbfcd8…`.

### 3.4 Templates missing — loud
Isolated `HOME` + `XDG_DATA_HOME` (empty dir), same command: **rc=1, artifact absent**.
stderr (exact):
```
ERROR: Cannot export project with preset "Linux/X11" due to configuration errors:
No export template found at the expected path:
/tmp/r101-mut7/emptyhome/.local/share/godot/export_templates/4.7.2.stable/linux_debug.x86_64
No export template found at the expected path:
/tmp/r101-mut7/emptyhome/.local/share/godot/export_templates/4.7.2.stable/linux_release.x86_64
ERROR: Project export for preset "Linux/X11" failed.
```
The two `No export template` lines do not themselves carry `ERROR:`; a row pinning an
`ERROR:`-prefixed substring must use the header/footer lines instead.

### 3.5 A failed export can leave a nonempty artifact
- Zero-resource project: rc=1, stderr `ERROR: Must select at least one file to export.`
  + `ERROR: Save PCK: Failed to export project files.` + `ERROR: Project export for
  preset "Linux/X11" failed.`; artifact exists, **73,703,800 B** (full template copy).
- Quota-interrupted template copy: rc=1, `ERROR: Prepare Template: Failed to copy export
  template.`; partial artifacts left at 64,143,360 / 46,747,648 / 46,661,632 B. df
  sampling during the repro never fell below 3,248,381,952 B free, but `/tmp` is
  `usrquota`-mounted and the battery itself hit Errno 122 ⇒ truncation is quota-induced
  (inference). The *left-behind partial file* on write failure is observed.
⇒ Rows must require rc=0 **and** artifact content evidence; presence alone can pass on a
failed export.

### 3.6 Filter mutation was inert (warning for the filter row)
`export_filter="customized"` + `include_filter="no_such_dir/*"` still packed every
resource: `--export-pack` rc=0, 828,108 B, magic `GDPC` — same size as the unmutated
export (sha differs; consistent with copied-tree cache state, inference). A "filter" row
whose mutation is only this config change would silently test nothing; it must show a
**census delta**.

### 4.3 Root cause probe: `OS.execute` multi-line capture comes back empty
`_engine_census` parses `OS.execute(OS.get_executable_path(), [...], out, true)`.
A minimal probe in the same project (`mut07_probe_os_execute.gd`) measures:
```
GD pass=0 rc=0 lines=1 census_lines=0      (×3 repeats, twice in separate processes)
SH  rc=0 lines=1 ["a"]                     (/bin/sh -c 'echo a; echo b; echo c')
GD_NOSTDERR rc=0 lines=1                   (read_stderr=false)
GD_VER rc=0 lines=1                        (single-line child is fine)
```
Executed with parent stdout redirected and under a pty (`script -qec`): identical.
⇒ On this host/version the `output` array receives **only the child's first line**;
the rest is dropped (in one early run, the tail raced to the parent's stdout instead).
Exact engine-internal cause: **unknown** (not chased). Consequence: the fixture's
engine-census child runs fine but the fixture cannot see its evidence, so R7c fails —
the class in its most deceptive form would otherwise be "child rc=0 + autoload seen ⇒
count 0 accepted". Here the fixture refuses, but the row is red as landed.

All landed export fixtures (shared `export_prod.gd` + s01–s11) call `OS.execute`
(1–3 calls each: `export_prod.gd` 1, s01 3, s02 1, s03 2, s04 3, s05 2, s06 1,
s07 2, s08 3, s09 2, s10 2, s11 2) ⇒ any of them that parses multi-line child
output is exposed under the battery's pipe-captured launch. Suggested fix for the
owner (not applied — not my file): have the child write its census to a file under
`--work` and read the file, or emit one single line.
