## 2. Ground truth — measured Godot 4.7.2 filter semantics

Engine (`--main-pack`, DirAccess `res://`) census, byte-identical to the PCK directory parse and
to the exporter's `Storing File:` log on all five arms (counts 9/8/7/8/8; 40/40 entries
`bounds_ok=true`, i.e. `data_offset + size <= file_size`):

```
A0_inc_all   (9): .godot/exported/…-main.scn, .godot/global_script_class_cache.cfg,
                  .godot/uid_cache.bin, data/keep.txt, data/skip.txt, main.gd.remap,
                  main.gdc, main.tscn.remap, project.binary
A1_inc_exc   (8): same minus data/skip.txt
A2_conflict  (7): same as A1 minus data/keep.txt
A3_names     (8): same as A1                (include keep.txt, exclude skip.txt)
A4_names_inv (8): same as A1 with data/skip.txt in place of data/keep.txt
```

Measured rules:
- `include_filter` packs matching **non-resource** files (A0 packs both `.txt`; `notes.md` is
  never packed — it matches neither include nor exclude).
- `exclude_filter` removes a file that also matched `include_filter` → **exclude wins on
  match** (A1: `skip.txt` matches `*.txt` and is excluded; keep.txt stays).
- The same file listed on both sides (A2) is **absent** → exclude wins on conflict.
- Swapping the two values (A3→A4) flips which `.txt` is packed: `keep.txt` ↔ `skip.txt`.

All five arms also contain exporter-generated entries `.godot/exported/…-main.scn`,
`.godot/global_script_class_cache.cfg`, `.godot/uid_cache.bin`, `main.gd.remap`, `main.gdc`,
`main.tscn.remap`, `project.binary` — any s06 census must either include or explicitly filter
these with a stated rule.

## 3. MUT-9 mutant + discrimination matrix (observed)

Mutant = A4: take A3's two filter values and swap them (`include="data/skip.txt"`,
`exclude="data/keep.txt"`). Both arms were exported for real and censused; results:

| pin shape | true A3 | mutant A4 | verdict |
|---|---|---|---|
| magic `GDPC` + exit 0 | pass | pass | **blind** |
| `count=8` | pass | pass | **blind** |
| pack size `2576` | pass | pass | **blind** |
| `entry: res://data/keep.txt` present | hit | miss | rejects mutant |
| full `CENSUS_BEGIN…CENSUS_END` block equal | hit | miss | rejects mutant |
| pack sha256 `e41c521b…` vs `b8909db1…` | — | — | rejects mutant |

F2-style forgery (single forged line injected **inside** the true census block, before
`CENSUS_END`): `forged_inside_block_passes_single_line_pin = true`,
`forged_inside_block_passes_full_block_pin = false`. I.e. a single-line evidence pin admits an
injected extra entry line; a whole-block pin rejects it (the r100-critic F2 lesson in this
scenario).

**Recommendation for s06 (`export_prod_s06.gd`, E6's file — this seat did not touch it):** the
row's pins/evidence must be the full sorted census block (exact `count=` line + one `entry:`
line per packed path), and the absent side must be checked as a set difference (`data/skip.txt`,
`data/notes.md` ∉ census), not asserted in prose. Do not use magic/count/size as the only
discrimination — each is measurably blind to the inversion.

## 4. PCK format-4 note (verified on 4.7.2 bytes; relevant to E2/E6/E9 parsers)

```
header:  u32 magic 0x43504447 "GDPC"; u32 fmt=4; u32 ver 4/7/2; u32 flags=2
         (PACK_REL_FILEBASE); u64 file_base=0x70; u64 dir_offset (e.g. 0x810);
         72 reserved bytes; file data starts at file_base; directory at dir_offset
dir:     u32 count; per entry: u32 path_len (utf8+NUL padded to a multiple of 4),
         path bytes WITHOUT the "res://" prefix, u64 offset (relative to file_base
         when flags&2), u64 size, 16-byte md5, u32 flags
```
My first parser (count read inline after the reserved block, `res://`-prefixed paths) read
`count=0`; the corrected parser agrees with the engine census and the `Storing File:` log on
all five arms.

## 5. Determinism caveat for sha256 pins (measured)

```
$ godot --headless --path /tmp/r101-mut9-det/proj --import
$ godot --headless --path /tmp/r101-mut9-det/proj --export-pack A3_names …/run_a.pck
$ godot --headless --path /tmp/r101-mut9-det/proj --export-pack A3_names …/run_b.pck
$ sha256sum …/run_a.pck …/run_b.pck
e41c521b6db2ce40652e90fe03795f497831665dfe00efeaa8fb7b8d916b598c  run_a.pck
e41c521b6db2ce40652e90fe03795f497831665dfe00efeaa8fb7b8d916b598c  run_b.pck
$ rm -rf /tmp/r101-mut9-det/proj/.godot && godot --headless --path … --import
$ godot --headless --path … --export-pack A3_names …/run_c.pck
ea08b1e37d5114933934c8a3f126d9c5dc8536f9c9eac3a5947c1956481e1385  run_c.pck
```

- Same import state → two exports **byte-identical** (and equal to the probe's A3/A1 sha).
- Fresh import → sha changes; total size unchanged (2576); entry-md5 diff shows **only**
  `res://.godot/exported/…-main.scn` changed (all other entry md5s identical, including
  `.godot/uid_cache.bin`; 20 differing bytes total: 4 inside the `.scn`, 16 in its directory
  md5 field).
- The 4 differing scene bytes (rel 0x1ed–0x1f0 of the 669-byte `.scn`) sit inside an 8-byte
  value that follows the ASCII property name `node_ids` + u32 `0x20` (PackedInt64Array) +
  count `1`: run_a `8a a8 eb 73 05 00 00 00` vs run_c `46 e8 16 30 05 00 00 00`.
  Observation: those exact bytes flip. Inference (from the property name; not proven
  further): a generated scene node ID stored in the import cache.
- Note: `main.gd.uid` (`uid://cvdwmramswo62`) was byte-identical in both states, so this flip
  is **not** a script-UID change.
- Implication: a row may pin per-entry sha256 / pack sha256 only within one import state
  (e.g. export twice in the same scratch, as E6's `r101-E6-filter_probe.sh` does by copying a
  materialized base); otherwise pin the census names+sizes, which stayed identical across this
  re-import. A fixture that rebuilds its project from source text and imports fresh each
  battery run must not pin the sha of the `.godot/exported/*.scn` entry.
