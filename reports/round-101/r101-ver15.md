# r101-VER-15 — `--main-pack` launch probes: exit-code/stdout pins + load qualification

Seat `VER-15` (g2d lane r101) | host loadavg **28–57** all session (foreign heavy 3D-lane round
running, as briefed; never idle) | Godot `4.7.2.stable.arch_linux.ed1daf0bf` (`/usr/bin/godot`),
export templates `~/.local/share/godot/export_templates/4.7.2.stable/` (linux_release.x86_64
present) | scratch **`/var/tmp/r101-ver15/`** — see §1 caveat | driver:
`reports/round-101/mutations/ver15_launch_probe.sh`, preflight:
`reports/round-101/mutations/ver15_pack_preflight.py`.

Plan executed: build production-shaped scratch project → export PCK variants → launch-probe
matrix over mailformed/ok/quit/flag/content classes → load qualification → land pins.

**Headline:** for `--main-pack`, **rc=0 is fail-open in at least four distinct ways** (missing
pack, bad magic, zero-length pack, settings-less pack, even a runtime script error) — the only
reliable success evidence is a whole-line boot receipt from the pack's own scene, backed by a
`project.binary` preflight of the PCK itself. Additionally, `--export-pack` on this host
intermittently emits a pack whose `project.binary` entry is present but **data_size=0**; such a
pack boots an empty engine, prints the banner, and exits **rc=0** under `--quit-after N`.

## 3. Findings

### F1 (HIGH) — a malformed pack exits rc=0; six distinct error classes share one output

| probe | rc | stdout | stderr |
|---|---|---|---|
| missing file `NOPE.pck` | **0** | banner only (101 B) | `ERROR: Cannot open resource pack '<abs>'.` + `   at: _setup (core/config/project_settings.cpp:691)` |
| zero-byte file | **0** | same 101 B | same `Cannot open resource pack` |
| random bytes (bad magic) | **0** | same 101 B | same |
| directory as `--main-pack` | **0** | same 101 B | same |
| truncated body (5036→4000, data region) | **0** | same 101 B | **empty** — completely silent |
| truncated inside dir region (→5000) | **0** | same 101 B | `ERROR: Corrupted header in binary project.binary (not ECFG).` + `Couldn't load file 'res://project.binary', error code 16.` |
| trailing 4 bytes cut (→5032) | 0 | **boots**: banner + 4 receipt lines, 208 B | empty |

All six failures produced the *byte-identical* banner-only stdout (sha256[:12] `1fb0f12cefe4`).
A pin that asserts `rc==0` and any stdout substring that is not a scene receipt accepts every
one of them. Conversely `--main-pack` **without an argument** is the only malformed-input case
with a non-zero code: rc=1, stdout `Missing path to main pack file, aborting.`, stderr empty.

### F2 (HIGH, cross-seat) — `--export-pack` intermittently emits a settings-less pack (rc=0, log lies)

Broken pack facts (measured on `out_ok.pck`, `imp1.pck`, `cw_okcopy_1.pck`):
`project.binary` entry present, `data_size=0`, no `ECFG` bytes anywhere in the file;
pack 240 B smaller than its good sibling; launch prints banner only, **rc=0**, and (only) the
2-line `Corrupted header … (not ECFG)` stderr block. Good pack: `data_size=239/247`, `ECFG`
at 3776, launch prints receipt. Correlation census over 28 packs built this session: **ECFG
present ⇔ a scene receipt appears** (7/7 settings-less packs → 0 receipt lines, rc=0; 21/21
ECFG packs → receipt, rc=0 or the intended rc=1 for the two content-error packs).
**The export stdout always logs `Storing File: res://project.binary` — including every broken
pack (20/20)**; the log is not a validity check.

Rate: of the first 20 export invocations (1-min load window 37→57), **6 packs were verified
settings-less by byte inspection** (batch2 `ok/err/missing/noscene`, `cw_okcopy_1`, `imp1` —
the last even after a successful `--import`); the five first-batch packs (4796 B, same size
class, overwritten before byte inspection) are counted only as inference. Of the next 30
invocations at load 28–33 — including 6 deliberately cold projects and 8 exports under 8/16
local `yes` hogs — **0/30 were settings-less** (every one ECFG-verified). So the
flake is intermittent, load-window-correlated, and not reproducible on demand; it must be
*enveloped*, never assumed away. The preflight+retry recipe (below) converged on every required
pack (5 canonical variants + 2 self-quit packs on try 1 in their phase).

### F3 (MEDIUM) — exit-code taxonomy for `--main-pack`

* **rc=0** — normal exit; `--quit-after N` expiry; *and* every malformed/settings-less pack (F1/F2);
  also a runtime **SCRIPT ERROR** inside the pack (below).
* **rc=1** — `--main-pack` with no argument; pack whose settings name a main scene that is absent
  from the pack (stderr: `Cannot open file 'res://missing.tscn'.` + `Failed loading resource:` +
  `Failed loading scene: res://missing.tscn.` @ `main/main.cpp:4767`); pack with **no** main scene
  defined (rc=1, message on **stdout**: `Error: Can't run project: no main scene defined in the
  project.`, stderr empty); export failures (`Project export for preset "Linux/X11" failed.`).
* **rc=7 / rc=0 chosen by the pack**: a scene calling `get_tree().quit(7)` makes the process exit
  **rc=7** (3/3 runs; `quit(0)` → 0, 3/3). This is the fail-closed receipt lever: the pack can
  carry its own expected exit code.
* **rc=137** — `timeout -s KILL` kill: `--quit-after 0` and `--quit-after abc` (parsed as
  “disable”, no error message) never quit; killed at the 25 s bound after ~3.5k receipt lines.
* Not observed: any other code (12 launch classes × reps).

Runtime errors inside the pack do **not** change rc: `err.gd`'s null `queue_free()` prints the
3-line `SCRIPT ERROR … GDScript backtrace` block on stderr, aborts the rest of `_ready()`
(`ERR_AFTER_CRASH` never prints), the node still `_process`es, and the run exits rc=0 with its
receipt — so a “script-error class” pin must be stderr-signature-based.

### F4 (MEDIUM) — receipt hygiene / CLI semantics (all measured)

* `--quit-after N` ⇒ exactly `N` `TICK` lines plus 1 `BOOT` line (N=1→2 lines, N=3→4, N=10→11;
  20 runs identical modulo pid, including `--fixed-fps 1` and `--fixed-fps 30`, relative pack
  path from another cwd, and an **unknown flag** `--ver15-nonsense` which is silently ignored).
* The `BOOT` line contains `OS.get_process_id()` → the pinned signature must normalize
  `pid=<N>` (raw stdout diffs every run; normalized sha256[:12] `781c078b7ed5` for the N=3
  receipt across 20 runs).
* The banner line `Godot Engine v4.7.2…` is version-coupled; pin receipts, not the banner.
* `--path <otherproj> --main-pack <pack>`: **the pack's settings win** (`BOOT … name=ver15-prod-ok`
  printed, not the `--path` project's scene) — precedence differs from the settings-less case.
* `--scene res://hang.tscn` resolves **inside the pack** (HANG_BOOT receipt, rc=0).
* A scene's self-quit loses to `--quit-after` when both are present (`self7` + `--quit-after 1`
  → rc=0, 2 lines): do not add `--quit-after` when pinning the pack-controlled rc.

## 4. Fail-closed launch guard (the deliverable recipe, r88 BLOCKER precedent applied)

r88 landed pid-derived ports + `rc_s`/`rc_c` guards because a hardcoded port could silently
cross-connect. The `--main-pack` analogues, measured here:

1. **PID-derived artifacts, not fixed paths** — this seat ran 10 concurrent launches + 8-way
   concurrency blocks with per-run logs; a probe that hardcodes one pack path or one output log
   (the “hardcoded port” of this surface) races parallel seats/battery runs. Every run gets its
   own dir (`$TMPDIR/<seat>-$$/…`, or the fixture's own process-unique path).
2. **Timeout is part of the guard** — every launch bounded (`timeout -s KILL 25` here); rc=137
   is FAIL for a pin that expects a receipt (never-quit packs are the normal failure shape,
   not an error).
3. **Check rc BEFORE reading output, and never accept rc=0 alone** — guard order:
   (a) rc != 137, (b) rc == expected (compressors: 0 normal; 1 = CLI/content error; pack-chosen
   e.g. 7), (c) settings preflight of the PCK (below), (d) **whole-line boot receipt** present,
   (e) forbidden-stderr census (`Corrupted header in binary project.binary`, `SCRIPT ERROR`
   when not expected).
4. **PCK preflight before trusting any launch receipt** — parse dir entry `project.binary`,
   require `data_size>0` and `file_base+file_offset` bytes start with `ECFG`; on failure
   re-export (retry converged 1–4×; every required pack succeeded) or FAIL the row. Landed as
   `mutations/ver15_pack_preflight.py`; validated **13/13** on the pack zoo: PASS for
   `v15_ok/v15_missing/v15_self0/trunc_5032` (the boots), FAIL for `out_ok/imp1/cw_okcopy_1`
   (`data_size=0`), `zero/badmagic` (magic), `trunc_4000` (dir beyond EOF).

## 5. Load qualification (observation, at load 28–57 on 32 cores)

* Launch wall times stayed tight under all phases: N=1/3/10 receipts 663–1074 ms,
  `--fixed-fps 1` and `30` the same, 8-way concurrency max 1.1 s. A 25 s bound leaves >20×
  headroom at load ~57.
* Frame receipts are load-stable: **N=3 → 4 lines in 20/20 runs** (quiet, matrix, concurrency,
  8/16-hog phases); N=10 → 11 lines ×2; N=1 → 2 lines. No envelope was needed for the *count*.
* 16 hogs + load ~29: all four export+launch probes exact, incl. rc=7 propagation.
* The only load-sensitive surface observed is the **export** flake (F2) — it hit the earlier
  high-load window (1-min 37→57) and never reproduced at 28–33 or under added hogs. Pins must
  therefore eliminate it structurally (preflight/retry) rather than “tolerate” it with retries
  at launch time (retrying a launch cannot fix a settings-less pack: it will never boot).

## 6. What this means for the export_prod lattice rows (for E4/E11/E0 integration)

* The `--main-pack … --quit-after N` receipt row must pin: rc == 0 **and** the pack's own
  `BOOT`/frame receipt lines **and** absence of the `Corrupted header` stderr block; add the
  preflight to the export step of the fixture (a settings-less export must FAIL the row, not
  silently pass through rc=0).
* Prefer a self-quitting scene (`get_tree().quit(<code>)`) for the run receipt: it gives a
  pack-controlled non-zero-capable exit code and removes dependence on `--quit-after` parsing;
  the measured semantics of both modes are pinned in §3/§4.
* Normalize or omit `pid=` in any pinned receipt line.

## 7. Observation vs inference vs unknown

* **Observation**: every rc/stdout/stderr string above; counts (20 identical receipts, 6
  byte-verified settings-less exports in the early window [+5 inferred], 0/30 later, 10/10
  concurrent, 3/3 rc=7, 13/13 preflight zoo, 28-pack ECFG⇔receipt correlation).
* **Inference**: the settings-less pack is a zero-length `project.binary` write race in the
  exporter (entry present, size 0, log claims stored); correlation with the load window is
  suggestive, not a controlled cause (hogs did not reproduce it).
* **Unknown**: the exact trigger of F2; whether a non-headless launch changes any of the above
  (out of scope by the round's headless-only rule); Windows/macOS pack semantics (linux only).
