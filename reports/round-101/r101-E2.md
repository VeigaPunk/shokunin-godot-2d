## 3. Integrity method (independent of the engine's own checks)

`PackedByteArray.decompress(…, COMPRESSION_DEFLATE)` **cannot** inflate Godot's own zip
payloads on this build:
```
ERROR: Condition "err != 1" is true. Returning: -1
try_a=0        # payload.decompress(usize, FileAccess.COMPRESSION_DEFLATE)
```
`ZIPReader` (`open`/`get_files`/`read_file`) does inflate them, and I use it only as the
inflater. The integrity check itself is a CRC32 (poly `0xEDB88320`) implemented in GDScript
and recomputed over the inflated payload of every entry against the stored CRC:
`crc_mismatches=0` on all 9 entries in every run. On a forged CD CRC, `ZIPReader` reported
`ERROR: Could not open file within zip archive` and returned an empty payload, which is why
that forgery surfaces as both `inflated_size@8 0!=243` and `crc32@8` [inference: the reader
validates the stored CRC before returning data — I did not read its source].

## 4. Observed non-determinism (handoff: this bounds any sha256-equality claim)

The zip is **not** byte-deterministic. Five exports of byte-identical inputs:
`2447/2448/2448/2449/2450` bytes with sha256 `470f31cb…`, `ff49da65…`, `cc800772…`,
`6cf8ce2a…`, `9b58faf2…`. All variance is inside entry 3, the converted binary scene:

* `us` is always 842; `cs` observed 397, 398, 399, 400; stored CRC differs every run.
* Diffing inflated payloads across four runs: **exactly bytes [662, 670) differ** (a
  random-looking per-run 64-bit value), all other 834 bytes identical, and
  `sha256(payload[0:662])` / `sha256(payload[670:842])` are equal in all four runs.
  Observed varying windows: `70a8c86bfbf8915b`, `2a3d1374049cdf38`, `059c955a81ecc175`,
  `7b01e24b05151332`, `280a07433b9fba66`.
* Consequently entry 3 is **mask-pinned** (prefix ≥ 662 and suffix from 670), not
  whole-file pinned. The other 8 entries are bit-stable across every run observed.

This is the concrete mechanism behind any "export determinism" claim: for this project the
only unstable bytes are that 8-byte field, and the archive's byte length is not stable.

**Residual gap (stated, not hidden).** A same-length content edit confined to bytes
[662, 670) of entry 3 is accepted. That window is the one field the engine itself fills
with a different value on every run, so no content pin can distinguish a forgery there from
legitimate variance. Every other byte of the archive is pinned or structurally verified:
834/842 bytes of entry 3, plus all 8 remaining entries whole, plus names, order, count,
sizes, header fields, EOCD contiguity and per-entry CRC self-consistency.
