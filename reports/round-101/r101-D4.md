## 3. Divergence-pin field definition (the requested spec)

**Field-id grammar**

```
<cell>.<key>[#<occurrence>]
  key        literal `key=` token in that cell's PASS line
  occurrence 1-based index of that key among the line's top-level tokens
             (omitted iff the key occurs once)
```

**Record**

```
DIVFIELD row=<CASES row> cell=<cell> field=<field-id>
         fresh=<exact bytes in the fresh single-cell CASES pin>
         replay=<exact bytes in the frozen replay transcript>
         delta=<pos(+dx,+dy) | entry-absent(<exact entry>) | literal(a->b)>
         cause=<cell whose Input.parse_input_event wrote the leaked state>
```

Byte strings are the **value only**, i.e. everything after `key=` up to the
next top-level space. They are exact substrings of the pinned lines, so a row
that pins the whole line necessarily contains every declared field value.

**Why review-side, not a CASES row.** The row signature is one literal
substring of merged stdout+stderr. `replay != fresh because <cause>` is not an

are the frozen probe copy, sha256 above). So the certificate is executable by
the checker below at review time; the *battery* keeps its byte pins (D2/D3
own the full-transcript pin). The field set is what makes those pins
*meaning-bearing*: it fails when the divergence moves, disappears, or when the
declared cause stops deriving the observed value.

## 4. Derivation of each divergence (cause + evidence)

The only writer of the viewport cursor is the **parse/flush** path. `push_input`
never moves it — the fresh `cursor` pin itself proves this: `c1_push_mm` stays
`(0.0, 0.0)` after `root.push_input(_mm(Vector2(20,20), …))` while
`c3_parse_mb` jumps to `(24.0, 24.0)`. Therefore the replay's cell N sees the
cursor left by the last `Input.parse_input_event` of cells 1…N−1.

* **cursor cell (`c0/c1/c2`) — cause `localpos`, source `r100b_seq.gd:412`**
  `_cell_localpos()` ends with `Input.parse_input_event(_mb(Vector2(30, 14), true))`.
  Derived leak `(30.0, 14.0)`. **Confirmed by prefix runs** (scratch copy with
  a `--seq=` selector):
  `--seq=cursor,touch` → `c0=(0.0, 0.0)`; `--seq=localpos,cursor,touch` →
  `c0=(30.0, 14.0)`. `warp`'s own `push_input`/`warp_mouse` calls do not write
  it.
* **touch cell `t3_emul_touch.a` — cause `cursor`, source `r100b_seq.gd:445-449`**
  `_cell_cursor()` parses `InputEventScreenTouch(index=0, pressed=true)` at
  `(44,44)` (line 449) and **never releases that index**; the clean-mode
  `_cleanup()` frees nodes but does not touch input state. The `touch` cell's
  `t3` then parses another index-0 press at `(8,8)`. Mechanism probe
  (`/var/tmp/r101-D4/probe/emulstate2.gd`, observation):
  `C1 first_st0_press held=1 cursor=(44.0, 44.0) log=["A:mb(b=1,p=1,bm=1,pos=44.0,44.0)", "A:st(i=0,p=1,pos=44.0,44.0)"]`
  then
  `C2 second_st0_press_while_held held=1 cursor=(44.0, 44.0) log=["A:st(i=0,p=1,pos=8.0,8.0)"]`
  — i.e. once a parsed touch press is outstanding, a further parsed touch
  press delivers only the raw `st`: no emulated `mb` and no cursor motion.
  Prefix bisection confirms the causal cell: `--seq=touch` keeps the `mb`
  prefix; `--seq=cursor,touch` drops it; `--seq=localpos,touch` keeps it
  (so `localpos`'s parsed mouse press is *not* the suppressor — probe arm
  `ARM_B` shows a real mouse press first still yields `mb` on the touch press).
  **Inference (labelled):** the suppression is keyed on the emulation path's
  outstanding touch-press state, not on `is_mouse_button_pressed(LEFT)`; the
  probe distinguishes those two only by counter-example, not by reading engine
  source.
* **subvp `cursor_root` / `root`, warp `w0..w3.cursor` — cause `touch`, source
  `r100b_seq.gd:636`** (with `:640` re-parsing the same position)
  `t4_emul_mouse` parses `_mb(Vector2(20, 4), true)`, setting the viewport
  cursor; `subvp` and `warp` themselves only use `push_input`/`*_warp_mouse`,
  neither of which writes the headless cursor. Derived leak `(20.0, 4.0)`.
  **Confirmed by discriminating prefix runs:**
  `--seq=subvp` → `cursor_root=(0.0, 0.0)`;
  `--seq=touch,subvp` → `(20.0, 4.0)`;
  `--seq=cursor,subvp` → `(44.0, 44.0)` (a *different* cause cell produces a
  different value, so the attribution is falsifiable, not decorative);
  `--seq=touch,warp` → all four `warp.cursor` fields `(20.0, 4.0)`.

The checker re-derives these positions **statically** from the fixture source
(`Input.parse_input_event(...)` positions in the cell prefix) and fails if the
declared cause is not the cell that supplies that position — so a fixture edit
that removes the leak fails closed instead of silently passing.

Readings:

* **M0 exposes a defect in the critic's proposed fix.** `r100-critic` §F2's
  "smallest safe correction — `"\n".join` of the replay's 14 lines" is
  **unsatisfiable as written**: the 6-line ERROR block sits between `focus`
  and `render`, so the 14 cell lines are not contiguous and the joined string is
  never a substring of the honest transcript (control REJECT). The workable
  forms are the whole-23-line join, or two segment joins with the ERROR block
  included. M6 also shows cells-only becomes satisfiable only by *forging* an
  appended contiguous block — an unsound direction.
* **Today's rows** (clean pins `cursor` only; noclean pins `hover` only) accept
  all seven forgeries — this reproduces F2 and extends it: even divergence
  erasure in unpinned cells is invisible.
* **Joined 23-line** catches everything inserted/mutated in place, but not
  append-position forgeries (M6, M7) — substring pins have no end anchor.
* **Certificate** is the only shape that catches M6/M7, and it accepts the
  honest transcript (M0) — no false positive. It also rejects M2 (a forged
  clean-mimicking cell line) and every divergence erasure/relocation.

## 7. Findings for integration

1. **F2 closed with a caveat:** land D2/D3's full-transcript pins as the
   **whole 23-line join**, not the 14-cell join (unsatisfiable, M0). The pins
   are row signatures; each row's allowlist stays `ERROR: Parameter "t" is null.`
   (the ERROR block is otherwise unclassified).
2. **The 4 divergences are clean-variant only.** The noclean row must declare
   **9** divergent cells; asserting "4" against `--clean=0` is false (measured).
   The certificate's declared sets are per-variant and fail on drift.
3. **Exact field set to cite in review:** the 10 records in §3. Any future
   re-derivation must reproduce the same `(field-id, fresh, replay, cause)`
   tuples, and `--check` must print `23/23 lines rebuilt` for the clean capture.
4. **Two extra measured facts** that belong in D2/D3's pins if they want
   completeness: (a) the ERROR block's frame `[2]` differs by variant
   (`_cleanup:135` vs `_cell_focus:750`); (b) `SEQ_DONE clean=<0|1>` is the last
   line and is the only end anchor the certificate can use.
5. **Operational:** the replay takes 1.5 s under loadavg 40; no retry storm
   needed. `/tmp` EDQUOT is real on this host — use `/var/tmp` for scratch.
6. **Cross-check against E12's `r101_seqfull.gd` receipt (independent receipt,
   measured 2026-10-18):** running that fixture from my scratch copy,
   `--clean=1` prints `SEQ_CENSUS identical=10 divergent_n=4
   divergent=[cursor|touch|subvp|warp]` and `SEQ_END digest=5be029c7d129bf6d
   9289a3b484efac34c73e2eae8fd34e47f8cdf4f88293718c`; `--clean=0` prints
   `identical=5 divergent_n=9 divergent=[hover|motion|localpos|cursor|clip|
   drag|touch|subvp|warp]` and `digest=da5cd7d7…856a`; both repeat byte-identically
   on a second run. Hashing my own captured cell lines
   (`sha256("\n".join(14 cell lines))`) gives exactly those two digests, so the
   new receipt and the frozen replay emit byte-identical cell lines, and its
   divergent-cell list equals my §2 census. The receipt carries cell *names*;
   the §3 field table is the per-field delta + cause granularity it does not
   carry — cite them together.
