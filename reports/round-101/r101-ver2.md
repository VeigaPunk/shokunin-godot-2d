## C1 — `export_prod` lattice: measured ground truth for s04/s05/s06

### F0 (BLOCKER, environment) — `/tmp` is quota-limited and silently fails exports with `EDQUOT`

The round brief told every export seat to stage under `/tmp/r101-<key>/`. On this host that path is a
16 GB tmpfs at 80–100 % with a per-user quota that is already exhausted:

```
$ mkdir -p .godot/exported/test && echo test > .godot/exported/test/x
/bin/bash: line 1: echo: write error: Disk quota exceeded
$ df -h /tmp
tmpfs            16G   13G  3.1G  80% /tmp
$ df -h /var/tmp /home
/dev/mapper/root  930G  143G  772G  16% /
```
A real export against `/tmp` fails **after** the pack is opened, with a misleading engine error:
```
ERROR: Unable to save export scene file to: res://.godot/exported/133200997/export-<md5>-main.scn
   at: _export_customize (editor/export/editor_export_platform.cpp:1096)
```
and leaves a **0-byte** `.pck` behind (`base.pck`, `packonly.pck`, both 0 B). This is exactly the failure
r100-critic hit (`shutil.copytree` → `Disk quota exceeded`). **Recommendation for integration:** any
`export_prod` fixture must stage under `/var/tmp` (or check free space and fail closed with a named

### s04 — main-scene semantics

Three mechanisms tested on `/var/tmp/r101-VER2/p04` and `/var/tmp/r101-VER2/p04b` (project with
`main.tscn` printing `SCENE=main`, `alt_main.tscn` printing `SCENE=alt_main`).
| mechanism | command | observed |
|---|---|---|
| preset option `application/run/main_scene="res://alt_main.tscn"` in `[preset.0.options]` | `godot --headless --path p04 --export-release "Linux/X11" out/s04.x86_64` then `godot --headless --main-pack out/s04.pck --quit-after 60` | **silently ignored.** `SCENE=main`. `project.binary` (235→231 B) still contains `main.tscn`, does **not** contain `alt_main.tscn`. The key is **retained verbatim** in `export_presets.cfg` after export (line 21) — the engine does not warn, does not drop it, does not honour it. |
| edit `project.godot` `application/run/main_scene` | same two commands on `p04b` | **works.** `SCENE=alt_main`; `project.binary` size 235, contains `alt_main.tscn`. |
| positional scene arg | `godot --headless --main-pack out/s04.pck res://alt_main.tscn --quit-after 60` | **works.** `SCENE=alt_main`. Control `res://main.tscn` → `SCENE=main`; no arg → `SCENE=main`. |

**Consequence for the lattice.** An s04 row that asserts "the preset override swaps the main scene"
would be **vacuous** — it cannot fail. The honest row set is (a) project-setting swap, (b) positional
scene arg, (c) a negative control pinning that the *preset* key produces the *project* default.

### s05 — PCK container, `.remap` and UID file formats (all decoded from measured bytes)

The 4.7.2 PCK header is **112 bytes**, not the 164 B of older 4.x layouts:

```
0   char[4]  "GDPC"
4   u32      pack_format_version = 4
8   u32      ver_major = 4
12  u32      ver_minor = 7
16  u32      ver_patch = 2
20  u32      pack_flags = 2
24  u64      file_base = 112        # absolute offset of the data region
32  u64      dir_offset             # absolute offset of the directory
40..111      reserved (zeros)
data region: stored files, each padded to a 16-byte boundary, offsets relative to file_base
directory @ dir_offset: u32 file_count, then per entry
    u32 path_len; u8 path[path_len]; u64 offset(rel); u64 size; u8 md5[16]; u32 flags
```
Decoded with `tools/pckls.py` (mine, in scratch — not landed); every offset verified by dumping the
leading bytes at `file_base + offset` and matching the expected magic.

`.remap` is a plain `ConfigFile`-shaped text file, **not** a binary map. Verbatim bytes:

```
alt.gd.remap        (30 B)  [remap]\n\npath="res://alt.gdc"\n
main.gd.remap       (31 B)  [remap]\n\npath="res://main.gdc"\n
alt_main.tscn.remap (101 B) [remap]\n\npath="res://.godot/exported/133200997/export-092f594f9048208b67ba7297a4994b24-alt_main.scn"\n
main.tscn.remap     (97 B)  [remap]\n\npath="res://.godot/exported/133200997/export-3070c538c03ee49b7677ff960a3f5195-main.scn"\n
```
So a remap target is `res://.godot/exported/<u32>/export-<md5-of-source-path>-<basename>.scn`, and each
bytecode file is stored **twice** in the census: `main.gd.remap` + `main.gdc` (no remap→`.gdc` rewrite
of the path; the `.gdc` sits at its own path).

**`<u32>` is not a constant.** It was `133200997` for `export_filter="all_resources"` and
`2333676692` for `export_filter="customized"` **on the same project with the same files**. It did
**not** move when the project path changed (`/var/tmp/r101-VER2-b/pathb` → `133200997`) and did **not**
move when the preset was renamed to `PROBE` (`133200997`). So it is a deterministic function of preset
filter configuration, and any pin on `.remap` content must be scoped to one preset configuration.
Neither value matches `djb2` of the preset name, project name, export_filter string or preset index —
the derivation is **unknown** (labelled inference: filter-config-derived, not path-derived).

`.uid` sidecars are 20 B each on disk. `.godot/uid_cache.bin` in the pack is 53 B = 4 + (8+4+12) + (8+4+13):
`u32 count=2`, then per entry `u64 uid`, `u32 path_len`, path —
`02 00 00 00 │ 75 d0 72 bf b8 2b 22 7b │ 0c 00 00 00 "res://alt.gd" │ 51 72 88 51 39 0c 0a 23 │ 0d 00 00 00 "res://main.gd"`.
`global_script_class_cache.cfg` in the pack is `list=[]\n` (8 B).

**`uid` sidecars change the exported `.scn`, but they are not the whole story** (see F6 below):
removing `main.gd.uid` / `alt.gd.uid` moves the `.scn` md5 pair from `c66f8147…/c3ce89f6…` to
`ba04c7b0…/e09ee761…`, while `.godot/uid_cache.bin` inside **both** packs stays md5 `e7f30434…`
(53 B, identical).

### s06 — export-filter glob semantics

Matrix over `/var/tmp/r101-VER2/p06-*`, each a fresh copy, `--export-pack` to a distinct path.
Files under test: `sub/keep.txt`, `sub/deep/note.txt`; baseline pack contains neither.

| `export_filter` | `include_filter` | `exclude_filter` | rc | `.txt` files in pack |
|---|---|---|---|---|
| `all_resources` | `""` | `""` | 0 | none |
| `all_resources` | `*.txt` | `""` | 0 | **`sub/keep.txt`, `sub/deep/note.txt`** |
| `all_resources` | `sub/*` | `""` | 0 | both |
| `all_resources` | `**/*.txt` | `""` | 0 | both |
| `all_resources` | `*.txt` | `sub/deep/*` | 0 | `sub/keep.txt` only |
| `resources` | `""` | `""` | **1** | — (export failed) |
| `customized` | `*.txt` | `""` | 0 | both |
| `exclude` | `""` | `""` | 0 | none |
| `totally_bogus` (spoof) | `""` | `""` | **0** | none |

Hard facts:
1. **`*.txt` matches across `/`.** It pulled `sub/deep/note.txt`. Glob `*` is not path-segment-limited,
   so a row "include `*.txt`" is not a shallow-match row.
2. **`**/*.txt` is not stronger than `*.txt`** — identical census. A row distinguishing the two is vacuous.
3. `exclude_filter` is applied **after** include and is path-prefix glob (`sub/deep/*` removed only the
   deep file, kept `sub/keep.txt`).
4. **`export_filter="resources"` hard-fails rc=1** with
   `ERROR: Must select at least one file to export.` +
   `ERROR: Save PCK: Failed to export project files.` (nothing is categorised as a "resource" here).
   The failed run still leaves a **112-byte header-only stub** at the output path — a valid `GDPC`
   header (version 4, `file_base=112`) with `dir_offset == 0` and no directory. So "did this export
   succeed?" is answerable from the artifact (`size == 112` / `dir_offset == 0`) and not only from rc.
5. **An unknown `export_filter` value is NOT refused.** `"totally_bogus"` exits 0 and produces the same
   11-file census as `all_resources`. A row that "proves refusal of a bad filter" by exit code would be
   vacuous — it must pin the **file census**, not rc.

but hides the defect.

### F2 (MEDIUM, confirmatory) — pack-only export vs binary export differ, and only one is launchable

Measured on the *same* preset and project:

```
--export-release "Linux/X11" out.pck        -> 3024 B, file_base 112, dir_off 2272, 11 entries
--export-pack  "Linux/X11" out.pck          -> byte-identical to the line above (cmp clean)   [that batch]
--export-release "Linux/X11" out.x86_64     -> writes out.x86_64 (73 519 416 B) AND out.pck
                                              (3264 B, dir_off 2512, project.binary 231 B ECFG)
```
In that batch both pack-only routes carried the empty `project.binary`, which is *why* they were
byte-identical; the 240-byte delta to the sibling pack is exactly the `project.binary` payload (231 B)
plus 9 B alignment padding. **The sibling pack written by a full-binary export is the only one of the
two that carries real project settings** — so a `--main-pack` row must launch `out.pck` as produced by
the `… .x86_64` invocation, or the fixture must build the pack and then assert its `project.binary` size.

### F6 (HIGH, new) — pack bytes are reproducible *within* a project directory but NOT across identical copies

Repeated exports of one project directory are byte-identical: 4/4 on `p08-noimport`
(`cf9d3b93…`), 4/4 on `p08-import` (`c7629cbc…`), 4/4 on `pbase` (`457fb828…`), 2/2 on `cpA`
(`4f48098f…`), 2/2 on `cpB` (`505e19b4…`).

But two **byte-identical source trees** produce different packs:

```
$ diff -r --exclude=.godot /var/tmp/r101-VER2/cpA /var/tmp/r101-VER2/cpB   # rc=0, no output
$ godot --headless --path cpA --export-pack "Linux/X11" out/cp-cpA-1.pck   # 4f48098fee4edcbc…
$ godot --headless --path cpA --export-pack "Linux/X11" out/cp-cpA-2.pck   # 4f48098fee4edcbc…
$ godot --headless --path cpB --export-pack "Linux/X11" out/cp-cpB-1.pck   # 505e19b4835fb267…
$ godot --headless --path cpB --export-pack "Linux/X11" out/cp-cpB-2.pck   # 505e19b4835fb267…
```
The only differing entries are the two `.scn` blobs (`cpA` `7fc376b7…/6682ce8c…` vs `cpB`
`c0200326…/edd847c8…`); every other entry md5 matches. So the exported scene embeds a value that is
**stable per project directory but not derivable from the source bytes**.

Five distinct `.scn` md5 pairs were observed for what is logically the same project
(`328e1003…/315842bf…`, `13d408a2…/37423843…`, `4c1633a3…/b8340a35…`, `7a05b5a7…/f46d5906…`,
`c66f8147…/c3ce89f6…`, plus `ba04c7b0…/e09ee761…` without `.uid` sidecars). Cause **not isolated** —
labelled *unknown*. Ruled out by measurement: the source bytes (identical, `diff -r` clean); the
`uid_cache.bin` contents (identical, md5 `e7f30434…`); and a `.tscn` rewrite (the 149-byte `main.tscn`
is byte-identical to what was authored — I retract that earlier hypothesis).

**Consequence for the lattice — and for s03.** The harness stages a fresh scratch project per battery
run, so a `sha256` pin on a `.pck`, or an md5 pin on a `.scn` entry, is **not stable across runs**. Only
these are safe to pin: the header fields (`magic`, `version` 4, `ver` 4.7.2, `pack_flags` 2,
`file_base` 112), the **directory shape** (entry names, entry count, sizes of the deterministic entries),
the `.remap` file **contents** (pure text, no hash), `uid_cache.bin` bytes, and within-run equality of
two exports (which *is* stable, 2/2 and 4/4 measured).

## C2 — r100-critic F2 closed: full-replay pins

Recap of F2 (`reports/round-100/r100-critic.md` §F2): each `r100b_seq_*` row pins one line of a 14-cell
replay, so a forged extra line inside the replay leaves both rows PASS.

**Division of labour with sibling seats.** `corpus/fixtures/r101_seqfull.gd` (E12) is the probe-side
closure — it re-emits the 14 cells as one contiguous `SEQ_BEGIN … SEQ_END digest=<sha256>` unit with
`FRESH_PINS` embedded by value. This shard is the **pin-side** measurement on the production classifier:
an independent replay of the *unmodified* `r100b_seq.gd`, the exact 10/14 + 4-divergence census, and an
accept/reject matrix proving which forged transcripts a whole-replay signature actually rejects. The two
agree on the 4 divergences; the remaining action is a CASES pin swap, which is integration's (I do not
edit the harness).

### Measured: the replay constrains 10/14 cells and diverges in exactly 4

`godot --headless --path <scratch>/proj --script res://r100b_seq.gd -- --clean={1,0}`
(probe `corpus/live/r100-boundary/probes/r100b_seq.gd`, sha256 `4718a19e…`; byte-identical to the
fixture copy). Each variant emits **17 stdout lines**: banner, blank, 14 `PASS r100_gui <cell>` lines,
`SEQ_DONE clean=<n>`.

| cell | clean vs fresh pin | noclean vs fresh pin |
|---|---|---|
| census, routing, focus, render, osmeta | **equal** | **equal** |
| hover, motion, localpos, clip, drag | equal | **diverge** |
| cursor | **diverge** | **diverge** |
| touch | **diverge** | **diverge** |
| subvp | **diverge** | **diverge** |
| warp | **diverge** | **diverge** |

Clean reproduces **10/14** fresh-process pins byte-identically — confirming the critic's count. The four
divergences, token-exact (fresh → replay):

* `cursor`: `c0=c1_push_mm=c2_push_mb=(0.0, 0.0)` → `(30.0, 14.0)` — the replay inherits the cursor left
  by the previous cell (`localpos` pushed at `(30,14)`); the fresh process starts at the origin.
* `touch`: `t3_emul_touch a=[A:mb(b=1,p=1,dc=0,bm=1,pos=8.0,8.0,gpos=8.0,8.0)|A:st(i=0,p=1,dt=0,pos=8.0,8.0)]`
  → `a=[A:st(i=0,p=1,dt=0,pos=8.0,8.0)]` — the emulated mouse-button line is lost once emulation state is
  already set by an earlier cell.
* `subvp`: `v2/v4 cursor_root=(0.0, 0.0)` → `(20.0, 4.0)` (two occurrences each).
* `warp`: `w0/w1/w2/w3 cursor=(0.0, 0.0)` → `(20.0, 4.0)` (four occurrences).

Noclean diverges in **9/14** (the four above plus hover, motion, localpos, clip, drag); the two rows
therefore pin *different* single cells (`clean`→`cursor`, `noclean`→`hover`) and neither constrains the
rest.

### Proposed pins and the discrimination they buy

Whole-replay signature = the 14 `PASS r100_gui <cell> …` lines joined with `\n` (they are contiguous in
the output, so a plain substring test on `stdout+stderr` is sufficient — **no `classify_process` change
needed**). Sizes: clean **6685 B**, noclean **6160 B** (current pins: 225 B / 209 B; +12.8 KB total,
~+2.5 % of the 507 KB harness).

Proof harness: `reports/round-101/mutations/ver2-c2-fullreplay-pins.py` (sha256 `bcabfc97…`). It
AST-extracts the **production `classify_process`** from the live harness (sha256 `c4db6153…`), reads the
live pins and per-row stderr allowlist from the same bytes, replays the probe twice, and runs an
accept/reject matrix:

| variant | forgery | current 1-line pin | full-replay pin |
|---|---|---|---|
| clean | real transcript | PASS | **PASS** |
| clean | extra line between hover and motion (`m_seq` shape) | **PASS** | **FAIL** |
| clean | `warp` cell edited `mode=0`→`mode=9` | **PASS** | **FAIL** |
| clean | extra line after `SEQ_DONE` | PASS | PASS (control) |
| noclean | real transcript | PASS | **PASS** |
| noclean | extra line between hover and motion | **PASS** | **FAIL** |
| noclean | `warp` cell edited | **PASS** | **FAIL** |
| noclean | extra line after `SEQ_DONE` | PASS | PASS (control) |

`4 forgeries accepted by the current pin are rejected by the full-replay pin; 0 real transcripts are
rejected`. The `m_seq` forgery the critic measured is now caught, and the three divergences the critic
listed as unconstrained (`touch`/`subvp`/`warp`) are pinned.

**Honest boundary of the fix.** A line printed *after* the 14-cell block (or *before* the first cell)
is outside the contiguous signature and still passes. Closing that too requires either extending the
signature to `banner…SEQ_DONE` (fragile: the banner carries the engine version) or adding a line-count /
`SEQ_DONE` assertion to `classify_process`. I did **not** do either; both are author-class harness
changes and belong to a seat that owns the harness.

`--apply` writes a patched *copy* of the harness to the scratch dir and prints the unified diff; the
shared `corpus/fixtures/run_battery.py` was never written.
