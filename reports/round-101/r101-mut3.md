## Mutation model

Take a C1 measurement (readback of the exported artifact: magic / size / pack table / census / sha) and
replace it with hardcoded golden constants that reproduce the receipt text exactly. The mutated fixture:

- is byte-invisible on the honest path (same receipt, same rc, same stdout);
- keeps printing PASS and exiting 0 when the artifact is tampered with or missing — that is the defect class.

Acceptance predicates measured in every stage:
- **P1 receipt_only** — substring pin of the golden receipt line (naive receipt pinning).
- **P2 battery_shape** — rc==0 + row signature + artifact exists + size>0 (shape of the `__godot_export__`
  classify in `corpus/fixtures/run_battery.py:1877-1880`).
- **P3 recompute** — independent readback: artifact exists, magic==GDPC, receipt values equal bytes on disk.

## Kill requirement (inference from the three stages)

For C1 `export_prod` rows, acceptance must not rest on the fixture's own receipts alone:

1. **Independent recompute arm** — a verifier re-derives magic / table census / size / sha256 from the
   artifact bytes (the `P3` predicate; e.g. a Python PCK parser, as used here), or
2. **negative-control arm** — feed a corrupted or missing artifact through the same row and require FAIL
   (the mutant cannot fail), or
3. pin **content hashes** in rows where content matters (`det_a`/`det_b` already do).

Receipt-only pins (P1) and artifact existence/size>0 (P2) are fooled whenever any artifact file is left on
disk. In-fixture forgery controls (`forgery_controls`, `s10:351-403`) do not help against this class: they are
printed by the same script and are trivially "passing" in a constant-emitting mutant.
