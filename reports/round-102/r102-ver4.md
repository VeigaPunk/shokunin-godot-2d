Semantics summary (observation): delta = set of *exported* files whose **content hash** differs from the
union of packs passed via `--patches` (mtime invisible); new files included; deletions encoded as
flags=2/zero-size entries; with no `--patches` the output is a full pack byte-identical (same root,
warm-warm) to `--export-pack`; ZIP packs are accepted as bases and produced as outputs. Files outside
the preset's exported set can never appear in a delta (extra.txt absent from `all_resources`
P0/P1, present only under `include_filter="*.txt"`). A preset key `patch=true` does nothing.

Pack header observed (needed by any fixture-side census parser): magic `GDPC`; u32 fmt_ver=4;
ver 4.7.2; flags=2; file_base(0x18)=112; dir_offset(0x20)=e.g. 288/1344; at dir_offset: count u32,
then per entry `plen u32` (padded, multiple of 4) + path + `offset u64` + `size u64` + `md5[16]` +
`flags u32`. Valid packs end exactly at end-of-file (`dir_end == total_bytes` in every parse).

## 4. Expected error classes (OBSERVATION; exact stderr bytes)

Streams: refusals print ALL `ERROR:` lines on **stderr**; stdout carries banner + progress bars
(split-stream probe saved `logs/split.out`/`.err`; rc=1). Common suffix line for export-path
failures: `ERROR: Project export for preset "<preset>" failed.` + `   at: _fs_changed (editor/editor_node.cpp:1417)`.

1. Unknown preset (`--export-patch "No Such Preset" …`), rc=1:
   `ERROR: Invalid export preset name: No Such Preset.` followed by
   `The following presets were detected in this project's \`export_presets.cfg\`:`
   and a quoted list (`"Linux/X11"`), `   at: _fs_changed (editor/editor_node.cpp:1417)`.
2. Unloadable `--patches` base — identical class for **missing path, garbage file, directory**:
   `ERROR: Patch Creation: Could not load patch pack with path "<path>".`
   `   at: add_message (./editor/export/editor_export_platform.h:270)`
   then `ERROR: Project export for preset "<preset>" failed.` rc=1. rc=0 never observed for these.
   (ZIP packs are *loadable*: pz.zip used as a base succeeded — class 2 is about unreadable/nonexistent
   packs, not format.)
3. Unwritable output (relative `out/patch0.pck` with no `proj/out/` yet), rc=1:
   `ERROR: Save PCK: Can't open file for writing at path "out/patch0.pck".`
   `   at: add_message (./editor/export/editor_export_platform.h:270)` + the `Project export … failed.` suffix.
   (Relative paths resolve against the project dir — the actual trap measured in REL above.)
4. Empty delta (nothing differs from supplied packs), rc=1:
   `ERROR: Save PCK: No files or changes to export.` (`at: add_message (./editor/export/editor_export_platform.h:270)`)
   then `Project export … failed.` Leaves a **112-byte header-only .pck** at the output path.
5. Output path without a supported extension (e.g. a bare directory), rc=1:
   `ERROR: Export path "/var/tmp/r102-v4/p1/out" doesn't end with a supported extension.`
   `   at: _fs_changed (editor/editor_node.cpp:1391)` + `Project export … failed.`
   (Extension check precedes the open attempt — different class from 3.)
6. `--export-patch "<preset>"` with no `<path>` and no preset default `export_path`, rc=1:
   `ERROR: Export preset "Linux/X11" doesn't have a default export path, and none was specified.`
   `   at: _fs_changed (editor/editor_node.cpp:1417)`
7. Success path: rc=0, **zero** `ERROR:` lines in merged output, `savepack | Storing File:` progress
   lines on stdout, output ends `[ DONE ] savepack`.

   (measured: CWD-relative `out/*.pck` fails with class 3 even when CWD/out exists).

   `/tmp/tmpproject.binary-*`); assert `project.binary` size > 0 if unshare is unavailable.
5. Assert refusal artifacts' exact bytes/sizes (112 B header-only on empty delta) — "no artifact"
   is WRONG for classes 3/4; only classes 1/2/5/6 written nothing (no output opened).
6. Preset key `patch=true` is inert (PKEY row) — do not build a claim on it.
