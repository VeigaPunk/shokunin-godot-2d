project.godot carries feature-tagged overrides `config/name.zzfeat="V3Feat"`,

- **[obs] Parsing law:** exporter splits `custom_features` on `,`, trims each token,
  drops empties, rejoins with `,`, stores it raw-as-normalized in a dedicated
  `project.binary` setting `_custom_features` (String variant: `04|len|bytes+pad`).
  Absent/empty → no key. Tags are **case-sensitive** at runtime.
- **[obs] `application/config/features` is rewritten:** in every variant the baked
  array is exactly `["4.7"]` (count=1; runtime `features_setting=["4.7"]`), even when
  project.godot authored `"4.8"`/`"zzthird"`; authored extras never appear in the
  pack and never become runtime features. `OS.has_feature("4.7")=false` and
  `has_48=false` → the features array is **not consulted** by `OS.has_feature`;
  runtime tags = compiled tags (`linux`+, `editor`+ under the editor binary) +
  `_custom_features`. Authored array rewrite is [obs] for the `--export-pack` path
  (4.7.2 stock templates); mechanism [inf].
- **[obs] Feature-tagged setting overrides:** `config/name.zzfeat` style keys are
  carried verbatim into `project.binary` alongside the base values (all variants;
  count=1 each). Resolution is runtime-side and requires
  `ProjectSettings.get_setting_with_override()`: with `custom_features="zzfeat"`,
  `name_ovr=V3Feat` while plain `get_setting()` stays `V3Base`; G_case
  (`ZZFEAT`) does **not** fire the lowercase override.
- **[obs] Options-key handling:** unknown `[preset.0.options]` key
  (`ver3/unknown="zzz"`) → export exit 0, pack identical class (591 B pbin);
  `binary_format/architecture="mips"` on the `--export-pack` path → exit 0, no
  validation error (architecture only gates template-binary outputs; E5's `arch`
  arm measures the `--export-release` side).
