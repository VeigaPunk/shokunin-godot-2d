# Round 102 — export launch matrix: embedded vs stock binaries, path-override support (Godot 4.7.2.stable)

Four independent scratch projects this round (r102-R1, r102-E0, r102-E2, r102-ver1; refusal gate also
r102-V2) measured what a *launched* Godot binary accepts and what it needs. Engine
`4.7.2.stable.arch_linux.ed1daf0bf` (editor 182,015,704 B); stock template `linux_release.x86_64`
73,519,416 B sha256 `d9f79ab8…c46a7c63` (`version.txt` 4.7.2.stable). Every claim below is an
observed run; [obs]/[inf]/[unk] labels per bullet.

## 1. Path-override support matrix (launcher class, [obs])

| launcher | `--main-pack` | `--path` | sanctioned project source |
|---|---|---|---|
| editor `/usr/bin/godot` | accepted | accepted | any (`--path`, `--main-pack`, positional) |
| stock export binary (`embed_pck=false`; **byte-identical to the template**, `cmp` SAME) | **refused rc=1** | **refused rc=1** | pack named `<exe>.pck` next to the exe |
| embedded export binary (`embed_pck=true`) | **refused rc=1** | **refused rc=1** | the appended pack itself; no files needed |

Verbatim refusal (stock and embedded binaries identical; 265 B stderr, stdout empty):
```
ERROR: `--main-pack` was specified on the command line, but this Godot binary was compiled without support for path overrides. Aborting.
To be able to use it, use the `disable_path_overrides=no` SCons option when compiling Godot.

   at: setup (main/main.cpp:1892)
```
The `--path` shape differs only in the flag name and `at: setup (main/main.cpp:1782)`.

- [obs] Refusal is decided at argument parse: a valid pack path and a **nonexistent** one produce
  byte-identical stderr (ver2 arms A/A2 `cmp` clean; E0 same). Pin the class, not the path.
- [obs+inf] Engine gate (source at tag 4.7.2-stable; both binaries embed `ed1daf0bf`):
  `OVERRIDE_PATH_ENABLED` is defined iff `env.editor_build or not disable_path_overrides`
  (`SConstruct:1101-1102`), and `disable_path_overrides` defaults **True**, described
  "(export template only)" (`SConstruct:272-278`). Editor builds always accept; default-built
  official templates refuse. [inf] A template built with `disable_path_overrides=no` would accept
  these flags — no such binary exists on this host (untested).
- [obs] Binary string census: refusal text occurs 5× in the template, 0× in the editor (ver2 §4);
  `godot --help` marks `--path`/`--main-pack` with its `X` legend — "Only available in editor
  builds, and export templates compiled with `disable_path_overrides=false`".
- [obs] Editor contrast is what makes a refusal row discriminate: `/usr/bin/godot --headless
  --main-pack <same pck>` runs rc=0 with the frame receipt, proving the pack is loadable and the
  refusal is a property of the launched binary (R1 row 17; E0 `editor_mainpack_contrast`; ver2 arm B).
- [obs] Wording asymmetry help `=false` vs refusal `=no` is not a defect — both are valid SCons
  bool spellings (ver2 §4).

## 2. Artifact shapes and the self-containment mechanism

| project | template T | stock pck P | embedded E | E−T | E−T−P | trailer payload |
|---|---|---|---|---|---|---|
| r102-R1 | 73,519,416 | 2,008 | 73,521,432 | 2,016 | **+8** | 2,004 = P−4 |
| r102-E0 | 73,519,416 | 2,056 | 73,521,480 | 2,064 | **+8** | 2,052 = P−4 |
| r102-E2 | 73,519,416 | 2,040 | 73,521,464 | 2,048 | **+8** | 2,036 = P−4 |
| r102-ver1 | 73,519,416 | 2,008 | 73,521,432 | 2,016 | **+8** | 2,004 = P−4 |

- [obs] `embed_pck=false` writes **two** artifacts: binary == template byte-for-byte (`cmp` SAME,
  R1; `bin_eq_template=true`, E2; ver1) plus sidecar `<exe>.pck` (head `GDPC`, R1/E2/E0). Launch =
  binary beside its name-matched pack (no CLI flags needed).
- [obs] `embed_pck=true` writes **one** artifact: template bytes + appended pack + 12-byte trailer
  `[u64 LE payload_len][47 44 50 43]` (`GDPC` at EOF). The pack starts exactly at offset T with a
  normal PCK header (R1 dd; E2, ver1 same). Payload is 4 B shorter than P and layout-shifted:
  `file_base` 104 vs 112, `dir_offset` 1528 vs 1536, first differing byte = 25; entry
  names/sizes/md5 identical (ver1 §2). Cross-format byte equality is **false** (R1: 1,599/2,004
  bytes differ, stable across warm re-exports).
- [obs] The embedded binary is **not** template+append byte-wise: exactly 6 bytes differ inside the
  last 1 KB of the template region (73518416..73518425 0-based) — the ELF **"pck" section header**
  patched with (offset `0x0461D138` = T, size `0x07E0` = 2,016). [inf] Mechanism (ver1 §1–2):
  `OS_LinuxBSD::get_embedded_pck_offset()` walks the ELF section table for a section named "pck";
  the loader's EOF fallback (`file_access_pack.cpp try_open_pack()`) reads the trailer.
- [obs] Embeddedness test: **never grep for `GDPC`** — the stock template itself contains five
  internal `GDPC` byte sequences (ver1: offsets 43122210/43122294/43122372/43122515/43295037). Use
  last-4-bytes == `GDPC` **and** u64 at EOF−12 == payload length **and** payload[0:4] == `GDPC`
  (E2 checks all three; E0 pins `tail_magic=47445043` = hex `GDPC`).
- [obs] Launch consequences: the embedded binary boots with no `.pck` and no project beside it
  (R1's dir held only binaries; E2/ver1 used true binary-only dirs), from other cwds, renamed
  (`renamed.bin` rc=0), under `env -i` (ver1). The stock
  binary alone fails with

```
ERROR: Error: Couldn't load project data at path "<dir>". Is the .pck file missing?

If you've renamed the executable, the associated .pck file should also be renamed to match the executable's name (without the extension).

   at: setup (main/main.cpp:2130)
```

  and the process **may not self-exit**: E0/E2/ver2 killed it by `timeout` (rc=124) while R1 once saw
  rc=1 and later rc=124 for the identical command — bound the arm with `timeout` and pin the class,
  not the rc alone. [inf] Mechanism (ver2 §0): non-tools builds call `OS::alert()` after the print,
  which runs the first of zenity/kdialog/Xdialog/xmessage found in `$PATH` **and waits** (blocked
  >75 s with zenity on PATH; `--headless` does not suppress it). Strip those programs from `PATH`
  and it exits rc=1 in ~10 ms with the same stderr (ver2 arm E′).

## 4. Export filters are case-insensitive (census, E4 + R1)

- [obs] E4's 14-variant matrix (all rc=0): `case/*.txt`, `case/*.TXT`, `case/*.TxT`, `CASE/*.txt`,
  `res://case/*.txt` produced **byte-identical packs** (sha256 `b577a43f…`); `*` crosses `/`;
  `exclude_filter=case/ONE.TXT` removes `one.txt`; uppercase `.GD` rides raw while lowercase `.gd`
  compiles to `.remap`+`.gdc`.
- [obs] R1's independent pair (different project shape): include `res/data/*` and `res/Data/*` →
  byte-identical packs (sha `9334925c…`), each adding **both** `res/data/note.txt` and
  `res/Data/other.txt`; a no-filter preset and a non-matching `res/nope/*` preset both produced
  7 entries with no `.txt` (negative controls). [inf] Matcher is a case-insensitive glob
  (`matchn`-like) applied after stripping `res://`; engine internals not read.
- Pin advice: keep a no-filter control so "added by the filter" is causal; the case-insensitivity
  discriminator is the byte-identity of the two case-variant exports.

## 6. Pin-design laws for launch rows

1. Refusal rows pin the launcher class, not file existence: valid and nonexistent `--main-pack`
   give byte-identical stderr; rc=1 + the two verbatim lines (+ `at: main/main.cpp:1892` as a
   version-locked diagnostic).
2. Always pair a refusal with a contrast: the editor accepts the same pack (rc=0 + frame receipt),
   so the row proves the build gate, not a corrupt pack (E0 `editor_mainpack_contrast`, ver2 arm B).
3. Embedded rows: one artifact, no sidecar (`artifacts=1 sidecar_pck=0`), EOF trailer magic +
   size-consistency + payload head magic; size as a **lower bound** (`E − T ≥ P`), never
   cross-format byte equality or template-prefix equality.
4. Frame receipts, never exit code alone: exactly `frames=[1..N]` + `extra=false`.
5. Missing-sidecar arms must be `timeout`-bounded (the process may idle on the platform alert) and
   run with zenity/kdialog/Xdialog/xmessage absent from `PATH`.
6. Warm state only: same-mode re-exports were byte-identical in all four projects; r101's
   cold-export anomaly (first export of an unimported project corrupt, 3672 B bad ECFG header)
   still applies — import first, compare same-root re-exports.
7. Never pin whole-file pack shas cross-root (r101 law); leave size fields trailing/unpinned; never
   emit device-census tokens (`joys`) in these rows.
8. Boot rows need structure beyond stdout: a wrapper script can print a marker and exit 0
   (crit1 attack 1); E0's m1/m2 mutants flip the census fields while boot rows survive — the
   structural (trailer/sidecar/size-vs-template) fields carry the embed/stock discrimination.
