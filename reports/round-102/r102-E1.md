## Mechanism and counterfactuals

- **[obs]** strace of the embedded binary (own executable opened; `lseek` to 73,519,104 =
  floor(EOF,4096), 2,376-byte read to EOF, ECFG read from inside the pack) — the loader
  locates the pack in the executable's final 4096-aligned window.
- **[obs] destroying only the tail trailer magic (`GDPC` at EOF-4 → `ZZZZ`): the binary
  still boots** — rc=0, marker, frames 1–3, empty stderr. The trailer magic is not the
  locator; do not build a negative control on it.
- **[obs] destroying the pack header at the template boundary (offset 73,519,416 →
  `ZZZZ`)**: rc=124 at the bound, no marker, launched binary's stderr verbatim
  `ERROR: Error: Couldn't load project data at path "<cwd>". Is the .pck file missing?`
  plus the rename hint; the process does **not** self-exit. This is the arm-2
  discrimination (pinned `refusal=missing_pck_refusal`, `exit_rc=124`, and — describing
  the mutated artifact — `pck_at_template_boundary=false` with trailer/accounting intact).
- **[obs] cold-export check (3/3)**: three fresh, never-imported projects each ran a single
  `--export-release` (embed_pck=true) inside `unshare` tmpfs and booted green; binary size
  73,521,480 in all three. Measure in `/var/tmp/r102-E1/cold/`. The r101 cold-export
  corruption law did not reproduce for the embedded path here; the default `embed` arm
  therefore uses one export (row 3 keeps the warm-up + independent pack reference).
- **[obs]** classifier-hazard scan of fixture output: 0 lines containing `ERROR:` /
  `SCRIPT ERROR:` / `Parse Error:` — nested engine output is redirected to logs, the
  fixture prints only PASS/FAIL + DIAG lines.
- **[obs]** `/tmp` on this host is a 16 GiB tmpfs at 80% use; exports run under
  `unshare -m --map-root-user` with a private 64 MiB tmpfs for the packer's fixed
  `/tmp/tmpproject.binary-<rand>` temp path (r101 E0 finding; same probe as `export_prod.gd`).

## Observation vs inference vs unknown

- **Observed**: every number/string above; run walls; PASS-line stability (4× embed,
  2× neg paths); the two refusal classes; cross-root sha drift at constant size.
- **Inference**: the standalone `ref.pck` (2,056 B) and the embedded payload (2,052 B) are
  the same logical pack exported twice — they share the header and suffix but differ in
  1,637 of the 2,052 common bytes, so byte identity is **not** claimed; the 4-byte size
  delta and the content delta are **unknown** in cause (not needed by the claim: the
  pinned relation is the size lower bound and the exact structural accounting).
- **Unknown / not measured**: behavior under a battery-time load spike (walls were
  measured at load 7–26); whether a future template repack changes `template_bytes`
  (rows carry that number, so a template change would surface as a red row, not a silent
  pass); whether `--quit-after` frame semantics differ on other templates (out of scope —
  that is E2's row).
