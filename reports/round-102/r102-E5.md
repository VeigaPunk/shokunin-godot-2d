**[obs]** Runtime feature-tag vector, 46 probes (`OS.has_feature`; `OS.get_feature_list()` does

  pc=true x86=true x86_64=true 64=true template=false editor=true release=false debug=true
  s3tc=true etc2=true bptc=true`; digest `95d8fa49…`.
- `--export-release` embedded binary: same platform tags, `template=true editor=false
  release=true debug=false`; digest `1adac65f…`.
- `--export-debug` embedded binary: `debug=true release=false`; digest `15f50436…`.

**[obs]** Preset `custom_features="r102e5cust"` is honored **at runtime**: exported release
binary `has_feature("r102e5cust")=true`; `custctl` (custom_features="") → `false`; the two
vectors differ only in that token (`…=true` 574 chars vs `…=false` 573 chars; digests differ).
This is the "preset feature actually honored" discriminator for the feature-tag class.

**[obs]** `binary_format/architecture="arm64"` honored: product is `ELF64/0xb7` — identical to
the installed `linux_release.arm64` template header (`ELF64_b7`), while `linux_release.x86_64`

`/usr/bin/sh: line 1: ./app.arm64: cannot execute binary file: Exec format error`.

**[obs]** `texture_format/s3tc_bptc` honored at pack level, by **withholding** not converting:
- `true`: pack contains `.godot/imported/tex.png-<md5>.s3tc.ctex` (2796 B, header `GST2`, 64×64,
  format word `0x0c800000`), packed `tex.png.import` keeps its `path.s3tc=…` line (235 B);
  pack boots under the editor binary: `TEXPROBE boot load_ok=true`, exit 0.
- `false`: pack contains **0 `.ctex` entries**; packed `tex.png.import` is 150 B with the
  `path.*` line and `[deps]` removed but `metadata.imported_formats=["s3tc_bptc"]` still present;
  the export exits 0 with **no warning** (grep of nested export log: no WARNING/ERROR/Unable);
  the pack then fails to load its scene — verbatim nested log:

- `s3tc_bptc=false, etc2_astc=true` (`tex_etc2`): same empty-remap outcome as `tex_off` —

**[inf]** The gate is a *variant selector* over on-disk `.s3tc/.etc2/.astc`-suffixed ctex files
(the `.import` now carries `path.<format>` keys + `metadata.imported_formats`), consistent with
the observed silent-drop when no enabled variant exists. Source project bytes are untouched by

## 5. Integration notes / hazards

1. `tmpl` resolves the templates dir as `$XDG_DATA_HOME` (else `$HOME/.local/share`)
   `/godot/export_templates/<ver>` and FAILs `templates_dir_missing` if absent — do not run the
   battery for these rows with `XDG_DATA_HOME` pointing at a bare scratch dir (r101's
   `templates_missing_class` row overrides XDG_DATA_HOME deliberately; mine must not).
2. `tex_off`/`tex_etc2` pin `run_exit=1` + `run_class=resource_file_not_found` as the *expected
   measured outcome* (nested editor `--main-pack` run; the editor accepts `--main-pack`, the
   stock template does not — that refusal class is E3's scenario, not this row's subject).
   If a future engine converts textures instead of dropping them, these rows flip to FAIL —
   that is the tripwire value.
3. Big products (73 MB embedded binaries) are deleted by the fixture after the run; only
   `app.sh` (123 B, debug console wrapper) and small packs (~3–6 KB) remain per variant.
4. Scratch root candidates: `EXPORT_LAUNCH_S05_ROOT` → `EXPORT_LAUNCH_ROOT` →
   `$TMPDIR/export_launch_s05` → user-data dir → `/tmp/export_launch_s05` (4096-byte
   write+readback probe). Battery-default run verified: root =
   `~/.local/share/godot/app_userdata/MechanicOneShotTest/export_launch_s05`, receipt identical.
5. Nested exports run under `unshare -m --map-root-user` private /tmp when available
   (r101 E0 EDQUOT/packer temp-path law); `EXPORT_LAUNCH_S05_DIAG userns_tmp_isolation=true`
   on this host. Without it the arms still run (pbin corruption would show in the run phase).
6. Row names must not collide with `export_launch.gd` (E0-LAUNCH-LEAD) rows — these 8
   `export_launch_*` names are the ones this shard pins.
