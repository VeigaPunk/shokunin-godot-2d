## 0. Verdict

[obs] Patch export works end-to-end on 4.7.2: `--export-patch` + `--patches` produces a normal
GDPC pack containing only files whose content differs from the listed base pack(s); it installs
onto the base pack at runtime via `ProjectSettings.load_resource_pack` (base pck + patch pck),
and against a release template binary + sidecar pck with a game-code loader. Preset-level
`patches=` and `patch_delta_encoding=true` keys are honored headlessly when placed at the
[preset.0] top level. Delta-encoded entries carry PCK entry flag 4 and reconstruct byte-exact
content at runtime. Runtime CLI `--patches` is inert (does not load patches); a patch pack has
no patch marker in its own header (flags byte-identical to a base pack).

## 1. Flag surface [obs]

`godot --help` (stripped) marks all patch flags `E` (editor builds only):
`--export-patch <preset> <path>  E  Export pack with changed files only. …`
`--patches <paths>  E  List of patches to use with --export-patch. The list is comma-separated.`

Verbatim failure classes (ANSI-stripped nested logs):
- missing / non-pack patch path: exit 1
  `ERROR: Patch Creation: Could not load patch pack with path "<path>".`
  `   at: add_message (./editor/export/editor_export_platform.h:270)`
  `ERROR: Project export for preset "Linux/X11" failed.`
- no changes vs base: exit 1
  `ERROR: Save PCK: No files or changes to export.` → plus the same `Project export … failed.` line;
  a 112-byte header-only stub file IS written (GDPC magic, file_base=112, all-zero directory).
- `--patches` with no value: exit 1, stdout line (no ERROR prefix, pre-banner abort):
  `Missing comma-separated list of patches after --patches, aborting.`
- bad preset name wins before patch loading (no Patch Creation line): exit 1
  `ERROR: Invalid export preset name: No Such Preset.`
- binary string only (UI path): `Failed to add patch "%s". Patches must be unique.` — but the CLI
  silently dedupes: `--patches base.pck,base.pck` with a real change → exit 0, count=1 [obs].

## 2. Measured matrix (manual probes, /var/tmp/r102-E6, then baked into the fixture)

Scratch project: project.godot + export_presets.cfg (Linux/X11, include_filter="patch/*") +
main.gd/main.tscn + patch/payload.txt; exports run nested under
`unshare -m --map-root-user sh -c 'mount -t tmpfs … /tmp; godot --headless --path …'` (r101 E0
packer-temp isolation). Base export ~1.8s, patch export ~1.5s, release export ~3s [obs].

- warm-warm base determinism: two `--export-pack` runs → sha256 identical
  (`a804d6a0…`, 1972 B manual project) [obs]; repeated in-fixture (`equal=true diff=0`).
- changed-only: main.gd+payload edited, `--export-patch "Linux/X11" out.pck --patches base.pck`
  → exit 0, 416 B, entries exactly {main.gdc, patch/payload.txt}; `project.binary` NOT re-stored
  (settings unchanged); `.godot/*` caches not stored [obs].
- argument order irrelevant: `--patches` before or after the positional pair → byte-identical
  output pack (sha `428da46c…` both) [obs].
- union semantics: `--patches base.pck,patch1.pck` with main.gdc equal to patch1's copy and only
  payload changed → pack stores ONLY payload.txt (main.gdc suppressed) [obs]. Diff is
  content-based: a disjoint foreign base pack (other project) skipped a file with identical bytes
  (payload.txt) while storing 7/8 [obs].
- settings delta: config/name change → patch contains {project.binary, patch/payload.txt} [obs].
- zip target: `--export-patch` to `.zip` → ZIP with exactly the changed names [obs].
- no `--patches` at all: `--export-patch` silently exports a FULL pack (exit 0), sha-identical to
  `--export-pack` of the same state [obs]. `--patches` passed to `--export-pack` is ignored
  (output sha == plain base) [obs].
- preset keys (top-level [preset.0]): `patches=PackedStringArray("<abs base.pck>")` honored —
  `--export-patch` without `--patches` emits the diff (exit 0, payload-only) [obs]; `patches=["…"]`
  (plain Array) also honored [obs]. `patch_delta_encoding=true` at top level engages delta [obs];
  the same key inside `[preset.0.options]` is silently ignored [obs].
- delta encoding: 8640-byte text file with one line changed: delta-off entry size 8648 flags=0,
  delta-on entry size 47 flags=4 (pack 8828 B vs 220 B) [obs]. Delta patch + base loaded at
  runtime via load_resource_pack reconstructs the new content exactly (len 8640→8648) [obs].
  Docs note the base packs must be the exact files/order loaded at runtime for delta patches
  (https://docs.godotengine.org/en/stable/tutorials/export/exporting_pcks.html) [inf for this tree].
- runtime consumption: `--main-pack patch.pck` alone → exit 0, boots nothing (no project.binary),
  no error line [obs]; `--main-pack base.pck --patches patch.pck` → marker still v1, i.e. runtime
  `--patches` does NOT apply the patch [obs]; in-pack script doing
  `ProjectSettings.load_resource_pack(abs_patch, true)` → `before=payload-v1 load=true after=payload-v2` [obs].
- release-binary end-to-end: `--export-release` with `binary_format/embed_pck=false` → 73,519,416 B
  binary + sidecar pck; game autoload loads `patch.pck` from exe dir → `ok=true`, marker v1→v2,
  payload-v1→payload-v2 [obs].
