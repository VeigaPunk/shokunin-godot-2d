## 8. Observations routed to the orchestrator (not this seat's claim)

* **O1 [obs]** PCK directory names are NUL-padded to a 4-byte boundary and the stored
  `name_len` **includes** the padding (`project.binary\0\0`, len 16; `.…-main.scn\0\0`,
  len 76). A parser that compares the raw decoded name misses every entry; decoding as
  UTF-8 instead of ASCII emits `Unicode parsing error … Unexpected NUL character` on
  **stderr** (3 lines, measured) — that alone would dirty a row. Relevant to every
  in-fixture pack parser (r101 `export_prod.gd` parses packs too).
* **O2 [obs, interpretation unknown]** On a pack exported straight from a freshly created
  (never imported) project, the directory reports `project.binary` at offset 1184 / 273 B
  while the `ECFG` settings blob actually sits at 1296; the pack nevertheless boots
  (`--main-pack` prints the marker). For the same project exported warm the blob is at the
  directory offset. My `ECFG`-position tripwire therefore **rejected a good pack**; the
  fixture now gates on `magic=GDPC ∧ entries>0 ∧ project.binary size>0` (which is exactly
  the r101-E0 F1 EDQUOT signature: 0-byte `project.binary` at exit 0) and leaves loadability
  to the two arms that actually run the pack. Same family as r101-E0 F1/F2 (cold-export
  anomaly) and r101-SCR1's image A/B; mechanism not read from engine source here.
* **O3 [obs]** `~/.local/share/godot` and `/var/tmp` are different mounts on this host
  (`stat -c %d`: 57 vs 31), so the template hardlink works only for scratch under the
  user-data dir (battery default) and falls back to `cp` elsewhere (`link_mode` receipt).
* **O4 [obs]** `quit()` inside `SceneTree._initialize()` does not terminate a `--script`
  run (a probe hung 60 s until killed); `call_deferred("_run")` then `quit()` exits
  immediately. The fixture follows the `export_prod.gd` pattern.
* **O5 [obs]** `HashingContext.update()` on a zero-length buffer returns FAILED and logs
  `ERROR: Condition "len == 0" is true` (fixture-side crash path on empty stderr, caught by
  M1 before the fix); `_sha256_bytes()` now returns `""` for empty input, so a mutated/odd
  run cannot dirty stderr.

## 9. Left undone / residual risk

* The `refuse` row gates the pack **structurally**; boot loadability is asserted by the
  `contrast`/`sibling` rows. If the orchestrator registers only the refusal row, the row is
  still non-vacuous (the verbatim fragment + rc + the nonexistent-pack counterfactual), but
  the family is strongest with all three rows.
* Scratch root: `EXPORT_LAUNCH_S03_ROOT` → `<engine user-data dir>/export_launch_s03/<hash(project dir)>`
  → `$TMPDIR/…` → `/tmp/…` (first candidate passing a 4096-byte write+readback probe). The
  battery's run-stamped scratch dir keeps runs isolated; each run leaves ~2 KB plus one
  hardlink under `<user-data>/export_launch_s03/` (deleting that directory is safe — it only
  drops the staged link, never the template).
* Not measured here: Windows/macOS/debug-template behaviour of `--main-pack`; `--scene`
  refusal (measured once as the same class, 260 B stderr, not turned into a row — E0's
  matrix territory); `--export-patch` (E6's seat).
* `/tmp` quota state during this session: a 1-byte probe succeeded (`/tmp` 80 % full,
  3.1 G free); the fixture's `unshare` retry path and `pbin_size` tripwire remain the guard
  for the r101-E0 F1 window.
