## Symptom
A queue of r91–r99 "dead-line" deletions (write-only stores, declaration-only helpers,
zero-call-site functions) was proven byte/verdict-neutral by three r101 simplifier seats and shipped
as 12 unified-diff shards (−59 lines, 10 fixtures). A round later none of it had landed — and
landing it is not `git apply`: one patch breaks a **live row** that pins the folded fixture's bytes
at runtime, several break prose citations, and one collides with a landed lesson.

## Dead-line queue discipline (what the three seats proved, measured)
1. **Two legs per item.** Static proof of deadness (declaration-only / zero-call-site / write-only
   store census) plus execution proof at the battery launch shape: byte-identical PASS lines and
   exit codes against the committed bytes, multiple fresh processes.
2. **Fold-sha identity.** Re-applying the patch must reproduce the sha the originating round
   recorded (r95: `c128e9cc…`/`b367559e…`, re-measured). This separates the queued fold from a
   re-derivation under the queue's name.
3. **Null-control rule.** A field counts as a fold effect only if single-valued on the committed
   side and different on the folded side; rep-varying keys are declared load noise (r101-simp1's 11
   such rows; r101-simp3 resolved a 14-vs-15 anomaly as load-conditioned by interleaved A/B).
4. **Teeth.** The comparator must reject mutants: 1-token mutations FAILed 2/2 via the battery's
   own pins (r101-simp2).
5. **Queue arithmetic is three numbers, not one.** Sites ≠ stores ≠ removed lines (r95: 18/15/5;
   measured dss −3, order −2). Headline counts can be wrong in the report itself (r98 "−19" vs its
   own per-file −17; r99 "−2" counted folds, not lines). Land by measured file deltas.
6. **Ownership is a set union, not two halves' prose.** r102 gap: `r99b_modes.gd` F2 and
   `r100b_seq.gd` SP2/SP3 were each handed to "the other half"; strict boundaries (≤ `project.godot`
   / > `r99b_modes.gd`) cover neither file, and both items are still unlanded. Verify the union
   covers the harvest; give every item one explicit owner.
7. **Apply once.** Independent seats can emit byte-identical patches (nav: simp1 ≡ simp3). Keep one.
8. **Dropped items keep their reasons** (r98 F5, r99 F3/F4, r100 SP1) — the ledger is part of the
   queue.

## Cite hygiene at landing — three citation classes
1. **Prose cites** (harness comments, SCORECARD command rows, PROVINCE claims): fix live surfaces at
   landing; a sha swap alone is not enough — claims like "identical bytes" or "deliberately NOT
   folded" must be restated (`run_battery.py:883`, `:886`, `:1408`). r101 shipped a comment patch for
   two sha lines and even it leaves those parentheticals stale.
2. **Historical receipts** (`reports/*`, `corpus/live/*`, 736 lesson occurrences): flag, never
   silently rewrite — the old sha *is* the history.
3. **Live bytes-pins**: a fixture that reads another fixture's bytes and a row that pins the result.
   Measured counterfactual: folding `r95b_order.gd` changes `r101_ytrans_census`'s output from
   `r95b_lines=778 r95b_sha256=4f7e945e…` to `r95b_lines=776 r95b_sha256=b367559e…`; the landed
   signature substring count goes 1 → 0 under `classify_process`'s `signature in output`, so the row
   would fail. Re-anchor the pin (or narrow the signature) in the same landing. Search for this class
   with a *fixture-layer* census (`get_file_as_string` / `sha256_text` over `res://<other fixture>`),
   not a prose grep.

## Stale-cite census method (cheap, repeatable)
1. Fix the dead pattern verbatim; count files + occurrences per scope; record zero-hit scopes to
   bound blast radius (`.shokunin/game-dev-2d/corpus/`: SCORECARD 3, lessons 100/736, fixtures 0,
   README 0).
2. Calibrate pattern width: the family pattern `.shokunin/game-dev-2d` finds 748 lesson occurrences
   (+12) and one extra PROVINCE hit (line 12). State the width with the count.
3. Classify each hit: live surface → fix; historical receipt → flag; present-tense claim → restate.
4. Census the fixture layer for runtime byte-readers and the harness for pinned fixture bytes
   (class 3 above) — the grep that matters most is the one in `*.gd`, not in prose.
5. Re-run at landing time.

## Pitfalls
1. "No live gate reads a sha" was false the moment a census row landed: `hashlib` in the harness
   hashes same-run artifacts, but a fixture can hash another fixture and a row can pin it.
2. Folded bytes shift GDScript backtrace line numbers; that diff class is declared and unpinned —
   check no `expected_errors`/`required_stderr` entry references a line number.
3. Queue deltas are measured per file; headline numbers drift (see discipline 5).
4. A frozen fixture can carry both an evidence role and a queue item; resolve the doctrine collision
   explicitly (r95b_order.gd: pitfall 3 of `r101-ytrans-dead-flag.md` vs the r95 fold).
5. Landing is atomic: fixture bytes + harness comments + live pins + (if taken) the doctrine note.
   None of the pieces is safe alone.

## Verification recipe
1. `git apply --check` every patch at HEAD; dedupe duplicates.
2. Apply in scratch; assert folded shas equal the originating round's records.
3. For every folded fixture, census both readers: harness comments citing its sha, and fixtures
   reading its bytes; re-anchor the pins found (§class 3).
4. Run the affected rows standalone on base vs folded; assert only declared diff classes
   (backtrace line numbers, load-noise fields).
5. After landing, re-run the dead-path census (expect the live counts at 0/0) and the battery once.
