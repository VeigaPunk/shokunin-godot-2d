# Round 32 regression scout — prior UI cases and battery caveats

Read-only review of the r32 CheckBox coverage proposal, current fixture inventory/runner cases, r31 named-verifier report/raw record, and earlier UI evidence. I ran no engine or battery command and changed no fixture or runner. This report is my only artifact.

## Existing UI and seeded-case boundary

The tracked UI-adjacent fixtures already include `ui_signal_hud.gd` (synthetic `score_changed` signal to `Label.text`, plus disconnected negative), `health_gauge.gd` (range/value and `value_changed` receipt, plus disconnected negative), and `button_activation.gd` (focused routed `ui_accept` to `Button.pressed`/Label, two press/release pairs, disconnected, initially unfocused, and between-pair focus-loss controls). The current `CASES` list has eight rows across those three fixtures. Neither fixture inventory nor `CASES` contains a CheckBox, checked-state transition, or `toggled(bool)` probe. Thus a two-action CheckBox with direct checked-state and ordered boolean signal assertions would exercise a distinct stateful control/signal behavior, rather than merely repeat the Button receipt path. The pre-existing HUD signal is a manually emitted score update and does not establish a CheckBox toggling behavior.

The r31 named verifier report/raw (`corpus/lessons/r31-focus-loss-verifier.json`, SHA-256 `e0f59818e105537ce800fec3d7c62f68123fe0c952db35e7f87b6eed7288c30b`) records 54/54 PASS (43 ordinary plus 11 probe/mutant records); it preserved the prior 53 case verdict/exit/signature triples and added `button_activation_focus_loss`. That is the prior baseline, not a fresh r32 replay. The preceding r3 UI verifier also supports only its narrow synthetic signal-to-Label test and explicitly disclaims production/rendered UI inference; it is not evidence for CheckBox semantics.

For an isolated paired control, both connected and disconnected arms should send identical focused `ui_accept` press/release actions and verify the CheckBox changes checked state after each action. The connected arm should additionally assert exact `toggled` receipt order `[true, false]` and Label On/Off text. The disconnected arm should demonstrate that the control still toggles while it has no receipts and the Label remains at baseline, then fail at a specifically intended signal/Label assertion—not setup. This separates the control's built-in state transition from callback wiring; do not manually emit `toggled` or derive its receipt from `button_pressed` in place of observing the signal. If the runner captures an expected-negative failure, its diagnostic signature should identify that deliberate assertion. Whether the proposed root-level `push_input(ui_accept)` actually toggles the new CheckBox is not established by this read-only review and needs real-Godot evidence from the executor/verifier.

## Export, timeout, and fault caveats

The r31 full verifier's export-launch and timeout opt-ins are regression evidence from that prior run only, not fresh r32 results. Earlier regression reports describe the export probe narrowly as a bounded Linux/X11 export-and-launch check (including a positive launch assertion and a negative control), not general export readiness across targets. Timeout probes classify bounded child-process behavior, not arbitrary hangs or all cleanup scenarios. The separate `corpus/lessons/r31-fault-verifier.json` has an outer harness PASS while intentionally recording `fault_hang` timeout and `fault_unrelated_error` as inner FAILs; it is a fault-injection self-test, not a clean seeded-fixture replay and not CheckBox evidence. Preserve the distinction if reporting the next full and fault-injection runs; do not count intentional inner fault FAILs as ordinary battery regressions or describe the fault run as all-pass.

## Bounded conclusion

The candidate is plausibly a distinct, narrow coverage addition because no current seeded row exercises CheckBox state or `toggled(bool)`. Its coverage claim requires the connected/disconnected causal contrast and a named non-author full replay showing prior rows unchanged; the disconnected treatment must still prove the built-in state transition before the callback-specific failure. This source/raw review makes no new runtime or regression-free finding. Claims should remain limited to synthetic headless routed-input, in-memory control state, signal receipts, and Label properties—not pointer activation, rendering, accessibility, real-user timing, or production UI. No engine/editor or seeded controls were changed; no commit, push, or merge.
