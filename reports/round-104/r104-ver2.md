## 3. C2a — tab-PASS tightening: verified effective AND false-positive-free

Probe: `python3 reports/round-104/mutations/r104-V2-gate-replay.py --census|--replay-tightened`
Battery copy sha `2af2bc841ccb416e5fb0e1bbaadc08627e2d4768a8822f6956e867d905a3d0fe` (identical to the repo file).

Current gate census is `line.startswith("PASS ")` (`run_battery.py:1904`). Tightened form tested: `re.match(r"^PASS(?=\s|$)", line)`.

**False-positive census (observation):** over all 8 stored runs — `PASS-space=4548 PASS-tight=4548 false_positive_candidates=0`. On the r104 green run (571 rows): `PASS-space=582 PASS-tight=582 FP=0`.

**Gate-level regression (observation):** `receipt_shape_audit` over three stored runs gives identical results before/after the tightening — `audited=554 flags=0` ×2 and `audited=538 flags=0`; sha of each run unchanged.

**Effect (observation):** with the tightened census, both previously-silent tab shapes flag:

| shape | current gate | tightened `^PASS(?=\s\|$)` | wide `^[ \t]*PASS(?=\s\|$)` |
|---|---|---|---|
| `s4d_tab_after_pass_simple` (`PASS\tforged=true`) | **UNFLAGGED** | `unaccounted_pass_lines` | caught |
| `s4e_tab_after_pass_grammar_seq` | **UNFLAGGED** | `pass_line_grammar_mismatch` | caught |
| `s4a_tab_lead_simple` (`\tPASS …`) | **UNFLAGGED** | UNFLAGGED (line no longer starts with `PASS`) | caught |
| `' PASS forged=true'` (leading space) | **UNFLAGGED** | UNFLAGGED | caught |

**Finding:** `s4a` (leading tab) and the leading-space variant are *not* caught by the plain `^PASS` tightening, because a leading whitespace char makes the line not start with `PASS` at all. They are a separate hole: the line is invisible to both the census and the anchor search. The wide form catches all three whitespace variants. Recommended line-pair (orchestrator applies, not applied by me):

```
-    pass_lines = [line for line in output if line.startswith("PASS ")]
+    pass_lines = [line for line in output if re.match(r"^[ \t]*PASS(?=\s|$)", line)]
```
and the corresponding anchor search at `run_battery.py:1929` / the span clause at `:1964` would need the same lead-whitespace tolerance to stay consistent.
