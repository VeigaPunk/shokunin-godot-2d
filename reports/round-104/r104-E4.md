## 3. Cross-process persistence — **the load-bearing law** (observation)

Project `/var/tmp/r104-E4/p2` (project.godot + alpha.gd + main.tscn).

`godot --headless --path … --editor --quit` produced exactly two artifacts:

```
/var/tmp/r104-E4/p2/alpha.gd.uid          (text)
/var/tmp/r104-E4/p2/.godot/uid_cache.bin  (binary, 30 B)
```

Text sidecar bytes: `uid://b42fwoffwfrx8\n` (19 B, xxd: `7569 643a 2f2f 6234 3266 776f 6666 7766 7278 380a`).

**Cache format law.** xxd of a 1-record cache:

```
00000000: 0100 0000 dbcf 5c86 24fa 243e 0e00 0000  ......\.$.$>....
00000010: 7265 733a 2f2f 616c 7068 612e 6764       res://alpha.gd
```

Decoded: u32 **record count** (`1`), then `<u64 id><u32 path_len><path bytes>`. The `dbcf5c8624fa243e` u64 is the same value `text_to_id("uid://b42fwoffwfrx8")` returns (`4477978964293111771`) — so the cache stores the **binary id**, not the text.

> **Correction row.** I first read that leading u32 as a format `version` (=1). It is the **record count**: adding a second script (`reader.gd`) to the same project made the same field read `2`. The fixture was corrected to `cache_records` / `cache_declared` / `cache_consistent` and the mismatch is now a hard FAIL reason (`cache_count_mismatch`). *Inference: had this stayed as a `version` claim, the pinned PASS text would have asserted a falsehood the moment a second script was scanned.*

**Authority matrix.** Same project, new `--script` process each time, cache/sidecar present or removed:

| # | cache | sidecar | new-process `has_id` / `get_id_path` |
|---|---|---|---|
| A | present | present | `has=true path='res://alpha.gd'` |
| B | **removed** | present | `has=false path=''` |
| C | present | **removed** | `has=true path='res://alpha.gd'` |
| D | removed | removed | `has=false path=''` |

**Laws:**
- The binary `.godot/uid_cache.bin` is the **runtime authority** (B vs A).
- The text `.uid` sidecar alone is **not** a runtime authority (B) — it is the *editor's input*.
- Re-running `--editor --quit` with only the sidecar present **rebuilds** the cache: after B, an editor run restored `has=true` (cache 80 B).
- `add_id` in a plain `--script` process **never persists**: `ADDED has=true` in-process, but the next process reports `RD has=false path='' cache=false` — no `uid_cache.bin` was written at all.
- `--editor --script res://mk.gd` **does** run the script (it printed `ADDED has=true`), but a later `--editor --quit` still left **no** cache file: script-time `add_id` is not the code path that writes the cache.
- A **hand-written** cache is honored: I wrote `[(1234567890123456789,'res://alpha.gd'),(9876543210987654321,'res://ghost_missing.gd')]` into a fresh `.godot/uid_cache.bin` and a new process reported `has=true path='res://alpha.gd'` and `uid_to_path(handwritten)='res://alpha.gd'`. A record pointing at a **missing** file resolves to nothing: `ERROR: Invalid UID.` + `Resource file not found:` + `load(ghost)=<Object#null>`.
- Malformed caches are non-fatal and yield an empty table: version-as-9 garbage → `ERROR: Condition "rl != len" is true. Returning: ERR_FILE_CORRUPT`, process still boots; truncated (4 B) and 0-byte caches boot silently with `has_id(1)=false`.
- **Unknown:** whether a *runtime* (non-editor) build ever writes `uid_cache.bin`; not probed (only the editor build is installed).

## 4. `.import` remap resolution (observation)

`godot --headless --path /var/tmp/r104-E4/p5 --import` over a 74 B generated PNG produced `tex.png.import` carrying a **third** UID carrier:

```
[remap]
importer="texture"
type="CompressedTexture2D"
uid="uid://dll8spw3sxib4"
path="res://.godot/imported/tex.png-10d3a990b41350f0a871e8ec6d1daf61.ctex"
```

and the cache gained `res://tex.png` (source path, not the `.ctex` dest). In a new process:

```
M1 text_to_id=7956084114577006903        M2 has_id=true
M3 get_id_path='res://tex.png'           M4 uid_to_path='res://tex.png'
M5 path_to_uid(res://tex.png)=uid://dll8spw3sxib4
M6 ensure_path(uid)='res://tex.png'
M7 load(uid)=(res://tex.png):<CompressedTexture2D#-9223372010430659126> class=CompressedTexture2D
M8 load(res path)=(res://tex.png):<CompressedTexture2D#…9126> same=true
M9 load(ctex path)=(res://.godot/imported/…ctex):<CompressedTexture2D#…5315>
```

**Law:** the uid resolves to the **source** path; `load(uid)` and `load(source)` return the **same object** (`same=true`), while loading the remap destination `.ctex` directly returns a **different instance**. So uid→source→remap is the identity-preserving route; the dest path bypasses the source-keyed cache.

## 5. Collision class verbatim (observation)

Two sidecars carrying the same UID text (`alpha.gd.uid` == `beta.gd.uid` == `uid://b42fwoffwfrx8`), then `--editor --quit`:

```
WARNING: UID duplicate detected between res://beta.gd and res://alpha.gd.
```

Cache after the scan (29 B, 1 record): `id 4477978964293111771 path res://beta.gd`. So the **contested id keeps exactly one record**, and the survivor is the path the scan bound last (observed `beta` over `alpha`; the other script's sidecar keeps its text but has **no** cache record). A new process then resolves that id to the survivor:

```
C has=true path='res://beta.gd'
C path_to_uid(alpha)=res://alpha.gd      (echo: no cache record)
C path_to_uid(beta)=uid://b42fwoffwfrx8
C uid_to_path='res://beta.gd'
C load(uid)=(res://beta.gd):<GDScript#-9223372010397104694>
```

**Unknown:** the tie-break is documented here as *observed* (beta over alpha) — the ordering rule behind it (scan order / directory listing) was not isolated, so the fixture asserts only `winner_in_pair` + `reader_matches_winner`, never a specific winner.

Timing (bound 8 s per `execute()`): persist 5 s, classes 1–2 s, collision 3–4 s. All under bound.

**Second correction row.** `create_id_for_path()` is **pure**: `create_id_for_path("res://beta.gd")` twice returns the *same* id (`107602395070482108`), but `has_id(cid)=false` and `path_to_uid` still echoes. It mints a deterministic id for a path **without registering it**. My first assertion was named `cidf_registers` and read `false` — the engine was right, my claim was wrong; renamed to `cidf_deterministic` + `cidf_pure`.

**Determinism defect found and fixed in-fixture:** the scratch project accumulated the generated `reader.gd` across arm runs, and every generated `.gd` gets its own `.uid` sidecar and cache record — the count drifted `1 → 2`. `_stage()` now wipes the project directory before each arm.
