## 2. Method: the harm criterion (why the naive test proves nothing)

`classify_process`'s verdict clause is `signature in output` (`run_battery.py:2107`) — a **substring**
predicate over the joined stdout. So the question is not "does a forged line get appended?" (an
*injection*: harmless while the genuine receipt line is still present — this is exactly why r103 read
the shapes as harmless), but:

> Can a forged line **carry** the pin while the row's own designed receipt line is **gone**?

Two test forms per (shape, base) pair:

* **A — plain**: the shape injected exactly as r103's `mut05_gate_evasion.py` built it.
* **B — strengthened (substitution)**: every output line containing the pin text is removed; the
  shape's own line form is appended, wrapped around the pin.
* **C — negative control**: B's removal, no carrier (pin absent everywhere).

`VERDICT_LAYER_HARM(B)` = gate silent **AND** `classify_process` True **AND** the row's exact designed
receipt line absent **AND** C classifies False. The last clause is what makes the carrier load-bearing:
it proves the row would have been rejected without the forgery.

1. **REFUTE** r103's disposition "6 unflagged = accounted classes … or verdict-layer-harmless".
   Three of the six (`s2a`, `s4a`, `s4d`) are verdict-layer harmful on the very base row r103 built

3. **Root cause is shared and single**: the gate's pass-line census is `line.startswith("PASS ")`
   (`run_battery.py:1904`) while `classify_process` uses substring membership (`:2107`). Every
   separator other than a single space (`\t` before, `\t`/NBSP after, trailing space) is invisible to
   the census and sufficient for the classifier. This is the same defect C2a (G1) routes for
   tightening; this shard supplies the missing harm proof for it.
4. **Not covered by any candidate fix here** (routed, not claimed): the `s2 diag-prefixed` carrier
   needs no PASS-shaped line at all — it evades by *not* being a PASS line. Tightening the PASS census
   alone does not close it; the row needs a positive receipt-identity binding (the mut09 G-B
   `run_log_sha256`/line-count closure, or a pinned-span byte binding).
