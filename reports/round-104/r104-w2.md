## 0. Headline

The widening is a **zero-false-positive, zero-blast-radius move on every stored receipt** — but the
routed phrasing "extend the pass-line census" **understates the surface by 3 sites**: HEAD tests
`line.startswith("PASS ")` at **four** places, and widening only the census site leaves the three
window predicates blind to the same evasive bytes. The recommended predicate is variant **C**
(separator clause), not a bare `lstrip().startswith("PASS")`.

## 1. Gate-site inventory [obs]

Command: `grep -n 'startswith("PASS' corpus/fixtures/run_battery.py`

```
1904:    pass_lines = [line for line in output if line.startswith("PASS ")]
1965:                if not (line.startswith("PASS ") or RECEIPT_SEQ_RE.match(line)):
1970:                if (line.startswith("PASS ") or RECEIPT_SEQ_RE.match(line)
1988:            if (line.startswith("PASS ") or RECEIPT_BANNER_RE.match(line)
```
`grep -c` = **4**. Roles: 1904 = the census (drives `pass_line_grammar_mismatch`,
`unaccounted_pass_lines`, `pass_line_unanchored`); 1965 = allowed-line set **inside** a
`SEQ_BEGIN..SEQ_END` window (`foreign_in_span`); 1970 = allowed-line set **after** the span
(`foreign_after_span`); 1988 = allowed-line set in a `*_DIAG` window (`foreign_in_diag_window`).

Every one of the four is an *allowlist* predicate: an unmatched line is a **foreign** line. So a
grammar-invisible PASS line is not merely miscounted at 1904 — at 1965/1970/1988 it is *already*
classified foreign by HEAD. That is why widening the three window sites is what turns an
invisible-allowline into a caught one (see §5).

Variant A (census site only) is strictly weaker than C: it leaves the three window predicates at
HEAD, so an invisible PASS line **inside** a span/DIAG window still flags (as `foreign_*`) but is not
accounted as a pass line, and — more importantly — the *clean* span baseline already flags for an
unrelated reason (see §6). Variant B and D are **separator-blind** and would false-flag any
`PASSIVE`/`PASS=`/`PASSTHROUGH` line; C's separator clause avoids that at no cost in coverage.

**Recommended: variant C at all four sites.**
`line.startswith("PASS ")` → `(line.lstrip() == "PASS" or line.lstrip().startswith(("PASS ", "PASS\t")))`

## 8. False-positive analysis [obs]

- **Stored corpus:** widening changes **0 of 25,221** PASS rows across all 252 runs. Every stored
  PASS line is already `S_SPACE`, so the widened predicate is a strict superset that fires on
  nothing new. This is the strongest available false-positive statement.
- **Current lineage:** the three current runs are clean under HEAD too — `…T212500…` 0 flags,
  `…T213443…` 0 flags, `…T005558…` 0 flags. The 68 corpus-wide flags sit in 15 **non-current** runs
  (r28/r29/r30/r79 era + 3 r104-era experiment runs: `…T200239…` 4, `…T202131…` 2, `…T001435…` 15);
  they are pre-gate records (`pass_line_unanchored`, `anchor_line_multiplicity`,
  `foreign_in_diag_window`), not regressions, and the widening does not touch them.
- **Separator false positives:** a bare `lstrip().startswith("PASS")` (variant B/D) would flag
  `PASSIVE`, `PASS=`, `PASSTHROUGH` if any fixture ever emitted them. None does today (source census
  §2: 0 `OTHER` literals), but the clause in C makes that class structurally impossible rather than
  merely currently-absent — the same "floor not ceiling" posture as the existing
  `RECEIPT_ANCHOR_MULTIPLICITY` and `RECEIPT_MULTI_PASS_GRAMMAR` tables.
- **Anchor side effect:** none observed. The widened set is identical to the HEAD set on all stored
  rows, so `anchor_line_multiplicity` hits are unchanged.

## 10. Residuals / handoff [inf unless noted]

- **R-1 (completeness):** the three window predicates (1965/1970/1988) must move together with the
  census or the account is inconsistent — a line can be foreign-in-window yet absent from the pass
  census. Variant A is therefore *not* a valid landing even though it is corpus-silent.
- **R-2:** the synthetic-span probe in §6 is not a green control (the span baseline itself flags).
  A C3-style replay probe should build its span case on the `r101_seqfull_*` fixture lineage and a
  green run, or declare the span shapes as label-only checks.
- **R-3:** `\r`-only line endings are normalised by `text=True` before the gate sees them, so a
  `\rPASS` lead is unreachable by construction (not covered by any variant). [obs from the capture
  idiom; the byte probe used `\n` only.]
- **R-4:** the widened predicate still does not bind *values* — a bound-verb, bound-key forgery with a
  normal separator is unaffected (r103 W2 residual R-1, unchanged by this tightening).
- **Maintenance:** the separator clause is a floor. If a future fixture emits `PASS` with a new
  separator it will flag, by design; the census §2 is the refresh trigger.
- **Verification hooks for other seats:** `gate_C.py` is importable; `pass_census2.py` and
  `source_census.py` are re-runnable over any future `corpus/live/**` tree, so the "0 invisible"
  claim is a standing regression check, not a one-off.
