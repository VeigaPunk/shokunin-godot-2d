**INFERENCE (load-bearing for the verdict):** because instance ids differ across processes, an
id field in a receipt is *unverifiable* by a later consumer, while a `same_*` boolean is a claim
about a relation inside the run. So a forged identity receipt cannot be defeated by checking ids
against a stored expectation — it can only be defeated by requiring the receipt to be *this run's
own* output.

**Residual (measured, not assumed):** the genuine probe's first row carries the identity claim as
`same_default=1` (REUSE), **not** `same_ignore=1`. Any naive classifier that keys on a specific
token rather than the identity relation itself will mis-reject a genuine row — see §5 defect D2.

## 5. Defects found and fixed in this script (kept for the record)

- **D1** probe could not write its evidence file: `FileAccess.open()` returned null because the
  parent dir did not exist → every arm silently produced an empty transcript and the genuine
  control was mis-classified `FAIL`. Fix: `g_ev.parent.mkdir(parents=True, exist_ok=True)`.
- **D2** `naive_verdict` keyed on `same_ignore == "1"`, which no genuine row carries (the claim is
  `same_default=1`). It mis-rejected the genuine control — a false-positive class in the naive
  classifier itself. Fix: accept any identity token (`same_default` or `same_ignore`).
- **D3** `t0` was a single mutable local reassigned by each arm, so the genuine assertion compared
  against the *last* arm's timestamp. Fix: dedicated `t0_g` captured immediately before the
  genuine run.
- **D4** `honest_reuse` had an mtime clause but no `mtime_ns` parameter, so the F3 stale check
  could never fire. Fix: added the parameter and passed the evidence mtime.
