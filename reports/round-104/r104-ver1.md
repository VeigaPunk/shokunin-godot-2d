Command: `godot --headless --path /var/tmp/r104-ver1/proj --script res://ver1_probe.gd`
```
A1 uid_methods=add_id,create_id,create_id_for_path,ensure_path,get_id_path,has_id,id_to_text,path_to_uid,remove_id,set_id,text_to_id,uid_to_path

```
**Trap:** `add_id`/`set_id`/`remove_id` return **Nil**. A fixture that writes `var e := ResourceUID.add_id(...)` fails to parse (`Cannot get return value of call to "add_id()" because it returns "void"` — my first probe died exactly this way, rc=1). Use `callv` or discard the result.

### 1.2 The `uid://` text codec [observation + inference from source]
Base **34**, alphabet `a b c … x y` (25 letters; `z` never emitted) then `0 1 … 8` (9 digits; `9` never emitted). `text_to_id` accepts `a–z` (so `z` decodes as 25, aliasing `0`) and `0–9` (`9` decodes as 34 = `10` in base 34).
```
uid://bqk3m5n7qar1 -> 103876737118377468   id_to_text round-trip exact
uid://baes3tab0rv7n -> 2395822100831663705  exact
uid://ddbllxjwch6x3 -> 7372581713343701886  exact
uid://dkcknnn0jeoy -> 231350303889713852   exact
uid://bxco4ao4o1moj -> 4005794691762572005  exact
uid:// -> 0 | uid://x -> 23 | uid://zzz -> 29775 | uid://z -> 25 | uid://9 -> 34
'' -> -1 | 'not-a-uid' -> -1 | 'bqk3m5n7qar1' -> -1 | 'uid://@@@@' -> -1 | 'uid://<invalid>' -> -1
id_to_text(-1) = uid://<invalid> | id_to_text(0) = uid://a | id_to_text(1) = uid://b
id_to_text(0x7FFFFFFFFFFFFFFF) = uid://d4n4ub6itg400   (== the source comment's own example)
```
My Python reimplementation round-trips all five measured pairs in **both** directions (`ALL ROUND-TRIP EXACT: True`). Note the source comment at `ruid472.cpp:42` — *"These constants are off by 1, causing the 'z' and '9' characters never to be used"* — is accurate for emission, and `uid://aaaa=0`/`uid://b0=59` confirm leading-digit equivalence.

### 1.3 Sidecar vs cache authority [observation — decisive]
Three project copies of an `--import`ed project, same fixture (`ver1_persist.gd`):
```
p1  cache+.uid present : get_resource_uid(sample.gd)=231350303889713852 ; get_id_path=res://sample.gd
p2  cache DELETED      : get_resource_uid(sample.gd)=-1 ; get_resource_uid(icon.svg)=-1 ; get_id_path="" ; has_id=false
p3  .uid DELETED       : get_resource_uid(sample.gd)=231350303889713852 ; get_resource_uid(icon.svg)=4005794691762572005
```
**Law:** `.godot/uid_cache.bin` is the sole runtime authority. A hand-written `<file>.uid` sidecar is an editor artifact and is **not** honoured at runtime. `load()` still works with the cache gone (it resolves by path) — only uid *resolution* dies.

### 1.4 Cache file layout [observation, verified byte-for-byte]
`--import` produced `.godot/uid_cache.bin` (57 B). Python decode of the raw bytes:
```
u32 count=2
entry 0 id=231350303889713852  len=15 path=res://sample.gd
entry 1 id=4005794691762572005 len=14 path=res://icon.svg
trailing 0
```
Matches `ruid472.cpp` `encode_binary_cache`: `u32 count` + `{u64 id, u32 len, bytes path}[]`.

### 1.5 Diagnostics and the `cache_initialized` gate [observation + source]
```
no cache, no add_id yet : get_id_path(unknown) -> ""   stderr 0 B
after add_id(4242,...)  : get_id_path(4242) -> res://g_probe.tres
                          get_id_path(unknown) -> "" + ERROR: Unrecognized UID: "uid://k18y".
cache present           : get_id_path(unknown) -> "" + ERROR: Unrecognized UID: "uid://<tok>".
always                  : get_id_path(INVALID_ID=-1) -> "" + ERROR: Invalid UID.  (resource_uid.cpp:196)
```
`get_id_path` prints `Unrecognized UID` **only** when `cache_initialized` (set by `load_from_cache` or by `add_id`); the `Invalid UID.` line for `INVALID_ID` is unconditional. This independently explains the `r96_scene_io_uid` allowlist entry at `run_battery.py:2541` ("fires iff the scratch project has .godot/uid_cache.bin").

### 1.6 `create_id_for_path` [observation + source]
```
same path twice, same content       -> identical          (stable=true)
same path, content changed v1->v2   -> DIFFERENT          (4626887699946119507 -> 5603804854903260943)
two different paths, same content   -> different
nonexistent path, twice             -> identical (md5 of a missing file is a constant)
cross-process, same project name    -> identical (3 runs byte-equal)
```
Source (`ruid472.cpp:142`): `rng.seed(project_name.hash64() * p_path.to_lower().hash64() * FileAccess::get_md5(p_path).hash64())`. It **never registers** (`has_id` stays false) and does **not** reproduce the value an `--import` mints into `<file>.uid` (`sample.gd.uid` = `uid://dkcknnn0jeoy` = 231350303889713852, while `create_id_for_path("res://sample.gd")` = 8221610698970337638).

### 1.7 Collision classes [observation]
```
add_id(x, p) twice                 -> REFUSED, first path kept, engine ERROR "Condition \"unique_ids.has(p_id)\" is true." (resource_uid.cpp:164)
set_id(absent)                     -> no-op + "Condition \"!unique_ids.has(p_id)\" is true." (:232)
remove_id(absent)                  -> no-op + same assert (:232)
two ids -> one path                -> BOTH ids answer get_id_path with that path; path_to_uid() returns the SECOND id's text; get_resource_uid() returns the second id
one id  -> path moved via set_id   -> get_id_path follows; ResourceLoader.get_resource_uid(old path) returns -1
```
All three void calls still leave the process exit code at **0** — a refusal is an ERROR line, never a non-zero exit.

### 1.8 Stale entries / uid-addressed load [observation]
```
cache maps uid -> res://moved_from.gd (file absent):
  has_id=true, get_id_path=res://moved_from.gd, uid_to_path=res://moved_from.gd,
  ensure_path(uid://…)=res://moved_from.gd, get_resource_uid(res://moved_from.gd)=<id>,
  path_to_uid(res://moved_from.gd)=uid://dkcknnn0jeoy, load(res://moved_from.gd) -> null
cache present : ResourceLoader.load("uid://bxco4ao4o1moj") -> CompressedTexture2D, resource_path=res://icon.svg
                ResourceLoader.exists("uid://bxco4ao4o1moj")=true
cache DELETED : load("uid://bxco4ao4o1moj") -> null
                ERROR: Condition "local_path.is_empty()" is true. ... at: _load_start (resource_loader.cpp:752)
load("uid://<invalid>") -> null (ERROR: Invalid UID. + Resource file not found:)
```
**Law:** `uid://` is a first-class address for `ResourceLoader.load`/`exists`, but it resolves *through the uid cache*, so it dies with the cache. Stale uid→path mappings survive in memory and are returned even when the target file is gone.

## 2. E2 expected values (independent)

### 2.1 CacheMode identity lattice [observation, re-measured 2-3x]
```
REUSE (default & explicit) : same instance across loads (is_same=true)
IGNORE                     : distinct instance, still carries resource_path,
                             does NOT displace the cache entry (later REUSE == original)
REPLACE                    : SAME instance, refreshed IN PLACE from disk
IGNORE_DEEP / REPLACE_DEEP : top-level semantics identical to the plain pair
```
Source `rl472.cpp:800-807` returns the cached `Ref` immediately for `CACHE_MODE_REUSE`; the REPLACE branch (`:560-599`) re-reads into the existing object.

### 2.2 Post-mutation and deleted-file classes [observation, print-order-safe probe]
```
rewrite v1->v2 then REUSE     -> still v1 (STALE), same instance
then REPLACE                  -> v2, same instance; every alias of it now reads v2
rewrite again then REUSE      -> keeps the REPLACE'd value (still stale w.r.t. disk)
file DELETED under a cached entry:
  REUSE   -> stale object (v3), same instance
  REPLACE -> stale object (v3), same instance, cache NOT evicted
  IGNORE  -> null (+ engine ERROR block)
exists() after delete of a cached path -> true  (cache-contaminated)
exists() for a never-cached missing path -> false
```

### 2.3 `.import` remap [observation]
`--import` of a project with `icon.svg` writes `icon.svg.import` containing `uid="uid://bxco4ao4o1moj"`, `path="res://.godot/imported/icon.svg-<md5>.ctex"`. Then
```
get_resource_uid("res://icon.svg")  == text_to_id(import uid)  -> 4005794691762572005
load("res://icon.svg") -> CompressedTexture2D, resource_path="res://icon.svg"
load("uid://bxco4ao4o1moj") -> same object
get_resource_uid("res://.godot/imported/icon.svg-….ctex") -> -1   (the dest path has no uid)
get_dependencies("res://icon.svg") -> []
```
**Inference:** the `.import` sidecar's uid is loaded into the cache by the same editor pass that writes `uid_cache.bin`; the arm must therefore run after an import (or against an already-populated scratch) to be non-vacuous.

## 4. Defects and risks found

### D1 — `res_uid_s02.gd`: two arms FAILed as written — **FIXED by the owner at 22:37**
Both failing arms evaluated a getter **after** `CACHE_MODE_REPLACE` had refreshed the shared cached instance in place, so the stale assertion saw the refreshed value.
- `_arm_bust` (22:33 rev, line ~183): expects `_red(stale)=="v1"` but `stale` aliases the cached object, which the REPLACE on the next line mutates. Measured `FAIL … stale_reuse=v2 stale_same=true repl=v2 repl_same=true after_reuse=v2 ign_fresh=v2`.
- `_arm_xproc_read` (22:33 rev, line ~268): same class — `_red(first)` evaluated in the `tokens`/`if` lines, i.e. after the REPLACE. Measured `FAIL … fresh_first=v2 same_in_process=true rewrite_reuse=v1 repl=v2`.
Fix shape this seat verified on a scratch copy (snapshot the value before the REPLACE — the owner's 22:37 revision adds `alias_after_repl` and snapshots `first_red`/`stale_red`, same effect):
```
# _arm_bust: snapshot before the REPLACE
	var stale := ResourceLoader.load(p)
	var stale_same := _same(stale, a)
	var stale_red := _red(stale)                      # <-- add
	var repl := ResourceLoader.load(p, "", ResourceLoader.CACHE_MODE_REPLACE)
	var tokens := "stale_reuse=%s …" % [stale_red, _b(stale_same), …]   # was _red(stale)
	if stale_red != "v1" or not stale_same or …                          # was _red(stale)

# _arm_xproc_read: snapshot before the REPLACE
	var same := _same(first, again)
	var first_red := _red(first)                      # <-- add
	_write(p, _grad(2))
	…
	var tokens := "fresh_first=%s …" % [first_red, _b(same), stale_red, _red(repl)]  # was _red(first)
	if first_red != "v1" or not same or …                                       # was _red(first)
```
**Status: closed.** Re-measured on the 22:37 revision — `bust` and `xproc_read` both PASS (receipts in §3), 9/9 arms green.
Two side notes from this defect: (a) the arms must be invoked **sequentially** (`xproc_seed` in one process, then `xproc_read` in the next) — running them concurrently against one project corrupts `user://` state (I hit this with two parallel shell calls; the collision is visible in the shared `~/.local/share/godot/app_userdata/<name>/`); (b) the owner's fix removed the `classes` arm, so `res_uid_s02` no longer carries the missing/dir/empty/unknown-extension refusal row that the 22:33 revision had (that coverage now lives only in `res_uid_s03.gd` `refuse`, which passes).

### D2 — `res_uid_s01.gd`: the `createid` pin is project-name dependent (latent)
`cfp_res_matches_pinned` compares against `8476142776992359011`, which holds **only** under `config/name="MechanicOneShotTest"`. Measured:
```
name MechanicOneShotTest                        -> cfp_res=8476142776992359011 matches_pinned=true
name V1IsoS01                                   -> cfp_res=2522886401100167276 matches_pinned=false
name MechanicOneShotTest-20261018T223000000000Z -> cfp_res=5667572246736465524 matches_pinned=false
```
`run_battery.py:2048` rewrites the name to `MechanicOneShotTest-<utcstamp>`, and `run_battery.py:2109` matches the expected string by **plain substring**. The arm itself still PASSes today (the pin is only printed), but any future expected-string pin containing `cfp_res_matches_pinned=true` would fail on every run. Recommend dropping the pin from the PASS line or pinning only `stable=true`.
