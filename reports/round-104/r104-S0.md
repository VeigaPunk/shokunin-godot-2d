## 4. Probe design (the deliverable)

`gate_evasion_replay(rows)` + the module-level catalog `GATE_EVASION_SHAPES` (10 tuples),
`GATE_EVASION_CONTROLS` (4 cases), `GATE_EVASION_ACCOUNTED_CLASSES` (the 6 declared-silent classes with
their reasons), `GATE_EVASION_MIN_SHAPES = 8`.

- Each shape = (name, base case, ops, **exact expected flag-reason set**). `()` means declared
  accounted-silent, with the class named in `GATE_EVASION_ACCOUNTED_CLASSES`.
- `observed != expected` → `shape_class_drift`. So a *tightening* that closes an accounted class turns
  the run red until the row is re-declared (floor-not-ceiling, same as `RECEIPT_MULTI_PASS_GRAMMAR`).
- 4 unmutated base rows replay as discrimination controls; any flag → `control_not_silent`.
- `shape_catalog_floor` fires if fewer than 8 shapes could be built.
- Fail-closed: a base row present but not green → `probe_base_row_not_green`; present without stored
  output → `probe_base_row_no_output`; `!BANNER!` unresolvable → `probe_banner_absent`. A base case
  *absent* from the run is recorded in `skipped`, not flagged (family presence is already gated by
  `cases_integrity`; pre-family historical runs stay replayable).

Two design bugs the dry-run caught and fixed (worth carrying forward):

1. **F5 interaction.** Naming the tampered row `probe_evasion_<shape>` made the gate's own
   probe-artifact rule (`receipt_shape_flag` F5: a case not in `CASES_SIG_BY_CASE` returns `[]`) skip
   every shape — the probe read 0/10 flagged and looked "passing". Tampered rows now keep the **base
   case name**; only the `output` list differs. Evidence: `/var/tmp/r104-S0/patch-apply.log` run 1
   (7 flags, all `shape_class_drift observed=[]`) vs run 2 (0 flags).
2. **Skipped vs flagged for absent bases.** The two oldest runs (546 rows) predate the `export_launch`
   family, so a missing base would have hard-FAILed them on a schema change, not a gate change.

## 6. Routed to C2(a): the pass-line census tightening (observation, measured)

`/var/tmp/r104-S0/tighten.py` builds three gate variants differing **only** in the census predicate
inside `receipt_shape_flag`, replays the 10 shapes and pin-audits all 8 stored runs.

`tighten-matrix.json` (1918 B, sha256 `07d9bef9…`).

| variant | shapes flagged | new false positives over 8 runs |
|---|---|---|
| `line.startswith("PASS ")` (**landed**) | 4/10 | 0 (baseline) |
| `line.startswith("PASS")` | 5/10 (+s4d) | **0** |
| `line.lstrip().startswith("PASS")` | **6/10** (+s4a, s4d) | **0** |

The `lstrip` variant closes **both grammar-invisible shapes at zero added false positives** across all
8 runs. Extra shapes probed (`extended.log`, 1278 B, sha256 `ef379b2c…`) confirm the shape of the win
and its limits: `H2 bare PASS` → flagged by `prefix`+`stripped`; `H3/H4/H5` (tab/space-prefixed PASS
**inside a grammar row**) → flagged only by `stripped`, as `pass_line_grammar_mismatch`. Still silent
under all three variants: banner flooding in a DIAG window (H1), banner into a plain row (H7),
`SEQ_EXTRA` into a span row (H9) — the out-of-census class.

Label: **observation** for the counts (measured over 8 stored runs); **inference** that `lstrip` is the
right tightening — it is the minimal predicate change that closes the class, and the false-positive
cost is measured, not assumed. This seat did NOT edit the gate; the decision and the edit are C2's.
