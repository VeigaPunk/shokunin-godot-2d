### 1b. BLOCKER 1 — `res_uid_w07.gd` prints two PASS lines for 6 of 13 arms

**Observation** (`grep -n 'print(' corpus/fixtures/res_uid_w07.gd`): the fixture's helper is
`_p(line) → print("PASS res_uid_w07 " + line)`. Arm-by-arm PASS-line census: `census` 2,
`builtin` 2, `custfile` 2, `cache` 2, `cachebust` 1, `api2` 2, `stale` 1, `nouid` 1, `collision` 1,
`mkpng` 1, `importremap` 2, `persist_a` 1, `persist_b` 1 — **19 PASS lines over 13 arms**, so
registering the whole script as one CASES row is impossible under the gate.

Measured against the real gate (probe `r104-ver7-census.py` machinery, scratch module):

| registration attempt | observed flags |
|---|---|
| w07 as **one** row (4 PASS lines shown) | `unaccounted_pass_lines observed=4 declared=1` |
| w07 **per-arm** (2 PASS, no grammar) | `unaccounted_pass_lines observed=2 declared=1` **+** `anchor_line_multiplicity observed=0 declared=1` |
| w07 per-arm **+ `RECEIPT_MULTI_PASS_GRAMMAR`** entry, pin line unique | `[]` — **silent** ✔ |
| same, but the pin line appears twice | `pass_line_grammar_mismatch observed=3 declared=2` + `anchor_line_multiplicity observed=2 declared=1` |

**Observation (the sharp edge):** the grammar entry alone is **not sufficient**. The gate then runs
the anchor check unconditionally: `hits = sum(1 for anchor in anchors for line in output if anchor in line)`
must equal `RECEIPT_ANCHOR_MULTIPLICITY.get(case, 1)` — i.e. **the CASES 5th field must be a
substring that appears in the output exactly once**. A w07 pin written as the whole first PASS line
works only if that line is unique in the receipt; a pin written as the arm name (`census`) appears
twice (both lines carry `res_uid_w07 census`) and flags.

**Recommended registration for w07 (verified silent):** one CASES row per arm, 5th field = the
arm's **first** PASS line verbatim, plus a `RECEIPT_MULTI_PASS_GRAMMAR` entry for each 2-PASS arm
whose token-pair list is `[("res_uid_w07", "<arm>")] * n`. Example that measured `[]`:

```
("res_uid_w07_census", "res_uid_w07.gd", ["--arm=census"], 0,
 'PASS res_uid_w07 census methods=… consts=… invalid=-1 cache_modes=…')
RECEIPT_MULTI_PASS_GRAMMAR["res_uid_w07_census"] = (("res_uid_w07","census"), ("res_uid_w07","census"))
```

### 1c. BLOCKER 2 — `res_uid_s04.gd` prints `RES_UID_DIAG`, engaging the strictest window

**Observation** (`grep -n '_diag(' corpus/fixtures/res_uid_s04.gd`): 7 call sites emit
`RES_UID_DIAG <arm> <key>=<value>`. That matches `RECEIPT_DIAG_RE` (`^[A-Z][A-Z0-9_]*_DIAG\b`), so
the gate takes the **whole-receipt account** (`:1988`): every line must be banner, blank, `PASS `,
`*_DIAG`, `[ N% ]` progress, or ANSI-only — anything else flags `foreign_in_diag_window`.

| s04 shape | observed flags |
|---|---|
| DIAG lines + one PASS, all accounted | `[]` — silent ✔ |
| + a leaked `READ has=… path='res://alpha.gd' …` line | `foreign_in_diag_window: "READ has=…"` |

**Observation:** `res_uid_s04.gd` also defines a nested-reader helper whose body `print`s
`READ has=…` / `READ cache=…` (lines 253–254). Those run in a **nested Godot process** whose output
`_nested()` redirects to a log file (`exec > <log> 2>&1`), so they do **not** reach the battery
stdout — the DIAG window is clean as written. **Inference:** the registration is safe **only if**
the nested redirection holds; the `_diag("nested_" + log_name, …)` line is the audit trail proving
which nested command ran. If a future edit lets a nested line reach stdout, this row flags.
**Recommendation:** register s04 per-arm (1 PASS line each, no grammar entry needed); keep the
nested-redirect invariant documented at the registration site.
