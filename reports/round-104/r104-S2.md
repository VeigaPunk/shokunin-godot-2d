```

$ python3 -c "open('/tmp/p','wb').write(b'A'*1)"        → OSError(122, 'Disk quota exceeded')
```

Measured both states within the same session: `TMP now WRITABLE 4096` at 22:36, `tmp BLOCKED OSError(122, ...)` at 22:41. It flips.

**Consequence chain (OBSERVATION + INFERENCE).**
- `--export-release` must copy a **73.5 MB** export template (`~/.local/share/godot/export_templates/4.7.2.stable/linux_release.x86_64`, `ls -la` = `73519416` bytes).

- `--export-pack` needs no template, but the packer serializes `project.binary` through a **fixed `/tmp/tmpproject.binary-<rand>`** path (documented at `export_prod.gd:36-45`); under the blocked state that entry lands 0 bytes and the pack still exits 0.

## 7. GATE BLINDNESS — routed to C2 (G0/G2), with measurements

**This is the highest-value finding of the seat and it is not a defect in the adoptions; it is a defect the adoptions would *inherit*.**

Measured with the real gate (`/var/tmp/r104-S2/spoof2.py`, `spoof3.py`), simulating registration by adding the case to `CASES_SIG_BY_CASE`:

**7a. Structural verbs are gate-invisible for non-`*_DIAG` cases.**
`s01`'s receipt carries **51** diagnostic lines whose first tokens are `SPEC` (10), `ROW` (15), `ENTRY` (14), `CENSUS_SHA` (1), `MUT` (10), `KNOWN_ACCEPT` (1) — none matches `RECEIPT_DIAG_RE` (`^[A-Z][A-Z0-9_]*_DIAG\b`), so the DIAG-window closure at `:1986-1994` never engages. For a registered `export_prod_s01_pck`:

```
+ ROW forged=true      flags=[] INVISIBLE
+ MUT forged=accepted  flags=[] INVISIBLE
+ ENTRY res://forged.gd flags=[] INVISIBLE
+ CENSUS_SHA deadbeef  flags=[] INVISIBLE
+ PASS something_else  flags=[unaccounted_pass_lines]        <- caught
```

A forged `ROW R1 magic=GDPC` is therefore **byte-indistinguishable** from a real one at the gate layer. Only `PASS`-line counting and the single-anchor multiplicity check bind these rows.

**7b. Unrelated `ERROR:` / `SCRIPT ERROR:` / `Parse Error:` lines are gate-invisible.**
For both `export_prod_s01_pck` and `export_prod_s11_pack`:

```
injection                     shape_gate   classify_process
none (baseline)               invisible    PASS
ERROR: sneaky (unrelated)     invisible    FAIL
SCRIPT ERROR: fake            invisible    FAIL
Parse Error: fake             invisible    FAIL
```

The shape gate does not flag them; `classify_process` does. So the **layered defense holds** — the receipt-shape gate is not a substitute for the classifier and must not be treated as one. Worth stating explicitly in the gate's own documentation.

**7c. Adopt-side hygiene consequence.** Blind-verb line counts measured on the exact receipts behind the 12 tuples (count of lines whose first token is one of `SPEC|ROW|ENTRY|CENSUS_SHA|MUT|KNOWN_ACCEPT|EXPORT_PROD_S02|R101E8|S06`; **no adopted receipt contains any `*_DIAG` verb**, `grep -l "_DIAG" r1-*.out` → none):
