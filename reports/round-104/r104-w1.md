## R2 — text codec (observation, B3 source + B2 probe, mutually confirming)

`ru47.cpp:38-40`: `char_count = ('z' - 'a') = 25`; `base = char_count + ('9' - '0') = 34`.
`uuid_characters[]` = `a..y` (25) + `0..8` (9) = **34 entries**, `uuid_characters_element_count = 34`.
Source comment verbatim: *"These constants are off by 1, causing the 'z' and '9' characters never to be
used. This cannot be fixed without breaking compatibility; see GH-83843."*

- **Encode** (`id_to_text`): repeated `% 34` into the 34-char alphabet, reversed. `z` and `9` are never
  emitted. `max_uuid_number_length = 13` (comment: max `0x7FFFFFFFFFFFFFFF` → `uid://d4n4ub6itg400`).
- **Decode** (`text_to_id`): strict base-**34** accumulate; lowercase letter → `c-'a'`, digit →
  `c-'0'+25`; anything else → `INVALID_ID`. Result masked `& 0x7FFFFFFFFFFFFFFF`.
- **Encode alphabet is size 34, decode base is 34, but digit values start at 25 while there are only 25
  letters** ⇒ `z`(25) aliases `0`(25), and `9`(34) aliases `ba`(34).

Probe receipts (`probe.gd`, `probe2.gd`, `mk7.gd`, `mk9.gd`, exact stdout):
`ID2TXT 0:a 1:b ... 24:y 25:0 26:1 ... 33:8 34:ba 35:bb 36:bc ... 40:bg`
`ALPHA a=0 b=1 ... y=24 z=25 0=25 1=26 ... 8=33 9=34`
`CANON 1155 = uid://88`, `CANON 1156 = uid://baa`, `CANON 1336335 = uid://8888`,
`CANON 1336336 = uid://baaaa`, `RT 9223372036854775807 -> uid://d4n4ub6itg400 -> 9223372036854775807`.
Round-trip holds in both directions for every canonical value tried; non-canonical inputs still decode.

## R3 — collision classes (observation, B2 `mk4.gd` + B3 source)

`text_to_id` is **not injective**. Receipts:
`COLLIDE uid://z=25 vs uid://0=25`; `COLLIDE uid://9=34 vs uid://ba=34`;
`COLLIDE uid://=0 vs uid://a=0`; `COLLIDE uid://zy=874 vs uid://0y=874`; `tt(uid://zz)=875 tt(uid://00)=875`.
Also `tt(uid://Z)=-1 tt(uid://A)=-1` (uppercase rejected), `tt(uid:/b)=-1 tt(b)=-1` (prefix required),
`tt(uid://<invalid>)=-1` (explicit guard, `ru47.cpp:97`).

⇒ **Any E1 row asserting "uid text ↔ id is a bijection" is false.** Rows must use canonical
`id_to_text` output when they need a unique key.

## R5 — cache file format (observation, B3 + B2 `p3`, CORRECTS an earlier W1 misreading)

`get_cache_file()` = `ProjectSettings::get_project_data_path().path_join("uid_cache.bin")` → `res://.godot/uid_cache.bin`.
`encode_binary_cache` (B3): `put_u32(p_entries.size())`, then per entry `put_u64(id)`, `put_u32(len)`,
`put_data(utf8 path)`. **There is no version field.** My first hexdump read of `03000000...` as
"version 3" was WRONG — `03` is simply the entry count. Verified: `python3` parse of the 87-byte file
returns `first u32 = 3 (entry count, NOT a version)`, `parsed bytes 87 of 87 exact= True`, yielding
`(7519208775685400614, res://sub/other.gd)`, `(3198594885916028803, res://sub/plain.gd)`,
`(1425095418933108187, res://mk.gd)`.
`load_from_cache` sets `cache_initialized = true`; `update_cache()` **appends** `saved_to_cache == false`
entries in place and rewrites the leading count (`ru47.cpp:343-372`).

## R6 — cross-process persistence, and the trap that decides E4's arm design (observation)

Three separate processes on `/var/tmp/r104-W1/p3`:

- `mk5.gd`: `ResourceUID.add_id(900000001, "res://persist_a.gd")` → `added has=true`,
  `cache_exists=true`. Then `quit()`.
- `mk6.gd` (fresh process): `has(900000001)=false path=` + `ERROR: Unrecognized UID: "uid://t2qoyj".`
  ⇒ **an `add_id` in a non-editor process does NOT survive**, because nothing calls `update_cache()`
  in a headless run (grep for `update_cache|save_to_cache` over `main/main.cpp`,
  `core/io/resource_loader.cpp`, `editor/editor_file_system.cpp`, `editor/editor_node.cpp` at
  4.7-stable → 0 hits each; they are editor paths).
- After a real `godot --headless --path ... --import` run, `.godot/uid_cache.bin` exists and the
  `.uid` sidecars exist, and a following non-editor process reads them back:
  `text_to_id(uid://bltonjmja6adf)=3198594885916028803 has_id=true get_id_path=res://sub/plain.gd`,
  and `id_to_text(3198594885916028803)="uid://bltonjmja6adf" equals_uid_file=true`.

**The trap.** `ResourceLoader::get_resource_uid` (`rl47.cpp:1412-1426`):
```
if (!Engine::get_singleton()->is_editor_hint()) {
    return ResourceUID::get_singleton()->get_path_id(local_path);
}
```
i.e. **outside the editor the `.uid` sidecar is never consulted**; only the reverse cache built by
`load_from_cache` at `main.cpp:2282` (with `enable_reverse_cache()` at `main.cpp:2280` when
`!editor`) matters. Proof, `/var/tmp/r104-W1/p4` with a hand-written `custom.gd.uid` and NO cache:
`cache_exists=false`, `uid_file_text='uid://dq4custom9999'`, `text_to_id(custom uid)=8342308629444280958`,
`has_id=false`, `path_to_uid(custom.gd)=res://custom.gd`, `get_resource_uid(custom.gd)=-1`,
`uid_to_path(custom uid)=''`.
Same project `/var/tmp/r104-W1/p5` with a hand-written 31-byte `.godot/uid_cache.bin` listing that one
pair: `get_resource_uid(custom.gd)=8342308629444280958`, `path_to_uid(custom.gd)=uid://dq4custonbbba`,
`uid_to_path(dq4custom9999)='res://custom.gd'`, `has_id=true`.
⇒ E4's cross-process arm must establish the cache via an editor/`--import` child, exactly as E0-spec
already noted; a `.uid`-sidecar-only design will read `-1` and the row will be a false negative.

**Second trap.** `path_to_uid` does not echo the sidecar text. In p5 the sidecar text was
`uid://dq4custom9999` but `path_to_uid` returned `uid://dq4custonbbba` (the canonical re-encode of the
same id; `t2.gd` confirms `canonical=uid://dq4custonbbba`, `roundtrip_id=8342308629444280958`,
`alias_check: uid://dq4custonbbba=8342308629444280958`). Asserting `path_to_uid == sidecar_text` fails.

## R7 — loader/importer/scene names E1 (C1 coverage) will need (observation, B3)

- `ResourceFormatLoader::get_resource_uid` (`rl47.cpp:118-130`): if the loader has custom UID support
  it calls the `GDVIRTUAL _get_resource_uid`; otherwise it opens `p_path + ".uid"` and `text_to_id`s
  the first line. `has_custom_uid_support()` = `GDVIRTUAL_IS_OVERRIDDEN(_get_resource_uid)`.
- `ResourceLoader::should_create_uid_file` (`rl47.cpp:1428-1438`): false if `<path>.uid` exists; else
  true iff a recognizing loader lacks custom uid support.
- `ResourceFormatImporter::get_resource_uid` returns `pat.uid`, parsed from the `.import` `uid=` key
  via `text_to_id` (`ri47.cpp:108-109`); `has_custom_uid_support()` = `true`.
- `ResourceFormatImporterSaver::set_uid` writes `[remap] uid=` into `<path>.import` via
  `id_to_text` (`ri47.cpp:602-611`).
- `ResourceSaver::set_uid` / `ResourceFormatSaver::_set_uid` exist (`rs47.cpp:52-54, 157-165`).
- Text scene: `uid="uid://…"` on an `ext_resource` → if `has_id(uid)` the path is *replaced* by
  `get_id_path(uid)`; if that path's own `get_resource_uid` disagrees it `WARN_PRINT`s
  `" - ext_resource, invalid UID: " ... - using text path instead: ..."` (`rft47.cpp:491-505`).
  On write, a `uid=` present makes the saver emit the uid text **instead of** the path
  (`rft47.cpp:950-958`).
- Binary scene: `FORMAT_FLAG_UIDS` gate; `er.uid = f->get_64()`, resolved via `has_id`/`get_id_path`,
  warning `"In external resource #%d, invalid UID: '%s' - using text path instead: '%s'."`
  (`resource_format_binary.cpp:1015-1028`).
- `CacheMode` enum is 0..4 — `CACHE_MODE_IGNORE=0, REUSE=1, REPLACE=2, IGNORE_DEEP=3, REPLACE_DEEP=4`
  (`ResourceLoader.xml` constants block + `resource_loader.h:53-57, 115-119`).
  `get_resource_uid` has **no** `cache_mode` parameter; the default arg belongs to `load()`/`load_threaded_*`.

pin is deterministic only for a fixed literal path with stable content — do not expect case-variants to
alias.
