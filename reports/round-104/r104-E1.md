## Measured laws

### U1 [M] `ResourceUID` has a mixed int/String signature surface — `path_to_uid` returns a String
`census` PASS line, verbatim (`--arm=census`, cache regime; identical in both):
`uid_sigs=id_to_text(id:int)->String|text_to_id(text_id:String)->int|create_id()->int|create_id_for_path(path:String)->int|has_id(id:int)->bool|add_id(id:int,path:String)->Nil|set_id(id:int,path:String)->Nil|get_id_path(id:int)->String|remove_id(id:int)->Nil|uid_to_path(uid:String)->String|path_to_uid(path:String)->String|ensure_path(path_or_uid:String)->String`
`saver_sigs=set_uid(resource:String,uid:int)->int|get_resource_id_for_path(path:String,generate:bool)->int`
`loader_sigs=has_cached(path:String)->bool|get_cached_ref(path:String)->Object|exists(path:String,type_hint:String)->bool|get_resource_uid(path:String)->int` `uid_consts=INVALID_ID=-1`

**Inference:** r96's census pinned only the method *name* list. `path_to_uid` and `ensure_path` are
String-returning, so a caller doing `var id := ResourceUID.path_to_uid(p)` and comparing to an int
gets a String and will not compile / will misbehave. Confirmed against ClassDB and by a parse error
on my first probe (`argument 1 should be "int" but is "String"`).

### U2 [M] `path_to_uid` on an unknown path returns **the path itself**
`pathtouid`: `ptu_missing=res://zzz_absent_e1.gd ptu_missing_is_path=true ptu_noside=res://project.godot ptu_noside_is_path=true`.
Not `""`, not `"uid://<invalid>"` — a String sentinel indistinguishable from a real answer by prefix.

### U3 [M] A hand-written `<file>.uid` sidecar is NOT honoured at runtime
`pathtouid`: `sidecar_written=true sidecar_text=uid://bqk3m5n7qar1 sidecar_readback=uid://bqk3m5n7qar1 ptu_sidecar=res://e1_sidecar_probe.gd sidecar_honoured=false sidecar_get_resource_uid=-1`.
The sidecar is written, reads back correctly, and the engine still echoes the path and reports uid `-1`.
**Inference:** sidecars are an editor artifact; the runtime authority is `.godot/uid_cache.bin`.
**Related [M]:** the *editor* does honour a pre-existing sidecar verbatim — after `--editor --quit`,
`custom_probe.gd.uid` kept `uid://bqk3m5n7qar1` and `custom_two.gd.uid` kept `uid://c7km4741xarb1`
(byte-equal to `animation_property.gd.uid`), i.e. a collision was adopted, not repaired.

### U4 [M] `create_id_for_path` is a pure deterministic path-string hash and never registers
`createid`: `cfp_res=8476142776992359011 cfp_res_text=uid://ds053len3my3l cfp_res_matches_pinned=true stable=true cfp_res_registered=false cfp_res_path_to_uid=res://e1_selfreg_probe.gd cfp_user=4163091229239537790 cfp_user_matches_pinned=true stable=true user_registered=false`.
Identical in cache and cache-absent projects and across processes; `has_id` stays false; `add_id`/`remove_id`
do not perturb it. `create_id()` by contrast is random per process (`create_id_distinct=true create_id_unregistered=true`).

### U5 [M] …but the value DIFFERS for a path that has a `uid_cache.bin` entry
For `res://animation_property.gd` (editor-registered, sidecar `uid://c7km4741xarb1`):
- cache absent → `create_id_for_path` = `7040310260038884848` = `uid://c7km4741xarb1` (the sidecar's own value; U4's hash).
- cache present → `5833861704554277050` = `uid://cpd735r5jhbos`, stable across processes, and ≠ the registered uid.
- `remove_id(sid)` → back to `7040310260038884848`; `add_id(sid, path)` → back to `5833861704554277050`.
Deleting the sidecar file did **not** change it (still `5833861704554277050`), so the trigger is
`uid_cache.bin` presence, not the sidecar. Tried and refuted as the hash input: the absolute path,
`res://`-stripped, trailing `/`, trailing space, upper-case, `res:/…`, and the uid text
(all produced distinct values ≠ `5833861704554277050`).
**UNKNOWN:** the exact input mix for the cache-present value. The fixture pins only U4, on a path the
battery scratch never populates, so the pin is regime-independent. If the orchestrator wants a pinned
cache-mode row, the reproduction is: `--editor --quit` the scratch, then
`godot --headless --path <scratch> --script … -- --arm=<new>` reading
`create_id_for_path("res://animation_property.gd")` → `5833861704554277050`.

### U6 [M] text<->id round-trip and the malformed family
`roundtrip`: `tok=uid://bqk3m5n7qar1 tok_id=103876737118377468 tok_id_text=uid://bqk3m5n7qar1 roundtrip=true invalid_id=-1 id_to_text_-1=uid://<invalid> id_to_text_0=uid://a id_to_text_1=uid://b id_to_text_max=uid://d4n4ub6itg400 text_to_id_empty_payload=0 text_to_id_single=23 malformed=<empty>=-1,uid://=0,uid://x=23,not-a-uid=-1,bqk3m5n7qar1=-1,uid://@@@@=-1 sid_unregistered=true id_text_stable=true`.
Note `text_to_id("") = -1` but `text_to_id("uid://") = 0` (a valid, merely unregistered id) — the
empty *payload* is not the empty *string*. `uid://toolongtokenhere` (19 chars) silently truncates to
`uid://cawy6sacu7jna` rather than refusing. No diagnostic is emitted by `text_to_id` on malformed input.

### U7 [M] registration collision classes
`collide`: `add=res://e1_x1.gd dup_add_refused=true set_id_overrides=true two_ids_same_path=true a_path=res://e1_x3.gd b_path=res://e1_x3.gd ptu_x3=uid://t1fa remove_a_has=false remove_b_has=true ptu_x3_after_remove_a=res://e1_x3.gd add_invalid_has=true add_invalid_ptu=res://e1_x4.gd`.
- duplicate `add_id(id, other_path)` is **refused** (engine assert, first path kept);
- `set_id` overrides;
- two ids mapped to one path both resolve to that path, and `path_to_uid` then returns `uid://t1fa`
  (a bare, non-13-char token — a 5-char uid text);
- `add_id(-1, …)` is accepted: `has_id(-1)=true`, yet `get_id_path(-1)=""`.

### U8 [M] the refusal diagnostic text depends on `uid_cache.bin`, but `INVALID_ID` does not
`diag` (cache): `diag_queried_id=103876737118377468 diag_queried_tok=uid://bqk3m5n7qar1 invalid_id=-1 get_id_path_invalid_empty=true invalid_has_id=false has_cache=true`
`diag` (no cache): identical but `has_cache=false`.
Raw diagnostics: cache-absent → `ERROR: Invalid UID.` (`core/io/resource_uid.cpp:196`);
cache-present → `ERROR: Unrecognized UID: "uid://bqk3m5n7qar1".` (`…:214`) for a valid-but-unknown id.
`get_id_path(INVALID_ID)` emits `ERROR: Invalid UID.` in **both** regimes — hence the cache-independent
allowlist anchor chosen for the `diag` row.
**Seat defect found and fixed during this work:** my first `roundtrip`/`pathtouid` arms called
`get_id_path`/`uid_to_path` on unregistered ids, which under a cache-bearing project emit
`Unrecognized UID` and would have failed the row as an unrelated error. All such queries now live in
`diag` only.
