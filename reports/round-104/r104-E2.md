## 2. Measured laws (observation [M], this build)

| # | Law | Receipt evidence |
|---|-----|------------------|
| L1 | REUSE (default **and** explicit `CACHE_MODE_REUSE=1`) is identity-stable: same object, same instance id, `get_cached_ref` identical | `reuse` |
| L2 | IGNORE (`=0`) returns a fresh object that is **not** the cached one and does **not** displace the cache entry; it still carries `resource_path`; two IGNOREs are distinct from each other | `ignore` |
| L3 | REPLACE (`=2`) returns the **same** object and refreshes its content **in place** — every pre-existing alias of the cached object observes the new content | `replace` `bust` `resdir` |
| L4 | the `_DEEP` pair (`IGNORE_DEEP=3`, `REPLACE_DEEP=4`) reproduces the plain pair's top-level identity semantics on a cache hit | `deep` |
| L5 | after an external rewrite, default REUSE keeps serving the **stale** content; REPLACE is the only mode that re-reads | `bust` |
| L6 | after the file is **deleted** under a cached entry, REUSE **and** REPLACE both keep serving the stale cached object — REPLACE does **not** evict (it re-reads, fails, leaves the cache as it was); IGNORE returns null | `deleted` |
| L7 | `ResourceLoader.exists()` is **cache-contaminated**: true for a cached path whose file is gone, false for a never-cached non-existent path | `deleted` |
| L8 | the cache is per-process: a second process loading the same path parses the current bytes, and L5 then holds again inside it | `xproc_seed`→`xproc_read` |
| L9 | the identity lattice is path-scheme independent (`res://` and `user://` behave identically) | `resdir` |

**L3/L6 are new or corrective against the landed law.** `scene_io_lattice.gd` L9
(lines 51–52) states only "REPLACE reloads the on-disk content into the SAME cached object
(identity-stable refresh); CACHE_MODE_IGNORE returns a fresh uncached object that still
carries resource_path; default REUSE returns stale content after an external write". It does
**not** state the in-place alias refresh (L3), the deleted-file class (L6), the
cache-contaminated `exists()` (L7), or the `_DEEP` pair (L4) — the battery exercises
neither `IGNORE_DEEP` nor `REPLACE_DEEP` anywhere (`grep -c DEEP corpus/fixtures/run_battery.py`
counts only the unrelated `CACHE_MODE_*_DEEP` absence; `scene_io_lattice.gd` uses only
IGNORE/REUSE/REPLACE).

## 4. Battery integration (mutation content — orchestrator applies)

The `deleted` arm intentionally triggers a load failure; the engine writes an ERROR block to
**stderr**, which the battery merges into `output` (line ~2242 `output = proc_stdout +
proc_stderr`), and `classify_process` (line 2093) rejects any ERROR line not in the row's
`expected_errors` allowlist. Verbatim merged tail of the arm:

```
ERROR: Cannot open file 'user://res_uid_s02/v1.tres'.
   at: load (scene/resources/resource_format_text.cpp:1442)
ERROR: Failed loading resource: user://res_uid_s02/v1.tres.
   at: _load (core/io/resource_loader.cpp:317)
ERROR: Error loading resource: 'user://res_uid_s02/v1.tres'.
   at: load (core/core_bind.cpp:82)
PASS res_uid_s02 deleted removed=true reuse_stale=v3 reuse_same=true ...
```

Exactly 3 distinct ERROR lines, each appearing twice (one block per failing load, lines 229
and 230). **Deliberately not allowlisted with a `,` prefix**: the shipped prefix clause is
`stripped.startswith(allowed) and stripped.count("ERROR:") == 1`, and each line already ends
in `.` — a trailing-comma entry can never match it, so exact-line entries are required.

`reports/round-104/mutations/r104-E2-battery-registration.md` carries the CASES rows, the
`expected_errors` entries, and the r103 gate-table rows that must grow with them.

## 6. Traps found (inference labelled; these cost real time)

- **A script error before `quit()` HANGS the process.** A null deref inside `_init` of a
  `--script` SceneTree aborts the callback and never reaches `quit(0)`; the process stays
  alive until killed. My first probe hit this and was killed at the 60 s bound (`rc=137`);
  a later `resdir` run hit it again and only looked like a pass because the second attempt
  no longer dereferenced null. All receipt accessors in the fixture are therefore null-safe
  (`_path_of`, `_iid_stable`). [observation]
- **Snapshot before REPLACE.** Because REPLACE refreshes in place (L3), any receipt token
  computed *after* the REPLACE call reports the refreshed value. My first `bust` receipt
  claimed `stale_reuse=v2`; the correct pre-REPLACE reading is `v1`. `bust`, `replace`,
  `resdir` and `xproc_read` now snapshot before the call. [observation]
- **`res://` subdirectory creation is not same-frame visible.** `make_dir_recursive_absolute`
  under `res://` followed by a `FileAccess` write and an immediate `load` of the nested path
  returned null on the first run and succeeded on the second. The `res://` leg now writes to
  the project root. [observation; root cause unknown]
