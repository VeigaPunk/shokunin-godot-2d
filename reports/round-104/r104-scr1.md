## Headline findings (each with its evidence file)

1. **`uid_cache.bin` is the runtime authority, not the `.uid` sidecar.** With all sidecars present and
   `.godot/uid_cache.bin` deleted, a plain `--script` process resolves nothing (`has=false path=` for
   both declared ids). `--import` rebuilds it and prints
   `WARNING: Missing .uid file for path "res://sub/deep.gd". The file was re-created from cache.`
   → `evidence/A-no-cachebin.txt`, `evidence/A2-cachebin-regen.txt`.

2. **The cache header u32 is a row COUNT, not a version.** Format `u32 count` + `count × (u64 id | u32
   path_len | path)`; parse self-checks to `eof_remaining=0`. Byte arithmetic: 153 B = 4 + 12·6 + 77 for
   6 rows; 70 B = 4 + 12·2 + 42 for 2 rows. Same project yielded count 5, 6 and 9 across rebuilds.
   → `evidence/s3-cachebin.txt`, `evidence/E3-oneasset-hex.txt`, `evidence/D2-cachebin-stable.txt`.
   **Contradiction flagged, not propagated:** `corpus/fixtures/res_uid_s04.gd:11` calls the header
   `u32 version(=1)` and its receipt pins `cache_version=1`. That label is falsified by the three sizes.

3. **The `uid://` body is base 34, big-endian, 13 digits max** (`34^12 < 2^63 < 34^13`). Alphabet
   `a`..`y`→0..24, `z`→25, `0`..`9`→25..34 — so `z` and `0` **collide at 25** (`uid://z` → 25 →
   `uid://0`; `uid://zz` → 875 → `uid://00`). Verified by arithmetic on measured values: `ba`=34,
   `bb`=35, `a0`=25, `0a`=850, `10`=909, `100`=30931, `vvv`=25011 — all match base-34 decoding.
   Consequence: `text_to_id → id_to_text` is **lossy**; only `id → text → id` is stable. Parsing is
   case-sensitive and requires lowercase `uid://`; `uid://` alone parses to 0. Quirk: digit `9` = 34 =
   the base, so a single digit can exceed `[0, base)`. → `evidence/s9-alphabet.txt`, `s2-canon.txt`.

4. **Collision class: one record survives, deterministically, plus a WARNING.**
   `WARNING: UID duplicate detected between res://beta.gd and res://alpha.gd.`; survivor was `beta.gd`
   in three fresh projects including one where `beta` was written *first*, so it is not scan order. A
   competing **inline `uid=` in a `.tscn` wins outright** over a `.gd.uid` companion; the losing resource
   stays reachable by path but any scene consuming it then fails with
   `Parse Error: [ext_resource] referenced non-existent resource`. Collisions are therefore not
   fail-safe. → `evidence/E-coll-warn.txt`, `E-coll-order.txt`, `E-coll-rows.txt`, `s4-loadbyuid.txt`.

5. **`CacheMode` real enum**: `IGNORE=0 REUSE=1 REPLACE=2 IGNORE_DEEP=3 REPLACE_DEEP=4`; there is **no**
   `CACHE_MODE_REUSE_DEEP`. Measured identity against a `.tres` rewritten on disk mid-process: `REUSE`
   never re-reads (stale value, same RID); `IGNORE` re-reads but leaves the cache untouched (a later
   `REUSE` still returns the *original* RID); `REPLACE` re-reads and installs the new instance (a later
   `REUSE` returns the *REPLACE* RID). `*_DEEP` behaved like its shallow twin at top level for a leaf
   `.tres` — deep recursion unexercised. → `evidence/s8-modes.txt`, `s3-bust.txt`, `s2-cache.txt`.

6. **`.import` remap + refusal classes.** `load(source)` returns the imported class with
   `resource_path` = the *source* path; the artifact path also loads directly. A remap-miss (sidecar
   present, artifact deleted) fails source and artifact alike while `ResourceLoader.exists(source)` still
   returns **true** — an exists/load disagreement. Non-resource and missing-script loads return null with
   engine ERRORs, never throws. `uid://` works in `ResourceLoader` *and* in `FileAccess.file_exists`, but
   `FileAccess.get_file_as_string("uid://…")` mangles bytes as UTF-8 (`efbfbd` + PNG magic) while
   `FileAccess.open(uid, READ)` reports the true 69 B length.
   → `evidence/s4-remapmiss.txt`, `C-remapmiss.txt`, `s2-remap.txt`, `s5-fa.txt`.

7. **Malformed `.uid` is non-fatal but `uid://` alone registers id 0** (a legal id) for its file, with no
   warning; `not-a-uid` and empty files parse to -1 and are skipped while `load(path)` still succeeds.
   → `evidence/s5-malformed.txt`.

8. **Cross-process persistence is stable and idempotent** (3 fresh processes, byte-identical mapping).
   `create_id_for_path` is deterministic and pure (does not register); `create_id` is not.
   `path_to_uid` / `ensure_path` **echo their argument back** for unregistered paths, so they cannot be
   used as a registration test — `has_id()` is the only reliable predicate.
   → `evidence/D-persist-3x.txt`, `s7-cidf.txt`.

## Harness note worth routing to C2

on the first invocation and rc=1 on the rerun, printing only `SCRIPT ERROR: Parse Error …` +
`ERROR: Failed to load script …`. A fixture whose script does not parse can therefore emit no `PASS` line
yet leave a clean-looking exit status. Both byte sets are archived (`evidence/dump.txt` vs the rerun).
