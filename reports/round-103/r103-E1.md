Observed laws:

* **L1 (container/extension).** The *preset* path decides the container from the
  preset's `binary_format/embed_pck` option and **ignores the output extension**
  (#5: a full embedded binary named `relpack.pck`). The *CLI pack* path is
  project-data only and the **extension selects the format** (`savepack` for
  `.pck`, `savezip` for `.zip` — the two stage markers appear in the nested logs
  `/var/tmp/r103c-E1/m1/logs/{cli_pck,cli_zip}.log`).
* **L2 (payload identity).** `sha256(cli.pck) = sha256(stock.pck) =
  dcb489a5b3e5f602c78d22fa910530986e3ddfc08967101235071b6e3c218eed` — the `.pck`
  emitted by `--export-pack` through the `Embed` preset (embed_pck=**true**) is
  byte-identical to the sidecar written by `--export-release` through the
  `Stock` preset (embed_pck=**false**). The container option never reaches the
  project data.
* **L3 (embedded payload = standalone payload, framing differs).** Extracting
  the embedded payload from #1 by its trailer (`<u64 payload_size><u32 'GDPC'>`
  at EOF; measured size field 1972) and parsing both with
  `reports/round-103/mutations/r103-E3_packparse.py`:
  * entry tables identical — 7 names in the same order in both (`.godot/exported/133200997/export-3070c538c03ee49b7677ff960a3f5195-main.scn`,
    `.godot/global_script_class_cache.cfg`, `.godot/uid_cache.bin`,
    `main.gd.remap`, `main.gdc`, `main.tscn.remap`, `project.binary`),
  * every entry's relative offset and size equal, every stored directory MD5
    equal, and the whole data region byte-equal at an 8-byte shift
    (`emb[104:1496] == cli[112:1504]`),
  * framing differs: `file_base` 104 vs 112, `dir_off` 1496 vs 1504, total
    1972 (payload) + 4 B pad + 12 B trailer vs 1976 standalone.
* **L4 (non-resource assets).** `extra.txt` is absent from every pack
  (`nondata=absent`) while `project.binary` is present — `all_resources` does
  not lift plain data files; the pack is 1 file, never a binary, on the CLI path.

Inference (not directly measured): L2/L3 generalize to any preset pair, as the
option is read only by the platform export wrapper; L4 is a filter law, not a
format law. Unknown: behaviour of `--export-patch`/`--patches` (r103 CLI help
lists them; out of scope here) and of `--export-pack` to an extension-less path.

Design notes (house conventions, cf. `export_launch.gd` / `export_div_s02.gd`):
every arm re-stages its own child project and re-exports its own artifacts
(no cross-row cache, each row passes standalone); scratch root =
`$EXPORT_DIV_ROOT` → `$EXPORT_LAUNCH_ROOT` → `<engine user data dir>/div_s01` →
`$TMPDIR/div_s01` → `/tmp/div_s01`, each gated by a 4096-B write+readback probe;
nested exports run under `unshare -m --map-root-user` with a private tmpfs `/tmp`
(the r101 fixed-`/tmp/tmpproject.binary-<rand>` EDQUOT hazard) *unless* the root
is itself under `/tmp` (a 64 MB tmpfs cannot hold the ~73 MB artifact); nested
engine output is redirected to `<root>/div_s01/<arm>/logs/*.log` and PASS lines
carry only derived booleans, hex magics and counts — host paths appear only in
`EXPORT_DIV_DIAG` lines; the fixture prints no `ERROR:`/`SCRIPT ERROR:`/`Parse Error:`
line (the battery classifier rejects any unrelated `ERROR:` line).
