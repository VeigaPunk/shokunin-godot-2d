## 2. G0 SPEC — gate predicate (stored records only)

Input contract: run_battery.py payload (`results` list of row records, fields at
run_battery.py:2359-2370: case/script/flags/command/xdg_data_home/expected_exit/actual_exit/
signature/verdict/error/output, + expected_errors/required_stderr/export_artifact).

Flag classes (fail-closed marked FC):
* `schema:{case,script,verdict,signature,output,record}` — missing/ill-typed fields on
  process-bearing rows (a row with `command` set). Non-process probe rows are audited
  structurally only (16/554 live rows carry no command, no output — by design). FC.
* `output_unreplayable` — process-bearing row with `output` absent/null. FC.
* `exit_or_error_state` — `verdict=="PASS"` while `actual_exit != expected_exit` or `error` set. FC.
* `signature_absent` — no signature alternative is contained in the merged output
  (skipped for synthetic `EXPORT PASS …` evidence rows, which are artifact-bound instead).
* `artifact_binding` — `executable_bytes=<n>` in the signature vs `export_artifact.artifact_bytes`. FC.
* `banner_shape` — engine banner not exactly once at line 0 when present.
* `foreign_line` — a non-PASS output line matched by neither the row script's literal census
  nor the engine-diag regex (W2 account, §3).
* `unaccounted_pass_line` — a PASS-shaped line not covered by (a) the matched signature
  line as a prefix (classifier semantics: `signature in output`, both directions of the
  containment), (b) the w4 multi-PASS allowlist lines, or (c) the row script's own
  `PASS`-literal print sites.
* `pass_multiplicity` — `#PASS lines > max(#signature PASS lines, allowlist count, #script PASS sites)`.

Signature semantics handled: string OR list/tuple of alternatives (bimodal rows,
e.g. `input_lattice_pre_frame` CASES row at run_battery.py:338 stores two variants; the
auditor requires ≥1 alternative contained and uses the matched alternative's PASS lines).
