## Measured laws

- LAW-1 [obs] Multi-preset sequential `--export-pack` (A then B, one session, one project
  dir): each pack carries exactly its own non-resource include-filter beacon — 8 entries
  each, 2000 B (PckOnly, `tag_pck_only.txt`) / 2004 B (Embed, `tag_embed_only.txt`); the
  4-byte delta is the directory name padding (16 vs 18+NUL → 16/20 bytes). No foreign
  entry name and no foreign beacon bytes in either pack.
- LAW-2 [obs] Order-invariance: exporting B then A in the same project dir reproduces the
  A→B packs byte-for-byte (`ref_a_match=true ref_b_match=true`; python sha equality same),
  and same-preset repeat is byte-identical (`sha_match=true`). Holds across fixture
  invocations and across battery run-1/run-2 shape (cycle B == cycle A incl. digests).
- LAW-3 [obs] PCK v2 directory `offset` fields are relative to a data base, not the file:
  base = 112 for this standalone pack (beacon abs 944 − entry off 832; same base for all
  six artifacts). The directory ends exactly at EOF (dir_off 1472 + 528 = 2000) — no
  trailing padding. The fixture therefore anchors beacon content by absolute search + the
  directory's own md5, not by `offset`.
- LAW-4 [obs] Pack sha256 is generation-variable in exactly one entry: the exported scene
  cache `.godot/exported/…-main.scn` (667 B) carries a random u32 `node_ids` value —
  measured differing bytes = offsets 491..494 only — three fresh generations gave
  `9d013c3b`, `18d85113`, and a third value (pack sha prefixes `e37b4753…`, `0e4d14d2…`,
  `f3e820c1…`), all other 7 entries md5-identical. Digest is stable
  while that cache file persists (hence LAW-2), and different across fresh project
  generations — **do not pin pack sha256 in expected lines** (hence the unpinned trailing
  digest fields; mut3/ver seats should compare hashes only within one project dir).
- LAW-5 [inference, from the receipts] Batch order matters only for `order` (adjacent-row
  dependency on `seq`); `seq` and `repeat` are order-independent among themselves.
