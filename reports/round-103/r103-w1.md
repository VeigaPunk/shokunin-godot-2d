Findings, each tied to a row of the table:

- **F1 template-gate asymmetry (rc-level, load-bearing).** Same project, same preset, same redirect:
  `--export-pack` → rc 0, artifact 1424 B; `--export-release` → rc 1,
  `ERROR: Cannot export project with preset "P0" due to configuration errors:` +
  `No export template found at the expected path:` (`…/emptyhome/.local/share/godot/export_templates/4.7.2.stable/linux_debug.x86_64`
  and `…linux_release.x86_64`) + `ERROR: Project export for preset "P0" failed.`. The pack-only path
  does not consult templates; the preset path requires both binaries.
- **F2 pack-only ≡ preset sidecar (content-level, with a caveat).** a1 == a5 == a6 byte-identical
  (three separate invocations, incl. the template-less one and the `embed_pck=true` preset), and in
  G2 c1 == c2.pck for the filtered preset (588 B, same 4-name set, `res/sub/note.txt` present in
  both). **Caveat:** b1.pck (G2) differs from a1.pck in exactly **20 bytes** — offsets
  `535,536,537,538` (a 4-byte field inside the converted scene blob) + `1156..1171` (that entry's
  16-byte md5 in the directory). And pack-only-vs-pack-only diverges identically: a1 vs rep1 differs
  in the *same* 20 offsets. So a raw "preset == pack-only sha" pin is **flaky by construction**;
  the sound rule is in §6.
- **F3 embedded pack is a shifted image, not a copy.** G2: b4 = template(73,519,416) + 1424-B image
  + 8-byte trailer (73,519,416 + 1432 = 73,520,848 = measured size). Last 4 bytes are the literal
  `GDPC`; the preceding u64 = **1420 = standalone size − 4** (G1: 1484 = 1488 − 4); and
  `pack_start = file_size − u64 − 12 = 73,519,416` = exactly the template length in both
  generations. The embedded image's header is 8 bytes shorter than a standalone pack's
  (`file_base` 104 vs 112, `dir_off` 1112 vs 1120 — G1 measurement; G2 trailer arithmetic agrees),
  so its data region differs from a standalone pack in **1118 bytes** (G1 byte-diff) — an embedded
  pack is *not* the standalone pack with a trailer bolted on.
- **F4 writer switch by extension.** `--export-pack P0 out/a2.zip` → rc 0, ZIP magic `PK\x03\x04`,
  same 5 entry names as the PCK, different container. Unsupported extension → rc 1 with
  `Export path "…/a3.bin" doesn't end with a supported extension.` — a *pre-write* refusal (no file
  created).
- **F5 preset resolution is shared and pre-write.** Unknown preset name fails identically in both
  modes (a4, b2) with `Invalid export preset name: NoSuchPreset.` + the detected-preset list, rc 1,
  no artifact.
- **F6 embedded flag is honored only by the preset path.** Preset `P1Emb` sets
  `binary_format/embed_pck=true`: `--export-release` produces a single 73,520,848 B ELF (no sidecar
  pck, `last4 == GDPC`), while `--export-pack "P1Emb"` produces the same bare 1424 B PCK as `P0`
  (`embed_pck` is meaningless for pack-only). Feed this as a *positive* divergence arm: one preset,
  two modes, different artifact shapes; and as an *equality* arm: pack-only output is invariant to
  the embed flag.

## 5. Vacuity warnings derived from the tokens (depth)

- **V1 `GDPC` is not evidence of a pack.** The literal occurs 5× inside the release template and 6×
  inside `/usr/bin/godot` (first at offset 43,122,210 in the template) — plain `find(b"GDPC")`/
  `grep GDPC` on an exported ELF (or on a *packed scene blob*) can match engine literals. Sound pins:
  `data[-4:] == b"GDPC"` plus trailer arithmetic `pack_start = len(data) − u64(len−12) − 12`, or a
  directory parse to exact EOF (`dir_end == file_size`, true for every pack measured here).
- **V2 "file exists, exit 0" is already known vacuous** (r101: 0-byte zip at rc 0; unrunnable pack at
  rc 0). New to this seat: the *same* rc-0 class also covers the template-less pack-only run (F1) —
  an E1 row that hides templates and only checks rc 0 would pass for the wrong reason unless it also
  censuses the artifact.
- **V3 census must compare *sets*, not ordered lists.** Directory order was
  `scn, class_cache, uid_cache, remap, project.binary` for one preset and
  `class_cache, uid_cache, project.binary, note.txt` for another — not alphabetical, not source order.
- **V4 `PCKPacker` is a registered class** (strings), so a fixture may write a reference PCK from
  GDScript without an export at all — an E4/E1 ground-truth cross-check that does not depend on the
  export path staying stable.

**One latent-flake finding (routed to E1, not fixed here — the fixture is not this seat's file).**
`s01`'s `ident` arm pins `sha256_equal` between two *independently produced* artifacts, which is the
one pin the r101 lesson already calls unstable (`r101-export-capability.md:49-51`) and which this
seat reproduced in a different project: in G2, one project + one preset produced **three distinct
pack images** over 14 invocations (a1 `9bc357e4…`, b1 `14673bbe…`, rep1-3/relr1-2 `1d639647…`), and
every pairwise difference is exactly two spans — a 4-byte field inside the converted `.scn` blob
(file offset 535-538 = `file_base` 112 + blob offset 423) and that entry's 16-byte md5 in the
directory (offset 1156-1171, located by walking the directory independently of the diff: entry 0
`.godot/exported/…-main.scn`, path_len 76 incl. NUL, md5_off=1156). Masking exactly those two spans
makes a1, b1, rep1, rep2 identical (`f1d1bbf284a3bcf3`). So the structure of the identity law is
sound, but the *pin form* is exposed: recommend E1 either canonicalizes before comparing (mask the
scn entry's 4-byte field + its dir md5) or reuses the `entries_equal`/`entry_bytes_equal`/
`data_equal` form that its own `embed` arm already uses. Observed frequency today: ident 4/4 PASS,
embed 2/2 PASS — the exposure is latent, not a current red. s03/s05 were not run by this seat
(out of scope); the same 20-byte class applies to any of their arms that compares two
independently produced artifacts by whole-file sha.
