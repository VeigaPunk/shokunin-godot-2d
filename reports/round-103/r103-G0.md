## 2. Account model (normative)

Per row, with `out = record["output"]` and the pin resolved from `record["signature"]`:

- Pin kinds: `str` → its `splitlines()` (1 line = line pin, ≥2 lines = **span pin**);
  `list[str]` → **any-payload envelope** (harness semantics: PASS iff ANY payload matches).
- **PASS-line account** (feeds F1), priority order:
  1. Case has a w4 allowlist entry → that entry is the account: exact line bytes, exact multiplicity.
  2. Else: every non-empty pin line `p` accounts an output PASS-line `l` iff `p in l` (substring —
     mirrors `classify_process`'s `signature in output`), multiplicity = per-line count in the pin
     (str) or per-line max across payloads (envelope).
  3. **Self-report credit**: if the pin matched only non-PASS output lines (a negative assertion, e.g.
     `save_process_missing` pins an `ERROR: SAVE PROCESS EXPECTED NEGATIVE: …` line), the row may present
     exactly ONE PASS self-report line, accounted once. If the pin matched inside a PASS line itself,
     credit is 0 (so an appended forged PASS line on fragment-pin rows still flags — AD11).
- **Pin-presence** (feeds F0) for `verdict == "PASS"` and non-harness rows: `"\n".join(pin) in
  "\n".join(out)"` (str pins), or ANY payload present (envelope pins).
- **Harness-verdict rows** (normative exemption): `script` starts with `"__"` (observed:
  `__godot_export__`, `__godot_export_missing__`, `__save_process_*`). Their `signature` is a synthesized
  evidence token (`run_battery.py:1940-1945`), never stdout content → exempt from pin-presence only;
  F1/F2 still apply (AD10).

## 3. Flag conditions (normative) and fail-closed

Gate verdict: PASS iff ZERO non-advisory flags. `advisory` = the record's own `verdict != "PASS"`
(a FAIL row's claim is already false; its shape findings are reported but do not gate — see §5.4).

- **F1 — unaccounted PASS-line**: a `PASS_RE`-matching line in `out` that cannot be debited against the
  row's account (§2) by exact multiplicity. Report: `case`, `out[i]`, line prefix.
- **F2 — foreign content inside a pinned span**: pin is a `str` with ≥2 lines; the pin's first and last
  lines both occur in `out` with `idx(last) > idx(first)`; and the interior `out[s:e+1]` is not exactly
  the pin. Foreign lines = interior lines (by `difflib.SequenceMatcher` opcodes vs the pin) that are
  neither blank (`SPAN_LEGAL_RE = ^\s*$`) nor a positional span member. This is the r101-crit2 SF1
  surface (mut09 A1 shape, AD1/AD2). Blank-only lenience is deliberate: text-mode trailing-whitespace
  drift is non-material and the byte-level closure is fixture-side (G-B).
- **F0 — fail-closed** (each item independently fails the row):
  1. `case` missing / not a non-empty str.
  2. `verdict` key missing.
  3. `output is None` and the row is not in the §1 exemption set.
  4. `output` present but not a `list[str]`.
  5. `signature` present but not `str`/`list[str]` (mixed envelope payload types are malformed).
  6. No `signature` at all (or `None`) while `out` contains PASS-lines.
  7. `verdict == "PASS"`, non-harness row, pin present but absent from stored stdout (**evidence-absent**).

## 4. DIAG_RE — the diag-account regex (final proposal; W2 landed nothing)

(a) as the family census for the gate's evidence table, and (b) in the advisory whole-output variant
(§7 extension). It is deliberately NOT applied to span interiors (a forged banner/diag line injected
mid-span must remain foreign — AD2); span interiors use blank-only `SPAN_LEGAL_RE`.

## 7. Ceilings / residuals (disclosed, not hidden)

1. **Out-of-span non-PASS foreign content** (mut05 s1a/s1b/s2a/s2b; r101-crit2 SF2): not flagged by the
   two normative conditions. Extension (non-normative recipe for G1): per-row per-family multiplicity
   envelope derived from a frozen reference record set (w4-style census), flag family-count increases.
   This is the only shape family the normative gate knowingly leaves open at the meta level.
2. **Self-report / prefix-pin substitution**: a row whose PASS line is only partly pinned (135 single-line
   pins are strict prefixes/fragments; 1 self-report row shape) cannot distinguish a substituted tail
   without a bytes binding — fixture-side closure (mut09 G-B: `run_log_sha256` + line count).
3. **Post-span epilogue** (SF2) and **out-of-span banner replay**: same class as (1).
4. **Cross-run byte drift**: 28 single-PASS rows drift between the two r102 runs (timing/pid tokens).
   The gate's baseline is per-record shape (pin + allowlist), never cross-run byte identity.
5. **Counting convention**: r102 LOG says 553 PASS; raw verdicts.json shows 554 PASS rows in both runs
   (w4 delta of 1) — unresolved by design, recorded here so the gate's row count (554) is not mistaken
   for a defect.
6. `SPAN_LEGAL_RE` blank-only: an attacker who inserts only blank lines inside a span is not flagged;
   judged immaterial (no content change) and disclosed.
