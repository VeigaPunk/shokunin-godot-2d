## 4. Boundary decisions and the measurement that forced each

* **The accounting/span clauses bind PASS receipts only.** Measured (this is the fix that came out of
  cross-run diligence): the older run `20261018T202131127599Z` carries three real **FAIL** rows
  (`input_lattice_census`, `input_lattice_dev_joy`, `input89_edges_axisdev` — the intermittent
  joystick/device census: stored pin says `joys=0` / older tail, the fixture emitted `joys=1` / other
  tail, so the pin is in neither containment direction). A first cut of the predicate flagged those
  three rows as `pass_line` defects — double-reporting a failure the battery already reports. The clause
  now returns early for non-PASS records; shape preconditions and `replay` still cover them (and `replay`
  is *silent* on them because stored FAIL == recomputed FAIL, which is the correct reading). After the
  fix all three stored runs replay with zero flags.
* **Export rows cannot use the generic replay clause.** Measured: of 538 signature-bearing records in the
  target run the generic clause disagrees with the stored verdict for exactly one — `export_readiness`,
  whose stored pin is *rewritten* from the artifact at the executor site (`evidence = f"EXPORT PASS
  preset=Linux/X11 executable_bytes={size}"`) while its PASS is decided by the export path
  (`[ DONE ]` + `savepack` + artifact exists, `run_battery.py:1940-1949`). Hence the artifact clause
  instead: pin `executable_bytes=73703800` == `export_artifact.artifact_bytes` `73703800`,
  `artifact_sha256` 64-hex, 3 products, `artifacts_deleted=true` (all observed in the stored record).
* **PASS-line accounting is bidirectional containment** (pin ⊂ line matches the classifier's own
  `signature in output` semantics; line ⊂ pin covers the shared sub-receipt families — the r100b/r101 seq
  rows echo the r100_gui cells, export_prod/export_launch rows echo their sibling receipts). Measured
  residue on the target run: exactly **one** line, `PASS save_process missing=true pid=3166974 path=...`
  in `save_process_missing` (expected-negative row whose registered pin is the ERROR string). That line is
  the entire allowlist; the pattern is anchored: `^PASS save_process missing=true pid=[0-9]+ path=\S+$`.
* **In-span non-PASS injection is decided only where a pin spans lines.** 3 rows carry multi-line pins
  (`ei_bound_refusal`, `r101_seqfull_clean`, `r101_seqfull_noclean`) and all 3 measured as contiguous
  windows on the green run. For single-line pins the span clause is silent by construction, so r102-mut9's
  G-A/G-B (pin a span, or an output-bytes binding) remains a **row-design** obligation — it is *not*
  closed by this gate, and the r103 `export_div_*` / `export_launch_*` rows should pin spans or byte
  counts for the gate to bite. (Inference, stated for the C1 rows.)
* **No classifier change:** `classify_process` / `classify_audio_process` / `classify_streams` untouched
  (pure insertion +165/-0); the predicate never re-runs a fixture and never reads the filesystem.
