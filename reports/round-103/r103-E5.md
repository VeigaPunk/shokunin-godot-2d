## 4. What was measured

**[obs]** The export run *bootstraps editor settings*: a bare `--export-pack` under a fresh
`XDG_CONFIG_HOME` creates `$XDG_CONFIG_HOME/godot/editor_settings-<major>.<minor>.tres`
(`editor_settings-4.7.tres`, 17728 B, sha `2dccc7bf…`) plus `feature_profiles/`,
`script_templates/`, `text_editor_themes/`. `default_store_bytes=17728` was identical under three
independent config roots (`root`, `rootZ`, `mutcheck`) ⇒ the default store is root-independent but
host-config-coupled.

**[obs]** Editor-settings **contents do not reach the pack**: after overwriting
`filesystem/external_programs/terminal_emulator` with `/nonexistent/s05-marker`, the pack is
byte-identical to the pre-craft pack (`pack_eq=true`) and the store was **not rewritten** by the
export (`store_untouched=true`, marker still present).

**[obs]** A corrupt store fails **open**: writing 23 bytes of garbage into the store, the export
still exits 0, the pack is unchanged (`pack_eq=true`), and the store is **healed** to the default
(17728 B, sha identical to the pre-corruption default, `heal_eq_default=true`). Verbatim nested log
class (hand probe `/var/tmp/r103c-E5/m3/corrupt.log`):

```
ERROR: <cfg>/godot/editor_settings-4.7.tres:1 - Parse Error: Expected '['.
   at: _printerr (scene/resources/resource_format_text.cpp:41)
ERROR: Failed loading resource: <cfg>/godot/editor_settings-4.7.tres.
   at: _load (core/io/resource_loader.cpp:317)
ERROR: Could not load editor settings from path: <cfg>/godot/editor_settings-4.7.tres
   at: create (editor/settings/editor_settings.cpp:1410)
```

**[obs]** `editor/export/convert_text_resources_to_binary` is an *editor-prefixed **project***
setting honored by the CLI export; its effective default is true. Hand probes (`m1`, single path):
default/unset and explicit `=true` both ship binary (`.godot/exported/133200997/export-3070c538…-main.scn`
667 B + `export-309be702…-notes.res` 244 B, 3 `.remap`, 9 entries, pack sha `3390d9a1…`);
explicit `=false` ships `main.tscn` (149 B) + `notes.tres` (71 B) as text with 7 entries and the
pack sha `a774d6e3…`. Scripts compile either way (`main.gdc` 513 B + `main.gd.remap` 31 B) — the
text pack still has 1 `.remap`, so `remaps=0` is *not* the discriminator; `scen/res=text` is.

**[obs]** `override.cfg` is a **runtime-only** override for this setting, in both directions:
project.godot silent + `override.cfg=false` → export behaves true (pack `3390d9a1…`) while the
source run prints `DIV_S05_CTB false`; project.godot `=false` + `override.cfg=true` → export stays
text (`a774d6e3…`) while the source run prints `true`. `override.cfg` never appears among pack
entries. The fixture pins the second direction end-to-end (`pack_eq=true` + `runtime_ctb=true`).

**[obs]** Pack bytes are **path-seeded, not content-only**: two fresh scratch roots produce packs
equal in every entry name/size (2596 B, 9 entries) but differing in exactly 20 bytes — offsets
939-942 and 2052-2067, both inside the `node_ids` block (context: `…node_ids\x00 \x00\x00\x00\x01`
then a 4-byte id; second hit in the id/path table). Same path + repeated runs → byte-identical
(four runs at `root` all gave sha `a210587a…`; `rootA` `a5ddf777…`, `rootB` `f8e54ca3…`, `rootZ`
`cb70d86b…`).

**[obs]** Binary string census: the setting path `editor/export/convert_text_resources_to_binary`
exists in the binary; EditorSettings' `export/` namespace is `export/{android,macos,ssh,web,windows}/*`
— no Linux/X11 pack-affecting key; the engine carries the classes `Could not load editor settings
from path: `, `Found override.cfg but could not load it.`, and the store names
`editor_settings-%d.tres` / `editor_settings-%d.%d.tres`.

**[inf]** The 20-byte variance is a per-path seed for freshly scanned scene node ids (same path ⇒
identical ids), not a timestamp: the two packs' only difference lies in `node_ids`, and the store
default digest is root-invariant while packs are not.

**[inf]** The export path constructs EditorSettings (it writes/heals the store) but the Linux/X11
exporter's inputs are preset + project settings only; editor-settings contents are read, validated,
and then unused for pack content.

**[unknown]** Whether an *exported binary* honors a sibling `override.cfg` (only the source-run
runtime path was measured; the product/game-mode equivalence is inferred, not measured). Whether
the ctb setting affects non-Linux platforms. Whether any EditorSettings key outside the crafted
marker influences the pack (only the absence of a Linux/X11 `export/*` key in the string census
supports "none").

## 6. Integration notes / hazards

1. **Never pin a raw pack/binary sha for these rows** — pack bytes are path-seeded (§4). The three
   arms compare two packs *inside one run*, so the seeding cancels; the same trap applies to any
   other seat pinning exported-artifact digests.
2. Only `XDG_CONFIG_HOME` is overridden for nested runs. `HOME`/`XDG_DATA_HOME` must stay ambient:
   the template lookup (`$XDG_DATA_HOME`/`$HOME/.local/share/godot/export_templates/<ver>/…`) runs
   before the export and FAILs `template_binary_not_found` otherwise.
3. `default_store_bytes=17728` / `heal_bytes=17728` are host-config-coupled (the store embeds
   absolute host paths, e.g. the Android SDK path). They are stable across all roots measured here;
   treat them as a **canary** — if the operator's editor config changes size, the row FAILs
   spuriously and the field should be replaced by a boolean (the real law, `heal_eq_default`, is
   self-referential and immune).
4. Store name is derived from `Engine.get_version_info()` (`editor_settings-<major>.<minor>.tres`),
   so the fixture survives an engine patch bump below a minor version change.
5. Nested export output is redirected to `<root>/div_s05/logs/*.log`; receipts carry no engine
   error class, so no `expected_errors` entry is needed (the W5 export_div gate stays
   vacuous-but-honest).
6. Re-run cost: 3 arms ≈ 4.4 s each; adding a fourth export to any arm would breach the 8 s bound
   under load.
7. Sibling seat V3 (the r103 verifier for this exact claim) **starved before measuring** — this
   shard carries the only evidence for the surface. An independent re-derivation is still worth a
   seat in r104, in particular of the export-vs-runtime `override.cfg` divergence.
