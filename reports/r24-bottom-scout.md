# Round 24 bottom-edge Camera2D scout

- Environment: Godot 4.7.2.stable, headless Linux. Scratch-only project/script under `corpus/live/r24-bottom-scout-scratch/`; no tracked fixture or project file changed.
- On the existing battery-style project config, `camera.get_viewport().get_visible_rect().size.y` was 64 px (Godot headless script viewport), so the runtime half-height was 32 px. With `camera.limit_bottom=1000` and target moved to y=2000, the active center was y=968 (`1000 - 32`), not target y=2000. The intended positive condition is `center.y <= boundary + epsilon`, `abs(center.y - (boundary - viewport_height/2)) <= epsilon`, target actually moved, and center remains distinct from target.
- With only the bottom limit changed to 100000 (same target and expected authored boundary=1000), center became y=2000 and matched target; the same clamp assertion therefore rejects this far-bottom control. This is causal rather than setup failure.
- Separate default scratch run had viewport height 450 and half-height 225, yielding center y=775 at bottom=1000; confirms the center offset must be calculated from the live viewport, not hard-coded (the battery config's headless runtime was 64px).
- Suggested invocation: scratch duplicate `camera_limit.gd` with `--bottom-bound` and `--far-bottom`; determine test axis by `bottom_test || far_bottom_bound`, move target to `(0,2000)`, keep boundary fixed at `1000`, use live `visible_rect.size.y/2`, expected `boundary - half_height`, positive inequality `center.y <= boundary + 0.01`. Far control changes only `camera.limit_bottom=100000`. Keep x for unrelated axis checks; avoid interpreting a zero center as evidence unless the same active/current, moved, clamp, and target-separation checks pass.
- Scope: feasibility and geometry only. No battery mutation, rendered framing claim, or production-camera/export claim. Scratch evidence is reproducible with `godot --headless --path <scratch> --script <scratch>/bottom.gd [-- --far-bottom]`.
