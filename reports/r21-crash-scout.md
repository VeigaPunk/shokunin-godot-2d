# Round 21 crash/signal scout

## Result
A real, safe normal-vs-signal contrast is reproducible with Godot 4.7.2.stable.arch_linux.ed1daf0bf on this Linux host. The same one-shot headless script emitted `CRASH_SCOUT: pre-exit signature` in both cases. Normal mode then called `quit(2)` and exited 2. Hold mode emitted the same marker, remained alive in a bounded 15-second loop, and was externally sent SIGTERM after its Godot PID was observed in `ps`; the bash-wrapped command returned 143 (128+SIGTERM 15). Thus identical stdout marker and intended nonzero code do not establish normal termination. This demonstrates feasibility only, not a production crash guarantee.

## Method / raw observations
Own scratch only: `.shokunin/game-dev-2d/corpus/live/r21-crash-scout/crash_exit_probe.gd`. Script prints the marker before branching. With no user args it calls `quit(2)`; with `--hold` it loops for at most 15,000 ms (25 ms delay each iteration), then would call `quit(2)`. Commands used: `godot --headless --path . --script .shokunin/game-dev-2d/corpus/live/r21-crash-scout/crash_exit_probe.gd` and the same command with `-- --hold`. Both stdout observations included the identical marker. Normal command exited 2 in 0.552 s. For hold mode, the wrapper PID was 827149 and the actual Godot PID was 827153 (`Sl`); SIGTERM was sent to PID 827153 while it was running. Wrapper then exited 143 in 5.442 s and included the same marker plus shell `Terminated` notice. A post-run process check found no matching Godot process. No children or zombies remained.

## Scope / caution
The harness bash wrapper reports signal termination as shell status 143, not the raw negative `Popen` return code; consumers must account for wrapper/platform semantics. This Unix SIGTERM test does not prove behavior under SIGKILL, Windows, macOS, timeouts, or process-tree cleanup. The marker is printed before termination and therefore only establishes pre-termination execution. Scratch script is not a seeded fixture and must not be treated as one.
