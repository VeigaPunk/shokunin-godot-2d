## Self-improvement suggestions (proposals only, nothing acted on)

- **Flag experimental APIs.** Do one read-only pass that lists every class or member in the lane's notes that the class reference marks as experimental. Under the new release policy these are the only APIs that can break in a minor release, so they should carry a visible label.
- **Judge staleness by release type.** A patch release (4.7.x) triggers no re-check. A minor release (4.8) triggers checking the notes against that version's migration guide. A note on an experimental API is re-checked on every release. This replaces the current habit of treating every version-scoped note as equally at risk.
