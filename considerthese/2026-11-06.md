1. **Save reconstruction must fail closed before any state replacement.** Batch 2 (`2026-11-03-curated-sources-02.md`) pins the 4.4 saving-games tutorial and its nested-object caveats: parents must exist before children, stored NodePaths can go stale, and JSON cannot preserve several Godot types. The not-performed fixture asks for a two-phase reconstruction with dangling-parent, duplicate-ID and malformed-type negatives, and requires every invalid record to be reported *before* state replacement. That is an admission pattern, not just a save tip: a candidate that mutates live state while still holding invalid records is not ready.

2. **UI focus evidence is owner identity, not screenshots, and shared actions are a hazard.** Batch 3 (`2026-11-03-curated-sources-03.md`) pins the gui_navigation page and proposes an asymmetric menu with a modal and a control that disappears. The passing rule is a recorded focus-owner identity after every directional and tab action, plus an intentional missing initial focus and a wrong neighbor as negatives. It also says to watch gameplay state during navigation so shared UI/gameplay action bindings surface. Visual capture alone would miss both the recovery rule and the binding leak.

3. **External authoring data must report unresolved content and keep a coordinate ledger before any engine comparison.** Batch 4 (`2026-11-03-curated-sources-04.md`) pins LDtk schema 1.5.3: when `externalLevels` is on, `layerInstances` is null and `externalRelPath` points elsewhere; pixel offsets already combine definition and instance offsets. The not-performed fixture pairs embedded vs external levels, adds a missing-external-file control, and requires unresolved-data reporting, preserved layer order, and a coordinate ledger *before* comparing in Godot. Schema conformance is explicitly not collision, importer or render proof, and absent external data must not silently become an empty playable level.
